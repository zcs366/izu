第一章：认识ComfyUI——一个全新的AI创作方式

1.1 ComfyUI到底是什么？

你有没有用过MidJourney或者Stable Diffusion WebUI（比如A1111）？那些工具通常给你一个"填框框"的界面——你写一句话，点一个按钮，它就帮你生成图片。方便是方便，但如果你想做更复杂的事情，比如：

  • 先生成一个背景，再在背景上放一个角色
  • 先让AI画一张图，然后只修改图中的某一部分
  • 给一张照片换个风格，但保留人物的姿势
  • 让AI根据你的草图生成完整图像

传统的工具就有点"力不从心"了。

ComfyUI不一样。 它不给你一个固定的操作面板，而是给你一块空白的画布**，和一些叫做"节点"的小方块。你像搭积木一样，把这些小方块连起来，就拼出了你自己专属的"AI流水线"。

💡 专业说法叫"节点式编程"（node-based programming），翻译成人话就是：
把你脑子里想的"先做A，再做B，然后把A和B合在一起"这个过程，在电脑上用方块和连线画出来。**

举个例子：做一杯奶茶

如果你去奶茶店点单，店员会帮你完成所有步骤，你只需要说"来杯珍珠奶茶"——这是MidJourney。

但如果你是自己在家做奶茶**，你需要：

  1. 拿出杯子
  2. 把茶包泡上
  3. 加牛奶
  4. 加糖
  5. 加珍珠
  6. 搅拌一下

每一步都是一个"节点"，串联起来就是一个"工作流"。ComfyUI就是让你这样搭积木。

举个例子：AI画一只猫

如果我说"帮我生成一张森林里的橘猫"，传统工具的做法是——你把这句话填进去，点生成，得到一张图。

ComfyUI的做法是让你看到这个过程：

[加载模型] → [写提示词] → [设置参数] → [生成图像] → [保存图片]
  ↓               ↓            ↓            ↓            ↓
 加载一个        告诉AI我      设置画质、    把文字描述    把最终结果
 AI绘画模型      想要什么      风格等参数    变成图片      存到电脑上

每一个方框都是一个"节点"，箭头就是"连线"。你看得见每一步，也可以随时修改中间的某一步**。

1.3 核心概念——你只需要记住这5个

① 节点（Node）

每个节点就是一个功能模块**。有的负责加载模型，有的负责写提示词，有的负责生成图片。

形象理解：** 节点就像乐高积木，每个积木做一件事。有的积木长这样（模型加载），有的长那样（图片保存），把它们拼在一起就能搭出你想要的东西。

② 连线（Link/Connection）

节点之间的数据通道**。一个节点处理完数据，通过连线传给下一个节点。

形象理解：** 连起来的节点就像水管——A节点出来的水（数据）顺着管子流到B节点。

线的颜色代表什么：**

  • 🔴 红色线** = 模型数据（checkpoint模型文件）
  • 🟡 黄色线** = CLIP（文字理解模块，负责把你的提示词变成AI能懂的信号）
  • 🟣 紫色线** = Latent（"潜空间数据"——图像的压缩版，还没变成你能看到的图片）
  • 🔵 蓝色线** = 条件（conditioning，指引AI要画什么）
  • 🟢 绿色线** = 图片/VAE解码后的结果
  • ⚪ 灰色线** = 控制信号（ControlNet等）

③ 工作流（Workflow）

你搭出来的整个节点拼图就叫一个工作流。可以保存成文件分享给别人。

④ 检查点（Checkpoint）

也就是基础模型文件**。可以理解为AI的"大脑"——它决定了AI会画什么风格。

举个例子：**

  • 用"写实模型" → 画出来的像照片
  • 用"二次元模型" → 画出来的是动漫风格
  • 用"3D模型" → 画出来像3D渲染

⑤ 潜空间（Latent Space）

这个词听起来很吓人，但理解起来很简单：AI处理图片的时候，不是直接看像素（1024×1024的图片有超过100万个像素点），而是先压缩成一个更小、更高效的表示**。这个"压缩后的版本"就叫Latent（潜空间数据）。

好处：** 处理速度快得多，占显存也少得多。

第二章：安装——把ComfyUI装到你的电脑上

2.1 先别急，看看你的电脑能不能跑

在开始安装之前，我们先搞清楚一件事：你的电脑够不够资格？**

最重要的事：显卡（GPU）

AI绘画最核心的硬件是显卡。就像打游戏需要好显卡一样，AI绘画也需要。

怎么看你的显卡？**

  • Windows：按 Ctrl + Shift + Esc 打开任务管理器 → 点"性能"选项卡 → 看"GPU"
  • 或者按 Win + R，输入 dxdiag，回车，看"显示"选项卡

不同显卡能做什么？

你的显卡能跑什么体验如何
无独立显卡**（只用CPU）基本跑不动❌ 不建议，一张图要几分钟到几十分钟
4GB显存**（如GTX 1650）SD 1.5（512×512）⚠️ 能跑，但很勉强
6GB显存**（如RTX 2060/3060）SDXL（1024×1024）✅ 够用，日常创作没问题
8GB显存**（如RTX 3070/4060）SDXL + 放大✅ 舒服，还可以加ControlNet
12GB显存**（如RTX 3080/4070）Flux + SDXL✅ 很舒服，基本都能跑
16GB+**（如RTX 4080/4090）都可以✅ 通吃，还能做视频
AMD显卡**部分支持⚠️ 兼容性不如NVIDIA

💡 如果你完全不确定，最简单的办法：你的电脑能不能玩一些3D游戏？** 如果能，大概率能跑ComfyUI。

其他你需要的东西

  • 硬盘空间：** 基础安装约2GB，加上常用模型大概30-50GB。建议留出至少100GB。
  • 内存（RAM）：** 建议16GB以上。
  • 操作系统：** Windows 10/11，或者macOS、Linux都行。

2.2 方式一：秋叶整合包（Windows用户最简单的方法）

如果你是Windows用户，这是最无脑、最推荐**的方式。

第一步：下载整合包

  1. 打开浏览器，访问B站UP主"秋葉aaaki"的主页，或者直接搜"秋叶整合包 ComfyUI"
  2. 找到他发布的ComfyUI整合包
  3. 下载压缩包（通常很大，5-10GB，包含了一些必要的模型）

第二步：解压

  1. 找一个空间大的盘（比如D盘或E盘），新建一个文件夹，比如 D:\AI绘图
  2. 把下载的压缩包解压到这个文件夹
  3. 解压后你会看到类似这样的文件结构：
D:\AI绘图\ComfyUI_aki\
     ├── A绘师启动器.exe  ← 就是它！你的启动入口
     ├── ComfyUI\         ← ComfyUI本体
     └── ...其他文件

第三步：启动

  1. 双击 A绘师启动器.exe
  2. 会弹出一个启动器窗口，里面有"一键启动"按钮
  3. 点击"一键启动"
  4. 第一次启动可能需要等一会儿，因为要加载环境

第四步：验证成功

启动成功后，你的默认浏览器会自动打开**，你会在浏览器里看到：

一块黑色的画布，左边有一个节点（叫"Checkpoint Loader"），整个界面看起来空荡荡的。**

如果看到这个画面——恭喜你，安装成功了！👍

如果没有自动打开浏览器：** 手动打开浏览器，在地址栏输入 http://127.0.0.1:8188 回车。

2.3 方式二：comfy-cli安装（更灵活的方式）

如果你想要更干净、更可控**的安装方式，或者你用的是macOS/Linux，推荐用comfy-cli。

第一步：安装Python

ComfyUI需要Python 3.10到3.12版本。

怎么检查你装没装Python？**

打开命令提示符（CMD）或终端，输入：

python --version

如果看到类似 Python 3.12.x 就说明已安装，如果报错就需要去 [python.org](https://python.org) 下载安装。

第二步：安装comfy-cli

打开命令提示符（CMD）或终端，输入：

pip install comfy-cli
💡 这个命令的意思是：通过Python的包管理工具pip，安装一个叫comfy-cli的软件。

第三步：安装ComfyUI

根据你的显卡类型，运行对应的命令：

NVIDIA显卡（最推荐）：**

comfy --skip-prompt install --nvidia

AMD显卡：**

comfy --skip-prompt install --amd

苹果电脑（M1/M2/M3芯片）：**

comfy --skip-prompt install --m-series

如果只有CPU（不推荐，非常慢）：**

comfy --skip-prompt install --cpu

第四步：启动

comfy launch

启动后，打开浏览器，访问 http://127.0.0.1:8188。

2.7 常见问题解决

Q1：启动时闪退

原因：** 最常见的原因是显卡驱动太旧，或者Python版本不对。

解决方案：**

  • 更新显卡驱动（去NVIDIA官网下载最新驱动）
  • 确认Python是3.10-3.12版本
  • 如果是秋叶整合包，尝试右键 A绘师启动器.exe → 以管理员身份运行

Q2：生成图片时显示"CUDA out of memory"

原因：** 显存不够了。你的显卡显存小于模型所需。

解决方案：**

  • 换更小的模型（SD 1.5比SDXL小）
  • 降低生成分辨率（从1024×1024降到768×768）
  • 在启动参数中添加 --lowvram（在启动器中找设置选项）

Q3：浏览器打开后一片空白，或者连接失败

原因：** ComfyUI没有正常启动。

解决方案：**

  • 查看启动窗口有没有报错
  • 确认端口8188没有被其他程序占用
  • 重启ComfyUI

Q4：生成的图片一团黑或者一团噪声

原因：** 模型没加载成功，或者节点连接有问题。

解决方案：**

  • 确认Checkpoint Loader里选了正确的模型
  • 确认所有节点都正确连接（线没有断）
  • 重新加载工作流

  • 安装Visual C++ Redistributable
  • 或者直接用comfy-cli重新安装（见2.3节）

3.4 连接节点——"从圆点拖到圆点"

节点上的小圆点（⚪）是连接点。每个圆点有特定的颜色和位置：

  • 左边的圆点** = 输入（数据"流进来"）
  • 右边的圆点** = 输出（数据"流出去"）
  • 圆点颜色** = 数据类型（红色是模型，紫色是潜空间数据等）

如何连接？

  1. 在一个节点的右边输出圆点**上按住鼠标左键
  2. 拖动到另一个节点的左边输入圆点**上
  3. 松开鼠标，一条线就连上了

连接规则

  • ✅ 相同颜色的圆点可以连**：红色连红色，紫色连紫色
  • ✅ 一个输出可以连多个输入**：比如一个CLIP节点的输出可以同时连到正向提示词和负向提示词
  • ❌ 不能连相同位置的**：不能从输出连到输出，也不能从输入连到输入
  • ❌ 不能循环连**：A→B→C→A 不行

第四章：实战——搭建你的第一个工作流

4.1 我们要生成一张什么图？

在开始之前，我们先定个目标：

"一只橘猫在夕阳下的窗台上打盹"**

想象一下这个画面：金色的夕阳透过窗户照进来，一只胖胖的橘猫蜷缩在窗台上，眯着眼，尾巴耷拉在窗台边缘。毛被阳光照得发亮。

这就是我们要用ComfyUI生成的图。跟着我一步步来。

4.2 第一步：加载模型（Checkpoint Loader）

操作步骤

  1. 如果你刚启动ComfyUI，画布上可能已经有了一个"Checkpoint Loader"节点
  2. 如果没有，在空白处右键 → 搜索 Checkpoint Loader → 点击添加
  3. 在这个节点上，点击模型名称旁边的下拉框
  4. 选择你下载的模型，比如 sd_xl_base_1.0.safetensors

这个节点在做什么？

Checkpoint Loader（检查点加载器）** 就像你做饭前要先"开火"一样——它在内存中加载AI的"大脑"。没有它，后面的所有操作都无法进行。

节点的输出口

这个节点有3个输出口：

  • model（红色）**：模型本身 → 传给KSampler
  • clip（黄色）**：文字理解模块 → 传给提示词节点
  • vae（绿色）**：图像解码器 → 传给VAE Decode节点

4.3 第二步：写提示词（CLIP Text Encode）

操作步骤

  1. 在空白处右键 → 搜索 CLIP Text Encode → 添加
  2. 添加两个**：一个用于"正向提示词"（你想要什么），一个用于"负向提示词"（你不想要什么）
  3. 把两个节点摆好位置

正向提示词怎么写？

在我们的猫片案例中，正向提示词写：

positive: an orange cat sleeping on a windowsill, warm sunset light, golden hour, cozy atmosphere, soft fur, detailed, highly detailed, photorealistic, 4k

解释：**

  • an orange cat sleeping on a windowsill = 一只橘猫在窗台上睡觉（主体）
  • warm sunset light, golden hour = 温暖的夕阳光，金色时刻（氛围）
  • cozy atmosphere = 舒适的氛围（情绪）
  • soft fur = 柔软的毛发（细节描述）
  • detailed, highly detailed, photorealistic, 4k = 高质量关键词（画质要求）

负向提示词怎么写？

negative: ugly, deformed, blurry, low quality, watermark, text, signature, bad anatomy, extra limbs, fused fingers, bad hands

解释：**

  • ugly, deformed, blurry, low quality = 不要丑陋、变形、模糊、低质量
  • watermark, text, signature = 不要水印、文字、签名
  • bad anatomy, extra limbs, fused fingers = 不要肢体畸形、多肢、手指粘连
💡 提示词技巧：** 正向提示词告诉AI"要什么"，负向提示词告诉AI"不要什么"。两条指令一样重要。

连接方式

  1. 从Checkpoint Loader的 clip（黄色）输出，连接到两个**CLIP Text Encode节点的 clip 输入
  2. 一个节点的输出叫 CONDITIONING（蓝色），代表"正向条件"
  3. 另一个节点的输出也叫 CONDITIONING（蓝色），代表"负向条件"
💡 一个输出可以同时连到多个输入——这是ComfyUI的常用技巧。

4.4 第三步：设置KSampler（核心生成引擎）

操作步骤

  1. 在空白处右键 → 搜索 KSampler → 添加

KSampler的参数设置

以我们的猫图片为例，我们这样设置：

参数设置值说明
seed（种子）**12345随便填个数字，下次用同一个数字能生成一样的图
steps（步数）**30适中，SDXL建议20-40
cfg（提示词强度）**7适中，太低了不听话，太高了画过
sampler_name（采样器）**euler最简单的采样器，出图稳定
scheduler（调度器）**normal标准模式
denoise（去噪强度）**1.0文生图固定为1.0

连接方式

KSampler需要连接3个输入：

  1. model（红色）** ← 接Checkpoint Loader的model输出
  2. positive（蓝色）** ← 接正向提示词节点的CONDITIONING输出
  3. negative（蓝色）** ← 接负向提示词节点的CONDITIONING输出

每个参数到底是什么意思？

别急——第五章会详细解释每个参数。现在先用我给的值。

4.5 第四步：VAE Decode + Save Image

VAE Decode（把数据变成图片）

KSampler输出的是一团"潜空间数据"（紫色Latent），人类看不懂。需要把它解码成我们能看的图片。

  1. 添加 VAE Decode 节点（右键搜索）
  2. 连接：

- samples（紫色） ← 接KSampler的 latent** 输出

- vae（绿色） ← 接Checkpoint Loader的 vae** 输出

  1. VAE Decode的 IMAGE（绿色）** 输出就是解码后的图片了

Save Image（保存到电脑）

  1. 添加 Save Image 节点（右键搜索）
  2. 连接：

- images（绿色） ← 接VAE Decode的 IMAGE** 输出

✅ 这一步之后，生成的不但在预览区能看到图片，还会自动保存到 ComfyUI/output/ 文件夹里。

问题：不像是橘猫**

→ 修改提示词，更具体描述。比如 orange tabby cat, striped fur, round face

问题：光线不温暖**

问题：构图不好看**

问题：猫的爪子画坏了**

4.8 进阶：给图片加点风格——LoRA

LoRA（Low-Rank Adaptation）是一种轻量级的"风格注入"方法。可以把它理解为给AI戴上一个风格滤镜**。

举个例子

你想让那只橘猫有"宫崎骏动画"的风格：

  1. 下载一个宫崎骏风格的LoRA（去CivitAI搜"Studio Ghibli LoRA"）
  2. 把下载的 .safetensors 文件放到 ComfyUI/models/loras/ 文件夹
  3. 在空白处右键 → 搜索 LoRA Loader → 添加
  4. 在LoRA Loader里选择你下载的LoRA文件
  5. 连接方式：
[Checkpoint Loader] → model → [LoRA Loader] → model → [KSampler]
                                    ↑
                              [CLIP Text Encode]（可选的触发词）
  1. 在提示词里加上LoRA的触发词（通常在LoRA的下载页面有说明）

4.9 进阶2：图生图——用你拍的照片做底

有时候你想用自己拍的照片，让AI换一个风格。

举个例子：把你家猫的照片变成"油画风格"

第一步：加载照片**

  1. 右键 → 搜索 Load Image → 添加
  2. 在Load Image节点里，点击"Choose Image to Upload"按钮
  3. 选择你家猫的照片

第二步：添加图生图节点**

图生图其实就是把KSampler改成"用图片初始化"**，而不是从纯噪声开始。

最简单的方式是使用"Latent From Image"节点：

  1. 右键 → 搜索 Latent From Image → 添加
  2. 连接：Load Image的IMAGE输出 → Latent From Image的images输入
  3. Latent From Image的latent输出 → KSampler的latent输入

第三步：降低denoise值**

这是图生图最重要的参数！

  • denoise = 1.0 → AI完全不参考原图，重新画
  • denoise = 0.7 → AI保留大部分构图和姿势，改变风格
  • denoise = 0.5 → AI保留颜色和大致布局，细节全改
  • denoise = 0.3 → AI只做微调，基本保持原图

对于"把猫变成油画风格"这个需求：

→ 设置 denoise = 0.6 到 0.7

第四步：修改提示词**

正向提示词写：a photorealistic cat, oil painting style, thick brush strokes, canvas texture, artistic, masterpiece

第五步：生成！**

你会看到：原图是一只真实的猫，生成后变成了一幅油画质感的猫——但姿势和基本样貌保持不变。

4.10 进阶3：局部重绘——给照片里的猫换一个表情

局部重绘（Inpainting）是AI绘画最实用的功能之一：只修改图片的某一部分，其他部分保持不变。**

举个例子：把你家猫的严肃表情改成微笑

第一步：准备模型**

你需要一个"Inpainting版本"的模型，或者使用专门的Inpainting流程。简单起见，我们可以用SD 1.5 Inpainting模型。

第二步：准备图片和处理区域**

  1. 用Load Image加载你家猫的照片
  2. 用图像处理软件（比如Photoshop、GIMP甚至Windows画图）在猫的嘴部涂成纯白色**
  3. 把这张"涂白后的图"保存
  4. 用第二个Load Image加载这张涂白图

第三步：连接Inpainting节点**

需要添加 VAE Encode (for Inpainting) 节点（右键搜索）：

  1. 原图 → VAE Encode for Inpainting的 pixels** 输入
  2. 涂白图（遮罩） → VAE Encode for Inpainting的 mask** 输入
  3. 输出的latent → KSampler的latent输入

第四步：设置遮罩处理参数**

遮罩边缘柔和度（grow_mask_by）：建议设为 6（像素），这样边缘过渡自然。

第五步：修改提示词**

正向：a cat with a happy smiling expression, happy mouth, cheerful

第六步：生成！**

只有你涂白的嘴部区域会被重绘，其他部分保持不变。猫的眼睛、耳朵、身体都还是原来的样子。

第五章：参数详解——每个旋钮是干什么的

这一章我们来逐个解开KSampler里每个参数的神秘面纱。

5.1 Steps（步数）——"笔触的数量"

它到底是什么？

想象你在素描一幅画：

  • 用10笔画完**：画面很粗糙，大概能看到是什么
  • 用20笔画完**：细节多了，但还不够细腻
  • 用30笔画完**：画面已经很丰富了
  • 用50笔画完**：每一根毛发都画了出来

Steps就是这个"笔触的数量"——AI从一张纯噪声图（全是雪花点），一步一步地"画"出最终的图像。每一步都在减少噪声、增加细节。

实际效果对比

Steps效果用时（3060显卡）
10**画面粗糙，很多瑕疵，但能看出来是什么约3秒
20**可以接受，大致清晰，细节不够约6秒
30**质量不错，细节丰富约9秒
50**非常精细，但再增加收益递减约15秒
100**几乎没区别了，白白浪费时间约30秒

最佳实践

  • SD 1.5模型**：建议20-30步
  • SDXL模型**：建议25-40步
  • Flux模型**：建议20-30步
💡 经验法则：** 30步是一个很好的起点。觉得质量不够就加到40，觉得太慢就降到20。

举个例子

同一条提示词 "一只橘猫在窗台上"

Steps=10: 能看到猫的形状，但边缘模糊，像失焦的照片
Steps=20: 猫的轮廓清晰了，毛发开始有纹理
Steps=30: 猫的胡须、眼里的反光都出来了
Steps=50: 每一根毛都清晰可见，背景也细腻了

5.2 CFG（提示词强度）——"AI有多听你的话"

它到底是什么？

CFG的全称是Classifier-Free Guidance Scale。翻译成人话就是：AI对提示词的"听话程度"**。

  • CFG很低（1-3）**：AI不太管你写了什么，自己自由发挥
  • CFG适中（5-8）**：AI认真执行你的指令，但也有一些自己的理解
  • CFG很高（10-20）**：AI拼命按照你的提示词去做，但容易"过度"

实际效果对比

CFG值效果例子：提示词"一只橘猫"
3**AI自由发挥，可能画成猫、可能画成别的，色彩柔和画了一团橘色的东西，大概有猫的形状
7**标准设置，AI认真画猫，构图自然，色彩合理一只清晰的橘猫，构图自然
12**AI非常努力地画猫，但色彩过于饱和，边缘有伪影猫的颜色太浓，背景有点怪异
20**AI"用力过猛"，画面失真，出现奇怪的纹理猫看起来像塑料做的，背景有奇怪的噪点

最佳实践

  • 写实风格**：CFG 6-8
  • 动漫风格**：CFG 7-10（动漫需要更明确的风格指引）
  • 创意/抽象**：CFG 4-6（给AI更多自由）
  • 不要超过15**：超过15通常结果反而更差
💡 CFG和Steps的关系：** Steps越高，你可以用稍低的CFG（因为AI有更多步数来"理解"你的提示词）。Steps低的时候，可以适当提高CFG。

举个例子

提示词："一只橘猫在窗台上打盹，夕阳"

CFG=3: 画面柔和模糊，猫和背景混在一起，像水彩画
CFG=7: 猫很清晰，背景明确是窗台，阳光温暖
CFG=12: 猫的颜色过于鲜豔，毛发像刺一样，阴影太重
CFG=20: 画面出现奇怪的纹理，猫的表情扭曲

5.3 Seed（种子）——"固定种子=固定结果"

它到底是什么？

Seed是AI生成过程中的随机数起点**。AI生成图片时，第一步是从随机噪声开始的。Seed决定了这个"起点"是什么。

  • 同一个Seed + 相同的参数 = 完全相同的图片**
  • 不同的Seed = 不同的图片风格和构图**

为什么要固定Seed？

  1. 复现结果**：你生成了一张好图，记下Seed，下次还能生成一样的
  2. 微调参数**：固定Seed，改变其他参数，看哪个参数影响什么
  3. 批量探索**：改变Seed，保持其他不变，快速生成不同构图

举个例子

所有参数相同（Steps=30, CFG=7, 提示词="一只橘猫"），只改Seed：

Seed=12345: 橘猫在画面左侧，看向右边，背景是木地板
Seed=66666: 橘猫在画面中央，正对镜头，背景是草地
Seed=99999: 橘猫在画面右侧，侧躺着，背景是沙发
Seed=42:    橘猫在窗台上，逆光，毛发光亮

常用Seed值

  • -1 或留空（有些版本支持）：每次随机
  • 随便输入一个整数（如 12345、42、777）：固定
💡 灵感发现：** 有时候随机Seed会意外得到很棒的结果。所以可以先随机几次，找到好构图后再固定Seed去精调。

5.4 Sampler（采样器）——"AI『降噪』的方法"

它到底是什么？

采样器是AI从"纯噪声"到"清晰图像"所用的数学方法**。不同的采样器就像不同的"绘画技法"——有的快，有的准，有的富有创意。

常见采样器对比

采样器速度画质特点
euler**快标准最基础、最稳当，适合新手
euler_ancestral**快好比euler好一点，但每次结果不同（随机性大）
dpmpp_2m**中好目前最推荐的，画质好、速度快
dpmpp_2m_sde**慢优秀画质极好，但慢，适合最终出图
dpmpp_3m_sde**很慢极好画质天花板，但时间翻倍
uni_pc**极快较好用很少步数就能出好结果
ddim**中标准老牌采样器，稳定但不够惊艳
lcm**极快（1-4步）一般适合实时预览，但细节不够

最佳实践

使用场景推荐采样器
探索构图（快速出图）euler 或 dpmpp_2m（20步）
最终出图dpmpp_2m_sde（30-40步）
SDXL标准出图dpmpp_2m（30步）
最快预览uni_pc（10-15步）
画质至上dpmpp_3m_sde（40步）
实时生成（LCM）lcm（4步）+ LCM专用LoRA

举个例子

提示词："一只橘猫在窗台上"，Steps=30, CFG=7

euler:             画面干净，中规中矩，是一只正常的猫
euler_ancestral:   画面生动，但每次结果不一样（随机性强）
dpmpp_2m:         细节丰富，毛发清晰，颜色准确 ← 推荐
dpmpp_2m_sde:     画质最好，毛发根根分明，但耗时多一倍
uni_pc:           10步就能出不错的结果，但30步反而可能不如dpmpp

5.5 Scheduler（调度器）——"降噪的节奏"

它到底是什么？

如果说采样器决定了"用什么方法降噪"，那调度器就决定了"降噪的节奏"**——比如前几步快一点还是后几步快一点。

常见调度器

调度器效果
normal**均匀降噪，每一步减少相同程度的噪声——最稳当
karras**前期快、后期慢——先确定构图，再精修细节
exponential**指数级衰减——前期极快，后期极慢
sgm_uniform**SDXL专用，比normal稍好

最佳实践

  • SD 1.5**：normal 或 karras 都可以
  • SDXL**：推荐 sgm_uniform 或 karras
  • Flux**：有自己的特殊调度器
💡 简单记忆法：** 拿不准就用 karras——它对大多数情况都是"最佳默认值"。

举个例子

Same: dpmpp_2m, Steps=30, CFG=7, "橘猫窗台"

normal:    每一步都差不多，画面稳定
karras:    前10步快速成形（猫的轮廓），后20步精修（毛发细节）
exponential: 前5步就完成了大致构图，后面25步都在修细节

5.6 Denoise（去噪强度）——"跟原图有多像"

它到底是什么？

Denoise只用于图生图**（从一张已有图片出发），不用于文生图。

它的范围是 0到1**：

  • denoise=1.0**：完全不参考原图，重新生成（相当于文生图）
  • denoise=0.7**：保留构图和颜色，改变风格
  • denoise=0.5**：保留基本布局和色调，但细节大变
  • denoise=0.3**：保留大部分原图，只改风格和纹理
  • denoise=0.0**：保留原图完全不变（没有意义）

实际效果示例

以一张"你家真实的猫照片"为底，提示词写"油画风格"：

Denoise效果
0.3**猫的姿势、表情、背景都完全不变，只是"表面"变成了油画笔触
0.5**猫的姿势保持，但毛色可能变了，背景可能简化了
0.7**猫的姿势大致保持，但颜色和背景都变了，更接近"重新画了一只猫"
0.9**完全不认识原来的猫了，变成了一幅全新的油画作品

最佳实践

场景推荐Denoise
换风格（如照片→油画）0.6-0.7
微调颜色/纹理0.3-0.4
大幅改变0.7-0.85
局部重绘（Inpainting）0.8-1.0

5.7 Resolution（分辨率）——"画布大小"

分辨率严格来说不是KSampler的参数，但你需要在"Empty Latent Image"节点（或者工作流的基础设置中）设置。

每个模型有自己的舒适区

SD 1.5的"舒适区"：512×512**

  • 最佳效果：512×528（宽高微调）
  • 能用：384×384 到 640×640
  • 超出太多（如1024×1024）：会出现重复的人物、畸形结构

SDXL的"舒适区"：1024×1024**

  • 最佳效果：1024×1024
  • 能用：768×768 到 1280×1280
  • 超出太多（如2048×2048）：内容可能重复或奇怪

Flux的"舒适区"：1024×1024**

  • 和SDXL类似

宽高比（Aspect Ratio）

除了分辨率，宽高比**也很重要：

场景宽高比示例分辨率
正方形（头像/图标）1:11024×1024
横屏（风景/壁纸）16:91344×768
竖屏（手机壁纸/海报）3:4896×1216
超宽屏（电影画面）21:91536×640
💡 总像素数保持接近是关键。** 1024×1024≈1,048,576像素，1344×768≈1,032,192像素——总像素接近，效果就会好。

举个例子

用SDXL模型生成"一只橘猫"

分辨率  | 效果

第六章：进阶技术详解（示例驱动）

本章不再讲理论，而是通过具体的"你想做什么"来展示对应的技术方案。

6.1 ControlNet：让AI按你的姿势来

场景：你想让AI生成的女孩摆一个特定的瑜伽姿势

你写提示词"一位在做瑜伽的女孩"，但AI每次画的姿势都不一样——有时站着，有时躺着。你想精确控制**她摆出"树式"（一条腿站立，另一条腿弯曲贴在另一条腿内侧）。

用OpenPose + ControlNet实现

什么是ControlNet？**

ControlNet是一种"辅助控制网络"，它给AI提供额外的参考信息——比如姿势、边缘、深度等。它不改变模型，而是在模型生成时"引导"它按照你给的参考来画。

步骤详解

第一步：准备参考姿势图片**

  1. 找一张你想要的人体姿势图片（可以从网上搜"tree pose yoga reference"）
  2. 保存到电脑上

第二步：搭建ControlNet工作流**

[Load Image] → [OpenPose Preprocessor] → [ControlNet Apply] → [KSampler]
                                                                    ↑
                                                              [模型 + 提示词]

具体节点操作：

  1. 添加 Load Image**（右键→搜索）

- 加载你的瑜伽姿势参考图

  1. 添加 OpenPose Preprocessor**（右键→搜索 OpenPose Pose）

- 这是"姿势提取器"——它会把参考图里的人体姿势提取成骨架图

- 把 Load Image 的 IMAGE 输出连接到它的 images 输入

- 你会看到输出变成了一个"火柴人"骨架

  1. 添加 ControlNet Loader**（右键→搜索 ControlNet Loader）

- 在它的 control_net_name 下拉框里选择一个OpenPose专用的ControlNet模型（如 control_v11p_sd15_openpose）

- 如果你没有这个模型：去CivitAI或HuggingFace搜索下载，放到 ComfyUI/models/controlnet/ 文件夹

  1. 添加 ControlNet Apply**（右键→搜索 ControlNet Apply）

- 连接方式：

- conditioning（蓝色）← 接你的正向提示词输出

- control_net（灰色）← 接 ControlNet Loader 的 CONTROL_NET 输出

- image（绿色）← 接 OpenPose Preprocessor 的 IMAGE 输出（即骨架图）

- 输出：positive（增强后的条件信号）→ 接 KSampler 的 positive 输入

  1. 其余部分和标准工作流一样**：Checkpoint Loader → CLIP Text Encode → KSampler → VAE Decode → Save Image

ControlNet的关键参数

Strength（强度）**：ControlNet对生成结果的影响力

  • strength = 1.0：严格按姿势来，几乎不会偏离
  • strength = 0.7：大致按姿势来，但AI有一些调整空间
  • strength = 0.3：弱引导，姿势可能改变但受到一定影响

Start At / End At（起止时间）**：ControlNet在生成过程中的什么时候起作用

  • start_at = 0.0, end_at = 1.0：全程控制（默认）
  • start_at = 0.0, end_at = 0.5：只在生成的前半段起作用（确定姿势后就不再约束）→ AI可以在后半段自由发挥细节
  • start_at = 0.3, end_at = 0.7：只在中间阶段起作用

实际效果对比（提示词"a woman doing yoga, tree pose"）：**

不用ControlNet:     姿势随机，可能站姿、坐姿、倒立
ControlNet + 1.0:   精确复现参考图的姿势，连手指位置都接近
ControlNet + 0.7:   姿势和参考图类似，但细节更自然
ControlNet + 0.3:   姿势有些相似，但AI自由发挥了很多

提示词也很重要！** ControlNet管姿势，提示词管"穿什么衣服、什么背景、什么风格"。比如：

positive: a woman doing tree pose yoga, wearing sportswear, studio lighting, detailed, 8k
negative: ugly, deformed, bad anatomy, extra limbs

其他ControlNet类型

ControlNet类型用途适用场景
Canny**边缘检测让AI照着你的线稿上色
Depth**深度图保持三维空间结构，适合复杂场景
Scribble**涂鸦控制随便画几笔，AI帮你完善成完整画面
Lineart**精细线稿动漫风格的线稿上色
Tile**分块控制HD高清放大时保持原图细节

6.2 LoRA：给AI加上"风格滤镜"

场景：你想让生成的图像都有梵高的风格

你画了一幅风景画，但希望它看起来像梵高的《星月夜》那种风格。不需要换模型，只需要加一个LoRA。

LoRA是什么？

LoRA（Low-Rank Adaptation）是一种轻量级的模型微调技术。你可以把它理解为给AI戴上了一个"风格滤镜"**——它不改变模型本身，只是在生成时注入额外的风格信息。

对比：**

  • 换模型（Checkpoint）= 换一个完全不同的大脑
  • 加LoRA = 在原有大脑上加一个"模块"，让它学会特定风格

步骤详解

第一步：下载LoRA**

  1. 访问 [CivitAI](https://civitai.com)，搜索 "Van Gogh LoRA" 或 "梵高 LoRA"
  2. 下载 .safetensors 文件
  3. 放到 ComfyUI/models/loras/ 文件夹

第二步：添加LoRA Loader节点**

  1. 右键 → 搜索 LoRA Loader → 添加
  2. 在 lora_name 下拉框中选择你下载的LoRA文件

第三步：连接方式**

[Checkpoint Loader] → model → [LoRA Loader] → model → [KSampler]
                         clip →                clip →    (CLIP输入)

关键点： LoRA Loader要插在Checkpoint Loader和KSampler之间**。模型先经过LoRA Loader"注入风格"，再传给KSampler。

第四步：设置LoRA强度**

LoRA Loader有一个 strength_model 和一个 strength_clip 参数：

  • strength_model**：控制LoRA对模型的影响强度（0.0 = 无效果，1.0 = 完全效果）
  • strength_clip**：控制LoRA对文字理解的影响强度（通常和上面一致）
Strength效果
0.2**微乎其微的风格提示
0.5**风格隐约可见
0.8**明显的风格（推荐）

6.3 IP-Adapter：用参考图告诉AI"我就要这个风格"

场景：你有一张喜欢的参考图，想让AI用同样的风格画别的内容

你看到一张赛博朋克风格的街景图，很喜欢它的配色和氛围。你希望用同样的风格**画一只机器猫，但保留赛博朋克的霓虹色调和质感。

什么是IP-Adapter？

IP-Adapter（Image Prompt Adapter）是以图提图**的技术——它从一张参考图中提取"风格特征"（配色、光影、质感等），然后应用到新图像的生成中。

与ControlNet的区别：**

  • ControlNet：控制姿势/结构**（骨架、边缘、深度）
  • IP-Adapter：控制风格/氛围**（配色、纹理、光影）

步骤详解

第一步：安装IP-Adapter模型**

  1. 下载IP-Adapter模型文件（通常从HuggingFace下载）
  2. 放到 ComfyUI/models/ipadapter/ 文件夹
  3. 安装 ComfyUI-IPAdapter-Plus 自定义节点（通过Manager安装）

第二步：搭建工作流**

[Load Image] ← 参考风格图
      │
      ▼
[IPAdapter Apply] → conditioning → [KSampler]
      ▲                              ▲
      │                              │
[CLIP Text Encode]            [Checkpoint → LoRA...]

第三步：关键参数**

  • weight（权重）**：风格参考的强度（0.3-1.0，建议从0.6开始）
  • noise（噪声）**：风格适配的灵活度（0.0=严格匹配，1.0=自由发挥）
  • start_at / end_at**：同ControlNet，控制IP-Adapter在生成过程中的起止时间

实际效果示例：**

参考图：赛博朋克街景（紫色霓虹灯、黑色背景、蓝色调）
提示词："a robotic cat, cyberpunk style"

weight=0.3: 背景隐约有紫色调，风格不明显
weight=0.6: 清晰可见的赛博朋克配色，机器猫被紫色霓虹光照亮  ← 推荐
weight=1.0: 几乎复制了参考图的构图，猫嵌入到街景中

使用技巧：** IP-Adapter和ControlNet可以组合使用！ControlNet管姿势，IP-Adapter管风格：

[姿势参考图] → [OpenPose] → [ControlNet Apply] → [KSampler]
[风格参考图] → [IPAdapter] → [IPAdapter Apply] →  ↑

6.4 视频生成（Wan2.1概述）

ComfyUI不仅能生成图片，还能生成视频。目前最流行的方案之一是使用Wan2.1**（一个开源视频生成模型）。

基本工作流

[Load Video Model] → [Text Encode] → [Video Sampler] → [Video Decode] → [Save Video]

你能做什么？

  • 文生视频**：写一段描述，生成几秒钟的视频
  • 图生视频**：给一张图，让AI生成"这张图动起来"的视频
  • 视频到视频**：输入一段视频，改变风格或内容

注意事项

  • 视频生成需要大量显存**（推荐24GB+）
  • 生成速度慢（一张3090生成4秒视频约需5-10分钟）

9.1 错误：生成的图片是一张灰色的图

错误的现象：**

你正常搭建了工作流，点击Queue Prompt，进度条走完了——但出来的是一张纯灰色**的图（或者偏灰色的模糊图像）。

预期效果: 一只橘猫在窗台上
实际输出: [████████████████████████████] ← 纯灰色方块

原因：**

你没有连接VAE**。VAE（变分自编码器）负责把潜空间数据（Latent）解码成肉眼可见的图片。没有VAE解码，你看到的只是一团"未处理"的数据。

修复步骤：**

  1. 添加一个 VAE Decode** 节点（右键→搜索）
  2. 连接：

- samples（紫色）← 接 KSampler 的 latent 输出

- vae（绿色）← 接 Checkpoint Loader 的 vae 输出（或单独加载一个VAE文件）

  1. VAE Decode 的输出（IMAGE）→ 接 Save Image
  2. 重新生成
✅ 正确的连接:
Checkpoint Loader → vae ──→ VAE Decode
                              ↑
KSampler → latent ──────────┘
                              ↓
                         Save Image

预防：** 每次搭建新工作流，第一件事就是检查VAE有没有连。

9.2 错误：Flux模型的输出一团糟

错误的现象：**

你用了Flux模型，写了一段详细的提示词，结果输出要么是一片模糊、要么是色彩混乱的噪声图、要么是完全不相关的内容**。

原因：**

Flux模型对CFG值非常敏感**！如果你用SDXL或SD 1.5的习惯把CFG设为7，Flux的输出就会崩掉。Flux需要的CFG值远低于其他模型。

修复步骤：**

  1. 把KSampler的 CFG值从7改成1.0-1.5**
  2. 如果效果还不够好，尝试 CFG=1.0**（Flux的推荐值）
  3. 有些Flux变体需要特殊的采样器，检查模型文档

对比：**

Flux, CFG=7.0: 输出一团糟，颜色溢出，内容不可识别
Flux, CFG=1.0: 输出清晰，完美遵循提示词
Flux, CFG=1.5: 细节略有增强，但可能稍过

经验法则：**

模型推荐CFG
SD 1.57-9
SDXL6-8
Flux**1.0-1.5**
SD33-5
LCM/LoRA1.0-2.0

预防：** 下载新模型时，先查一下它的"推荐参数"——通常模型发布页面都有写。

9.3 错误：加载模型时所有节点变红

错误的现象：**

你拖入一个别人分享的工作流，所有节点都是红色背景**，界面上有报错信息。

┌──────────────────────┐
│ Checkpoint Loader    │ ← 红色背景
│ [ERROR]              │

原因：**

这个工作流使用了你没有安装的自定义节点**。报错信息通常会告诉你缺少哪个节点（比如 "ComfyUI-IPAdapter-Plus"）。

修复步骤：**

方法一：自动安装（推荐）**

  1. 安装 ComfyUI Manager**（如果还没有）
  2. 点击 Manager 按钮 → "Install Missing Custom Nodes"**
  3. 它会自动检测缺少哪些节点并安装
  4. 安装后重启ComfyUI

方法二：手动安装**

  1. 看报错信息，记下缺少的节点名字（如 "ComfyUI-IPAdapter-Plus"）
  2. 打开命令提示符，进入 ComfyUI/custom_nodes/ 目录
  3. 执行：git clone https://github.com/作者名/节点名

方法三：已知常用节点手动安装清单**

9.4 错误：生成的图片中人物手指畸形

错误的现象：**

生成的图片中人物手指数量不对（6根手指、3根手指）、手指粘连在一起、手指扭曲**。

原因：**

这是Stable Diffusion模型的老毛病**——模型对"手"的理解不够好。手指是很复杂的小结构，AI经常"数不清"。

修复步骤：**

步骤1：强化负向提示词**

# 在负向提示词中加入这些关键词：
negative: bad hands, extra fingers, missing fingers, fused fingers,
          deformed hands, ugly hands, bad anatomy, disfigured hands

步骤2：使用手部修复LoRA**

  • 去CivitAI搜索 "hand fix LoRA" 或 "detail enhancer LoRA"
  • 加载到工作流中（strength=0.6-0.8）

步骤3：使用ADetailer插件（推荐）**

  1. 安装 ComfyUI-Impact-Pack 或 ComfyUI-ADetailer
  2. 添加 ADetailer 节点到工作流（在VAE Decode之后）
  3. 选择 "hand"** 检测模型
  4. ADetailer会自动检测手部区域并进行二次修复

步骤4：高分辨率修复**

  • 先生成低分辨率的图，再用高分辨率（2x）放大
  • 高分辨率时AI有更多像素来处理手部细节

步骤5：隐藏手部（最后的办法）**

  • 在提示词里加 hands behind back、hands in pockets、crossed arms
  • 让AI不要画手，这是最"不优雅"但有效的办法

9.5 错误："CUDA out of memory" 显存不足

错误的现象：**

生成过程中跳出红色错误信息：CUDA out of memory. Tried to allocate X.XX GB。或者生成到一半直接崩溃。

原因：**

你的显存（VRAM）不够当前操作使用。可能是：

  • 模型太大（比如用了Flux但只有8GB显存）
  • 分辨率太高（比如2048×2048）
  • 同时叠加了太多ControlNet/LoRA
  • 同时生成了多批（batch size > 1）

修复步骤：**

即时修复（从最有效开始）：**

  1. 降低分辨率**：从1024×1024降到768×768或512×512
  2. 减小batch size**：把batch size设为1，一次只生成一张
  3. 关闭其他程序**：关掉Chrome（非常吃显存）、关掉游戏
  4. 使用--lowvram模式**：在启动参数中添加 --lowvram 或 --normalvram
  5. 换小模型**：Flux → SDXL → SD 1.5

永久优化：**

# 在ComfyUI启动参数中加入（根据你的显存选择）：
--lowvram        # 显存 < 6GB
--normalvram     # 显存 6-10GB（推荐）
--highvram       # 显存 > 12GB

# 秋叶整合包用户：在启动器的"高级设置"中找到显存优化选项

9.6 错误：生成的图片过曝/颜色失真

错误的现象：**

图片的颜色过于鲜艳、发白、或者出现不自然的色彩过渡——像是"饱和度拉满"或者"HDR过度"的效果。

原因：**

最常见的原因是 CFG值过高（超过12），或者 VAE文件不匹配**。

修复步骤：**

  1. 降低CFG**：把CFG从12降到7-8试试
  2. 更换VAE**：如果你手动加载了VAE，试试用模型自带的VAE（即不手动加载，直接从Checkpoint Loader接）
  3. 检查VAE匹配**：某些模型有专用的VAE（比如SDXL的vae-ft-mse-840000），用错了会颜色异常

9.7 错误：两张图之间几乎一模一样（seed不生效）

错误的现象：**

你改了Seed值，但生成的图片看起来几乎一模一样**——只是微小的像素变化。

原因：**

你使用了 euler_ancestral 或其他"祖先采样器"，它们本身就有很大的随机性，导致Seed的影响被掩盖。或者你的denoise值太低**（图生图时denoise<0.3，seed的作用很小）。

修复步骤：**

  1. 改用 euler 或 dpmpp_2m** 采样器（它们更严格遵循Seed）
  2. 如果是图生图，提高denoise到0.5以上
  3. 确认Seed值确实不同（有时候手误填了同一个数字）

9.8 错误：ControlNet没有生效

错误的现象：**

你搭好了ControlNet工作流，但生成的图片和没用ControlNet完全一样**——姿势、构图没有任何变化。

原因：**

ControlNet模型的版本和你的主模型不匹配！最常见的是：主模型是SDXL，但ControlNet是SD 1.5版本的（或者反过来）。

修复步骤：**

  1. 确认版本匹配**：

- SD 1.5模型 → 使用SD 1.5版本的ControlNet（文件名含 sd15）

- SDXL模型 → 使用SDXL版本的ControlNet（文件名含 xl 或 sdxl）

- Flux模型 → 使用Flux专用的ControlNet

  1. 检查Strength值**：确保ControlNet的strength > 0.3（太低等于没用）
  1. 确认节点连接正确：ControlNet Apply的输入必须是从正向提示词**来的conditioning，输出再接KSampler的positive

9.9 错误：工作流加载后节点不全

错误的现象：**

你下载了一个工作流（.json或.png），拖入ComfyUI后，有一部分节点丢失**，或者出现"Unknown node"的报错。

原因：**

这个工作流使用了你没有的自定义节点或不同版本的ComfyUI**。

修复步骤：**

  1. 查看报错信息，找出缺少的节点名字
  2. 打开ComfyUI Manager → Install Missing Custom Nodes**
  3. 如果Manager找不到，去GitHub上搜索该节点并手动安装
  4. 如果节点已经废弃或改名，需要找更新版本的工作流

提示：** 一个工作流的截图中通常包含了它的"工作流元数据"——把截图拖回ComfyUI就能还原。但不是所有截图都包含这个信息（需要ComfyUI生成的图片才包含）。

10.1 工作流组织：命名、分组、注释

随着你的工作流越来越复杂（几十个节点互相连接），清晰的组织变得至关重要。

给节点重命名

默认情况下，所有节点都叫"KSampler"、"CLIP Text Encode"——如果你有3个KSampler，根本分不清谁是谁。

操作： 右键点击节点 → 选择 "Title"** → 改为有意义的名字（如"KSampler_文生图"或"KSampler_高清放大"）

✅ 好的命名：
  [CLIP Text Encode: 正向提示词-主体]
  [CLIP Text Encode: 正向提示词-背景]
  [KSampler: 首次生成 × 低分辨率]
  [KSampler: 高清放大]

❌ 不好的命名：
  [CLIP Text Encode]
  [CLIP Text Encode_1]
  [CLIP Text Encode_2]

使用分组（Group）

你可以把相关的节点框在一个分组**里，让工作流一目了然。

操作： 选中多个节点（按住Ctrl点击）→ 右键 → "Group Selected"**（或快捷键 Ctrl+G）

分组建议：**

┌─────────────────────────────────┐
│ 组1: 模型加载 (Model Loading)   │
│  [Checkpoint Loader] [LoRA]     │
└─────────────────────────────────┘

┌─────────────────────────────────┐
│ 组2: 提示词 (Prompting)         │
│  [CLIP Text Encode 正] [CLIP负] │
└─────────────────────────────────┘

┌─────────────────────────────────┐
│ 组3: 精确控制 (Control)         │
│  [ControlNet] [IP-Adapter]      │
└─────────────────────────────────┘

┌─────────────────────────────────┐
│ 组4: 生成 (Generation)          │
│  [KSampler] [VAE Decode]        │
└─────────────────────────────────┘

添加注释

在关键节点旁边添加注释文字，解释这个节点是做什么的。

操作： 右键 → "Add Note"** → 输入文字

注释示例：**

[注意] 这里的denoise不能超过0.6，否则会改变人物面部特征
[提示] 先跑一次再看效果，不要一次性批量生成太多
[参数] CFG=7对于这个模型是甜蜜点

为什么这很重要：**

  • 下次你自己打开这个工作流，不用重新"破解"每个节点的作用
  • 分享给别人的时候，对方能快速理解你的思路
  • 方便调试——加了注释的工作流出错的概率更小

10.2 5分钟规则：拿到一个工作流先分析再使用

一个来自社区的"5分钟规则"：拿到别人的工作流，花5分钟分析它，而不是直接点生成**。

实际示例：分析一个"高清放大"工作流

你从网上下载了一个"高清放大"工作流，包含以下节点：
[Load Image] → [KSampler] → [VAE Decode] → [Upscale Image] → [Save Image]
                                    ↑                           ↑
                              [另一个KSampler]            [另一个Save Image]

你的5分钟分析：**

第1分钟：看整体结构**

  • 这个工作流有两条路径？为什么有两个KSampler？
  • 哦——一条是"原始图"，一条是"放大后的图"

第2分钟：追踪关键连接**

  • 第一个KSampler的输出分成了两路：一路直接解码保存（原始分辨率），另一路送到第二个KSampler（做高清放大）
  • 第二个KSampler的latent输入来自第一个KSampler的输出

第3分钟：检查参数**

  • 第一个KSampler: steps=30, cfg=7, denoise=1.0（正常值）
  • 第二个KSampler: steps=20, cfg=5, denoise=0.4（denoise低！因为是高清放大，要保留原图结构）

第4分钟：找潜在问题**

  • Upscale Image用的是"4x_NMKD-Superscale"模型——检查自己有没有这个模型
  • 如果没有→去下载或换一个放大模型

第5分钟：做决定**

  • 这个工作流适合我当前的需求吗？（是的，我想放大一张图）
  • 第一个KSampler对我来说多余吗？（如果已经有了原图，可以跳过第一个KSampler）

5分钟规则的好处

  • 避免"闭眼跑别人的工作流，出来一团糟也不知道为什么"
  • 帮你理解别人的设计思路，转化为自己的知识
  • 提前发现依赖缺失（缺少的模型、节点）

练习： 下次在CivitAI下载工作流时，打开后先不要点Queue Prompt——花5分钟做上面的分析**。

Depth Anything V2 Processor

                └─ 输出一张"深度图"（越白越近，越黑越远）

即使不知道具体技术细节，从名字就能猜到：这个节点能提取一张图片的深度信息**。

步骤2：查文档或GitHub

  • 在Google搜索 "Depth Anything V2 ComfyUI"
  • 找到节点的GitHub仓库或Wiki页面
  • 看README中的"快速开始"部分

高级节点通常附带示例工作流（在GitHub的 examples/ 文件夹或 workflows/ 文件夹）。

  • 下载示例工作流
  • 拖入ComfyUI
  • 看它怎么连接到其他节点

步骤4：最小化测试

用一个最简单的输入来测试：

[Load Image]（随便一张图）→ [新节点] → [Save Image]

什么都不加，就看这个节点的输入输出。看输入一张图后，输出变成了什么**。

步骤5：逐步增加复杂度

理解基本功能后，再把它整合到你的工作流中。比如Depth Anything提取的深度图可以：

  • 作为ControlNet Depth的输入
  • 用来做景深效果
  • 做3D重建的输入

核心原则

永远从一个"最小可工作示例"开始。新节点要做的第一件事：给它一个输入，看它输出什么。**

11.5 五个技术预言：2027-2028

预言一：实时生成——从"等待"到"互动"

当前AI视频生成需要数秒到数分钟。但到2028年，实时生成将成为现实：

  • NVFP4等量化技术**将VRAM需求降低60%，消费级GPU能运行更大的模型
  • DGX Spark**等桌面级AI超算正在普及（2999美元）
  • 流式生成技术**正在从LLM扩展到视频领域

当AI视频生成达到实时（每秒24帧以上），交互式AI叙事**将成为可能——游戏中的动态过场动画、直播中的实时风格迁移、VR中的AI生成环境。这将彻底改变"媒体消费"的本质。

预言二：Agentic AI——工作流即智能体

2026年被称为"AI智能体元年"。Agentic AI正在从对话式AI进化为能够自主规划、执行、观察和迭代的系统。这与ComfyUI的工作流概念有着天然的对应关系：

  • ComfyUI工作流** = 静态的AI管线（固定节点序列）
  • Agentic工作流** = 动态的AI管线（根据中间结果自主决定下一步）

可以预见，未来的ComfyUI工作流将不再是固定的节点序列，而是包含决策节点、循环节点、条件分支**的智能系统。一个工作流可以：

  1. 分析输入内容 → 判断风格需求 → 选择合适的模型 → 生成 → 评估质量 → 决定是否需要重新生成
  2. 如果角色一致性不达标 → 自动切换到参考图模式 → 重新生成 → 再评估

这本质上是让ComfyUI从'被动执行工具'进化为'主动创作智能体'。** 创作者的角色将从"手动操作每一个节点"转变为"设定目标和约束，让系统自主执行"。

预言三：本地模型的黄金时代

很多人曾断言AI创作最终会全部迁移到云端。但现实恰恰相反——本地AI模型正在迎来黄金时代。**

原因有三：

  1. 隐私与合规**：商业客户无法将品牌资产上传到未知云服务
  2. 成本结构**：本地推理的单次边际成本趋近于零，而云API按调用计费
  3. 硬件进步**：量化技术让消费级GPU能运行过去需要数据中心才能运行的大模型

当一张RTX 5090可以在本地运行FLUX.2 Klein 9B并高效工作，当"权重流式处理"让系统RAM可以在VRAM不足时充当后备，"本地AI工作站"正在成为新一代创意专业人士的标准配置。**

预言五：开源AI工具的胜利

ComfyUI的成功揭示了开源AI工具的独特竞争力：

  1. 社区飞轮**：免费用户贡献节点和工作流 → 吸引更多用户 → 部分转化为付费服务
  2. 模型中立性**：不绑定任何特定模型 → 价值随模型生态自动增长
  3. 可审计性**：每个节点都可检查 → 专业用户信任开源胜过黑盒
  4. 更新速度**：在模型迭代极快的时代，开源架构天然具有速度优势

在AI领域，由于模型迭代速度极快，封闭工具永远跟不上开源工具的更新节奏。** ComfyUI可以做到"模型发布当天即支持"，而Adobe Project Graph在Firefly模型发布后数月才更新。在"模型速度"竞争的时代，开源架构天然具有优势。
