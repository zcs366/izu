# P0 执行报告

## P0-1：WSL Docker 实测 OpenHands ✅

### 安装过程

| 项目 | 数值 |
|------|------|
| **主镜像** | `ghcr.io/all-hands-ai/openhands:0.50` — **1.9 GB** |
| **运行时镜像** | `ghcr.io/all-hands-ai/runtime:0.50-nikolaik` — **8.74 GB** |

| **启动命令** | `docker run -d -p 3001:3000 -v /var/run/docker.sock:... -v ~/.openhands:/.openhands ...` |

| **访问地址** | http://localhost:3001（3000已被Open WebUI占用） |
| **Python版本** | 3.12.10 |
| **运行用户** | root |

### 关键发现

1. ⚠️ **镜像总大小 10.6GB** — 对普通用户太重型。这也是匠石建议不引入SDK的原因——完整OpenHands生态太重。
2. ⚠️ `docker.all-hands.dev` 自定义Registry在WSL下DNS不通，**ghcr.io 是唯一可用镜像源**
3. ✅ 启动快速（11秒），服务稳定

## P0-2：Docker 沙箱隔离策略分析 ✅

### 挂载点分析

| 挂载 | 源 | 目标 | 权限 | 用途 |
|------|-----|------|------|------|
| bind | `~/.openhands` | `/.openhands` | rw | 用户状态/文件存储 |
| bind | `/var/run/docker.sock` | `/var/run/docker.sock` | rw | **⚠️ 沙箱容器管理** |

### 沙箱架构

```
OpenHands 主容器 (1.9GB)
  ├── FastAPI + Uvicorn + Socket.IO
  ├── 挂载 docker.sock ──────────────┐
  └── 需要沙箱时 ────────────────────┤
                                      ▼
                          docker run runtime:0.50-nikolaik (8.74GB)
                            ├── 独立的文件系统
                            ├── 独立的网络命名空间
                            └── 执行用户代码
```

### 隔离策略总结

| 机制 | 实现方式 | 安全等级 |
|------|---------|---------|
| **文件系统隔离** | 独立容器，不挂载宿主机路径 | 🟢 好 |
| **网络隔离** | 独立网络命名空间 | 🟢 好 |
| **进程隔离** | 独立PID命名空间 | 🟢 好 |
| **权限控制** | 非root运行（nikolaik镜像的node用户） | 🟡 中 |
| **资源限制** | 容器级别的CPU/内存cgroup | 🟡 未明确配置 |
| **⚠️ docker.sock暴露** | 主容器挂载docker.sock，可创建任意容器 | 🔴 **高风险** |

### 关键风险

**`docker.sock` 挂载 = 如果Agent被攻破，攻击者可以启动特权容器逃逸到宿主机。** OpenHands接受此风险以换取动态沙箱管理能力。这对izu不适用——我们不需要多租户沙箱，ProcessSandbox方案更安全。
