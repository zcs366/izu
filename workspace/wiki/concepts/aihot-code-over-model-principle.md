# AIHOT：用代码而非模型的Agent设计哲学

## 一句话

AIHOT 是卡兹克（AI自媒体人）做的一个 AI 信息筛选工具，2026年5月开源。其核心设计哲学是：**能用代码就别用模型**——模型只做打分这一件事，其余全用公式和规则。

## 核心设计

### 1. 三层信源分级

168 个精选信源，分三级：

| 等级 | 内容 | 示例 | 权重 |
|------|------|------|------|
| T1 | 官方一手信息 | OpenAI 官方博客、Anthropic 工程博客 | 最高 |
| T1.5 | 官方社交媒体 | OpenAI Twitter | 中 |
| T2 | KOL、媒体、资讯站 | 第三方报道 | 低 |

### 2. 模型只做一件事

经过 11 版迭代后的最终架构：

- **模型职责**：对每条信息打 5 个维度的分（不打最终分、不判断精选）
- **代码职责**：信源权重计算、类型加权、是否过精选阈值——全部用公式
- **Prompt 演化**：从 600 行砍到 200 行

### 3. 事件聚类

用 embedding 将语义相近的条目聚到同一事件簇，选最权威的当主条。同一件事精选页只展示一条。

### 4. 日报零延迟

每天早上 8 点自动生成日报——不需要模型，因为精选、分类、翻译在入库时已全部完成，日报只需要分桶排序。

## 关键教训

1. **规则做加法，模型反而变笨**：V7→V8 是负向优化。最终是减法救了项目。
2. **能提前算好的绝不现算**：日报生成 1 秒搞定，因为所有重活都在入库时做完了。
3. **做给自己用的比做给别人用的靠谱**：自己是用户，反馈闭环极短。

## 对 Agent 设计的启示

这个案例回答了 Agent 工程化的核心问题：**模型和代码的边界在哪？**

- 模型的优势：语义理解、内容评估
- 代码的优势：确定性的权重计算、规则判断、批处理

把模型用在它最擅长的环节，其余全用代码——这个原则对所有 Agent 项目适用。
