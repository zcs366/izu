# Agent 交叉审核循环（Cross-Review Loop）

> 概念 | 多 Agent 协作中的质量闭环机制

## 定义

Agent 交叉审核循环：让多个 AI Agent 互相审查对方产出，用**量化评分**代替主观判断，**只保留可测量的改进**，不达标就回滚重做。

源自 Karpathy 的 AutoResearch 方法论，由鸟窝（smallnest）迁移到软件开发领域。

## 核心机制

```
识别任务 → Agent-A 实现 → Agent-B 审查打分 → 达标？→ 合并
                              ↓ 不达标
                         反馈报告 → Agent-A 重做
```

关键不是"多个 Agent 一起干"，而是**评分标准必须是可测量的**。不依赖"我觉得代码不错"，而是五维度（正确性/风格/测试/安全/性能）各有 0-10 分的硬标准。

## 与 Spec Coding 的关系

Spec Coding 解决的是"AI 写代码前先定规矩"。交叉审核循环解决的是"AI 写完代码后怎么验证规矩被执行了"。两者是同一方法论的前后两端：**Spec 定义检查点，Cross-Review 执行检查点**。

## 对 izu 流水线的启示

izu 七智能体目前在中间交接处缺少硬检查。交叉审核循环的三要素可直接适配：

1. **量化评分**：每个智能体的产出设 3-5 个可测量指标
2. **交叉验证**：让"织"审查"搜"的结果，而非信任传递
3. **回滚机制**：不达标不退给下一步，避免烂尾传递

## 参考实现

- **autoresearch**（smallnest）：GitHub Issue → Codex 实现 → Claude 审查打分 → 通过/回滚
- **Karpathy autoresearch**：提出想法 → 修改 train.py → 跑实验 → val loss 下降？→ 保留/回滚
- 两者共享同一哲学：**只保留可测量的改进**
