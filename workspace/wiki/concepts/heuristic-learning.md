# 启发式学习（Heuristic Learning）

## 核心定义

> **不训练任何神经网络，不更新任何模型权重，仅仅通过修改代码规则和维护软件系统来实现学习。**

由OpenAI工程师翁家翌提出，核心论文：[Learning Beyond Gradients](https://trinkle23897.github.io/learning-beyond-gradients/)

## 核心机制

启发式系统（HS）的完整闭环：

```
状态（可读表示）→ 动作（代码逻辑生成）→ 反馈（多元输入）→ 更新（Agent直接改代码）→ 记忆（显式存储）
```

## 与深度强化学习的关键差异

| 维度 | DRL | HL |
|------|-----|-----|
| **存储介质** | 神经网络参数（黑箱） | **程序代码**（可读可审计） |
| **更新方式** | 梯度下降（渐进微调） | **Agent直接修改代码**（一步跃迁） |
| **遗忘管理** | 灾难性遗忘（结构性问题） | **工程化可管理**（测试+版本控制） |
| **样本效率** | 需要海量样本 | 一次有效代码更新即跃迁 |
| **可解释性** | 差 | 代码可直接翻译为自然语言 |

## 核心优势

1. **可回归测试性** — 旧能力写入测试用例，新修改不破坏旧功能
2. **样本效率** — 代码级更新实现策略跃迁，无需海量样本
3. **可解释性** — 代码策略可直接翻译为自然语言
4. **缓解灾难性遗忘** — 旧能力固化在规则和测试中，不依赖权重存储
5. **约束过拟合** — 工程化正则化

## 为什么专家系统失败了而HL成功了

**关键区别**：维护者从"人"变成了"编码Agent"。

- 专家系统：人类手工维护 → 臃肿、脆弱、无法迭代的"代码怪物"
- 启发式学习：编码Agent作为持续智能输送管道 → 自主进化

> "人工维护如同工业革命前的手工纺纱；编码Agent如同纺织机。"

## HL也会遗忘——但性质不同

HL的遗忘是**工程问题**而非**结构问题**：
- 新规则破坏旧场景 → 写回归测试
- 记忆模块误导 → 清理记忆
- 测试覆盖窄 → 补测试
- 规则堆积 → 压缩重构

## 耦合复杂度：关键设计指标

**定义**：编码Agent一次更新需要兼顾的状态、规则、测试、反馈和历史约束的总数量。

**关键规则**：
- 反馈信号越清晰，Agent能处理的耦合复杂度越高
- 模块边界越清晰，耦合复杂度越可控
- 不取决于代码行数（500行好代码 > 80行坏代码）

## 局限与未来方向

**局限**：
- 无法做纯代码难以表达的复杂感知（如图像分类）
- 受限于代码表达能力和长程泛化

**未来方向：System 1（感知网络+HL） + System 2（LLM Agent）深度融合**

## 与izu/ITA的直接关联

> ⚠️ **核心共鸣点**：

**ITA项目的三语交互**（自然语言↔代码↔AI内部编码）本质上是启发式学习的高阶实现：

| ITA概念 | HL对应 |
|---------|--------|
| Compact Encoding | 代码策略 |
| 三语交互（Agent读写） | 编码Agent修改代码 |
| Routing机制 | HL的耦合复杂度管理 |
| Compression策略 | HL的"只增长不压缩必成屎山" |
| 影子路径验证 | HL的"新规则在影子路径上跑50 tick后对比" |

**对izu/核战队的直接启示**：
- 核战队的"以代码为知识载体"已经走在HL路线上
- 需要引入**耦合复杂度**作为设计质量指标
- 需要建立**回归测试体系**固话旧能力
- 压缩（compaction）不是优化而是防退化的必要操作
