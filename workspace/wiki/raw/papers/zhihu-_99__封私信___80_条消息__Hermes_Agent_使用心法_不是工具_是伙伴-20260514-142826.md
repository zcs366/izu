一、四条设计哲学
1. 渐进式自治

Hermes 不是一步到位的全自动 agent。它是渐进的：

单次对话 → 记忆积累 → 技能固化 → cron 自主运行

先用 hermes chat 单次对话解决问题
发现重复模式 → 保存为 skill
需要定时执行 → 升级为 cron job
复杂任务 → 拆解为多 agent 协作

不是「装上就全自动」，是「越用越自动」。每次用都在为下一次铺路。

2. 人在回路

所有危险命令默认需要审批。Agent 建议，人拍板。

这不只是安全考虑。更重要的是——你不拍板的东西不会自动执行。这意味着 Agent 永远不会在你不知情的情况下做不可逆操作。很多人在用 Agent 时焦虑「它会不会乱来」，Hermes 的设计从根上解决了这个问题。

3. Skills 是复利单位

Skill 是 Hermes 最核心的差异化能力。它不是什么「插件市场」的东西——是你和 Agent 一起积累的「可复用的问题解决流程」。

粒度原则：

太细：单次命令 → 不值得存。你不需要一个 how-to-cat-a-file skill
太粗：万能手册 → 每次加载 token 爆炸
刚好：一个可复用的工作流，5-15 步，含坑点和验证

你的第一个 skill 可能是「怎么查 A 股 PE 分位」。一个月后你会有 20 个。三个月后 Agent 不用你解释就知道你要什么。

4. Memory 贵在精不在多

Hermes 的 memory 不是对话日志。是「以后还会用到的关键事实」。

存：你的偏好、环境配置、踩过的坑、重要的决策理由
不存：任务进度、临时 TODO、已完成工作的流水账

很多人抱怨「Agent 记性不好」，其实不是记性不好——是塞了太多垃圾。

二、五种高级模式
1. Cron + Skill：定时任务从「能做」到「聪明做」

不是简单的「每天早上 8 点跑个脚本」。是：

Python 采集数据 → Agent 分析解读 → 多平台推送

比如每天扫描 RSS → Agent 判断哪些值得看 → 推送飞书。有重大突破全量推，常规一天一行摘要，没东西就不推。

2. 多 Agent 协作：不是一个大 Agent，是一群专精 Agent

Hermes 支持两种模式：

delegate_task：子 agent 同步执行，适合快速并行子任务
独立进程：完全独立的 agent，长时间跑，通过 tmux 通信

社区有人用 9 个 Agent 创建两家 AI 公司互相竞争 GitHub Stars。别被数字吓到——核心思路是「每个 Agent 只干一件事」。

3. Profiles 多身份

不同项目/角色用独立的配置、记忆、skill。比如：

日常管家 profile：全工具集，闲聊+帮查东西
投资分析 profile：只开 web+terminal+file，专注不跑偏

同一个人，不同场景用不同 Agent——token 消耗立降。

4. MCP 工具扩展

MCP（Model Context Protocol）让 Hermes 可以接入外部工具服务器。截至 2026 年中，MCP 是 agent 生态最大的趋势——可以接入金融数据、浏览器自动化、专业软件。Hermes 本身就支持作为 MCP Server 运行，把自己的能力暴露给其他 Agent 调用。

5. Webhooks 事件驱动

Cron 是「每 X 分钟检查一次」。Webhooks 是「有事发生才通知」。对于指数暴跌预警、新闻突发等场景，webhooks 比轮询更合理。Hermes 原生支持 webhook 订阅。

三、新手常踩的三个坑
坑一：把 Agent 当万能的神

扔一句「帮我做投资分析」然后等结果。Agent 不是神——它需要你告诉它：查什么数据、分析什么维度、输出什么格式。开始阶段越具体，长期越省力。

坑二：不存 Skill

每次遇到同样的三步操作，手动重做。Agent 不会主动说「你应该把这个存成 skill」。你得养成习惯——任何超过 3 步的操作序列，做完就问一句「这值不值得存成 skill」。

坑三：Memory 塞满垃圾

把对话当聊天记录存。Hermes 的 memory 上限有限（默认几千字符），每一条都在和其他条目竞争注意力。只存「以后还会用到的事实」，不存「今天做了什么」。

四、前沿方向（2026）
Agent 组合模式

一个「编排 agent」管理多个「执行 agent」——类似 Kubernetes 的 controller + worker 模型。

MCP 扩展生态

外部工具、数据源、计算资源都可以通过 MCP 接入。对深度用户最大想象空间是接入专业数据。

Voice + 多模态

内置语音转录、TTS、视觉分析。前沿方向是 voice-first 交互——你说 → agent 做 → 语音反馈。

记忆后端升级

支持 Honcho、Mem0 等外部记忆系统，提供向量搜索、语义关联、自动总结。

五、如果你刚开始用 Hermes

第一周： 只用 hermes chat。让它帮你查东西、解释概念、改代码。养成每次完成后扫一眼 skill_manage 的习惯——有没有值得存下来的操作。

第一个月： 建第一条 cron。选一个你每天都做的事（比如早间新闻摘要），让 Agent 定时跑。跑通 Script → Agent → 推送的完整链路。

第三个月： 你的 Skills 应该有 10+ 个了。Agent 不用你说也大概知道你的偏好。这时候可以开始试验多 Agent 协作——把复杂任务拆成几个并行的子任务。

最关键的一条：Agent 是复利资产。 你今天的每一次「教会它」，都在让明天更省力。一个月后回头看，你会发现它已经不是工具——是伙伴。
