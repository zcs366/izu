你有没有过这种体验：让 AI 帮你实现一个功能，它三分钟写完了，跑了一下还能用。你很高兴，觉得效率提升了十倍。

然后第二天你想加个新功能，发现昨天写的代码没有测试，没有文档，接口设计一塌糊涂。改一处坏三处，跟推多米诺骨牌一样。更离谱的是，你翻了一下代码，发现 AI 连最基本的安全检查都没做——用户输入直接拼进了 SQL 语句。

这种开发方式有个名字，叫 Vibe Coding：给个模糊意图，让 AI 自由发挥，跑通了就算完事。短期看确实爽，但代价是技术债务疯狂累积——Controller 里塞业务逻辑，Service 里直接拼 SQL，异常被 catch 后只打印一句 failed，第二天再改就开始连环炸。等到要维护的时候，你会发现「能跑」和「能交付」之间隔着一道鸿沟。

与它相对的是 Spec Coding：先定义好技术规范和代码风格，让 AI 始终在同一套规则下干活。说得直白一点，Vibe Coding 是放养，Spec Coding 是立规矩。

AI 编码工具的能力确实越来越强，但模型越强，走捷径的毛病越明显。拿到任务就一股脑往前冲，不会主动补上测试、边界、安全和可维护性。这也是 AI 编码最容易翻车的地方。

小金 最近关注到 Addy Osmani 开源的一个项目：agent-skills。它把资深工程师的工作流和开发规范，封装成了 20 个可复用的技能包，让 AI 在每个开发阶段都按工程规范干活。

我一开始以为这又是一个 Prompt 集合，看完仓库结构后，才发现它真正有价值的不是提示词，而是把工程流程拆成了可执行的检查点。

项目已经拿下三万多 GitHub Star，而且还在持续上涨。它不是单纯堆 Prompt，而是把需求、计划、测试、评审、上线这些工程动作拆成了可执行流程。

即使你暂时不用 AI 编码工具，这个项目的设计思路也值得花时间研究。

核心是 22 个 Skills（技能包），覆盖完整开发生命周期：Meta（发现用哪个 Skill）→ Define（澄清需求）→ Plan（分解任务）→ Build（写代码）→ Verify（证明正确）→ Deploy（上线）。每个 Skill 不是一段 Prompt，而是一套包含检查点、规范约束、交付标准的可执行流程。

场景举例：当你让 AI "加一个用户注册功能"，Spec Coding 模式下 AI 会先问：输入校验规则？密码强度？邮箱验证？数据库 schema？测试覆盖？——而不是直接扔给你一段能跑但不安全的代码。

适用场景：个人开发者或小团队，缺乏成熟的工程流程；使用 Claude Code、Codex、Cursor 等 AI 编码工具的开发者；需要快速建立工程规范的项目。不太适合的场景：只是偶尔让 AI 写几段代码的轻度用户；已经有成熟开发流程和完整团队的大型项目；完全不懂工程规范的纯新手。

项目地址：https://github.com/addyosmani/agent-skills
