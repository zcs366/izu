朋友们，这是一个喜大普奔的好消息：
TinyFish 把 Search 和 Fetch 两个 API 彻底免费了。

不是送几次试用额度那种，是拿个 Key 就能用、永久免费的那种。Search 每分钟 5 次，Fetch 每分钟 25 个 URL。

我盯着这个公告看了好几秒，第一反应是：它踩中了一个太好的时间点。
一、Agent 的最大短板，终于有人补上了
你有没有发现，最近半年 Agent 这个赛道突然加速了。

Claude Code、Codex、Cursor Agent、OpenClaw、Hermes，各种框架和工具井喷一样往外冒。

但它们有个共同的短板：跟互联网之间隔着一层纱。

你让 Claude Code 查一个库的最新文档，它得去网上找。你让 Hermes 每天早上抓一遍 V2EX 热帖推送到微信，它得能读网页。你让 OpenClaw 帮你比价，它得能搜索、能读页面。

这些对人类来说跟呼吸一样自然的操作，对 Agent 来说一直是个麻烦事。

要么自己搭爬虫，要么花钱买第三方 API。很多想做 Agent 的人，就卡在这儿。
二、我自己接进去试了，说几个有意思的玩法1. 给 Claude Code 装上”自己查资料”的能力
TinyFish 支持 MCP 协议。

你把它的 MCP Server 丢进 Claude Code 的配置里，Claude 就能直接搜索和抓取网页了。

之前 Claude Code 想查一个 npm 包的兼容性问题，每次都得我自己打开浏览器搜完再粘给它，然后它才能继续干活。现在直接让它自己去查就行，拿到干净的 Markdown 内容直接放进上下文里。

我对以前那种”我无法访问互联网”的提示的评价是：可以永远消失了。
2. 给 Hermes 加上”眼睛”，跑通资讯推送
Hermes 做个人自动化很擅长，但涉及网页信息的部分一直比较弱。

现在通过 REST API 把搜索和抓取能力接进去，一个很自然的场景就跑通了：

每天早上让 Hermes 定时搜索几个关键词的最新资讯，抓取摘要，推送到飞书或微信。

我自己跑了一个监控 Claude 相关资讯的小任务，已经稳定跑了好几天了。

之前要做这事，得自己写爬虫逻辑处理各种乱七八糟的 HTML。现在就是两个 API 调用的事，搜一下拿到 URL，抓一下拿到干净正文，喂给大模型总结完事。效果比我想象的好。
3. 真实浏览器渲染 + stealth 模式，爬虫人的福音
TinyFish 的 Fetch 不是简单的 HTTP GET，它是用真实浏览器渲染的。

JavaScript、SPA、动态加载的内容都能处理。配合 stealth 模式，能过 Cloudflare 这类反爬检测。

我自己写爬虫写了好几年，说真的，处理反爬、渲染 JS、清理 HTML 这些脏活累活，每次都得从头搞一遍，烦得要死。

现在有人把这些基础设施做好了还免费，说实话没理由不用。
三、3分钟接进去，真的不难
说了这么多，很多朋友可能想问：怎么接？麻不麻烦？

我来说一下流程，真的很快。

第一步，注册账号。

打开 https://agent.tinyfish.ai/sign-up 直接注册，邮箱就行，完全不用绑信用卡。新手还能领 500 免费 credits，开局就有礼包。

第二步，拿 API Key。

注册成功后系统直接给你一个 Key，一个 Key 能用所有功能，不用管理一堆密钥。

第三步，选你顺手的接入方式。

最推荐的是 MCP 协议，把 TinyFish 的 MCP Server 地址丢进 Claude Code、Cursor 的配置里，两分钟搞定，你的 Agent 就有了上网的能力。

如果你是用 n8n、Dify、LangChain、CrewAI 这些框架，也都有官方集成，文档里有现成的示例代码，直接抄就行。

不想用框架，REST API 和 Python/TypeScript SDK 也都支持，想怎么调怎么调。

官方文档在这：https://docs.tinyfish.ai/ ，Search API 和 Fetch API 的完整示例代码都在里面，写得非常详细，我第一次看就看懂了。不会安装的话，直接把这个官方文档给ai看。

我对这个接入体验的评价是：比我预期的简单太多了。
四、最后再说一个新东西：Codex 直接控制 Chrome 了
说到 Agent 和浏览器的关系，不得不提 Codex 最近的新动作。

Codex App 现在直接支持在 Chrome 浏览器里单独操作了，而且可以并行多个 Chrome 窗口，还完全不和你抢鼠标。

可能很多朋友会问：这和之前的 computer use 插件有什么区别？

我仔细对比了一下，区别还挺大：

Token 消耗不同。 computer use 本质上是截图 + OCR 识别再去操作，比较费 Token；而 /chrome 是代码层次的操作，省 Token 得多。

操控范围不同。 computer use 是全局操作，可以控制剪映、PS、AE、WPS 这些工具；/chrome 只能操控 Chrome 浏览器。

会不会抢鼠标不同。 computer use 有时候会抢你的鼠标，/chrome 完全不会，它独立在后台跑，并行多个窗口也没问题。

我对 /chrome 的评价是：在需要操控浏览器的时候，首选它。

TinyFish 给 Agent 接上了”眼睛”，Codex 的 /chrome 给 Agent 接上了”手”。

免费的基建，开放的接口，越来越聪明的模型，再加上这些让 Agent 真正触达互联网的能力——这些东西凑在一起的时候，会发生什么？
