# 深度解析三大 Agent 上下文工程：Claude Code、OpenClaw、Hermes 的设计哲学

**来源**: 歪斯Wise (公众号)
**核心主题**: 上下文工程（Context Engineering）——决定模型每轮对话中能看见的内容，直接影响AI的任务理解、指令遵循和执行表现。

## 1. 上下文工程是什么？

**Anthropic 定义**: 通过持续优化上下文，保障大模型在固有约束下持续地实现预期效果。

### 模型运行时看到的上下文组成
持久的记忆、全局的规则（CLAUDE.md/AGENTS.md）、系统提示词、用户提示词、MCP/Function等工具描述、工具调用返回结果、近x轮对话历史、压缩后的摘要……

### LangChain 四维框架
- **Write**: 把信息分门别类记录
- **Select**: 按需选择信息
- **Compress**: 总结、裁剪上下文，保留高价值信息
- **Isolate**: 隔离上下文

### 上下文要解决的5大问题：窗口有上限、上下文变长会变笨、越长越贵越慢、新会话信息丢失、工具噪音

## 2. Claude Code：渐进式上下文压缩

### 5层压缩思路
1. 处理高噪音的工具结果
2. 历史裁剪
3. 带缓存感知的轻量压缩
4. 上下文折叠/自动压缩（全文换摘要）
5. 压缩后自动恢复

**关键优势**: 压缩后自动恢复工作集，避免重新读取刚刚编辑的文件、重新激活skills。

## 3. OpenClaw：极度开放的上下文框架

### 核心特性
- 裁剪/压缩机制相似，会话重置
- context-engine 插件：可替换组件
- /context list、/context detail、usage 视图

**设计哲学**: 开放平台，高度可定制。

## 4. Hermes：把交接当成常态

### 双层压缩机制
| 层级 | 阈值 | 作用 |
|------|------|------|
| Gateway层 | 85% | 兜底机制 |
| Agent层 | 50% | 主动压缩 |

### 结构化摘要（交接文档）
每次压缩明确包含：目标、完成进度、核心决策、相关文件、下一步。

### 增量更新
多次压缩后不会从零重新总结，而是在上一次摘要上追加更新。

## 5. 给Agent设计的5条启发
① 上下文分层 ② 能删就删 ③ 缓存稳定性优先 ④ 交接文档代替总结 ⑤ 压缩后恢复

## 6. 总结

| Agent | 核心设计 | 优势 | 局限 |
|-------|----------|------|------|
| Claude Code | 渐进式压缩+工作集恢复 | 稳定、不易失忆 | 封闭、不可定制 |
| OpenClaw | 开放框架+可替换引擎 | 高度可定制 | 需主动配置，开箱不稳定 |
| Hermes | 双层压缩+结构化交接 | 早压缩、交接清晰、增量更新 | 较新，生态待完善 |
