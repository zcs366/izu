# 商鞅 —— 实验设计官

## 最小可行实验（20工时）

### 实验0号: CodeBERT Round-trip基线测试
**目标**: 回答「现有基线在哪？」
**工作量**: 4小时
**步骤**:
1. 选取CodeBERT（或GraphCodeBERT）作为编码器
2. 对BigCodeBench中的100个代码片段做encode → simple linear decoder → decode（不用FSQ/VQ，直接用连续隐空间）
3. 计算每个片段的round-trip edit distance和AST等价率
4. 结果：如果已有基线 > 85% AST等价 → 压缩空间大；如果 < 60% → 基础编码器就不够强

### 实验1号: FSQ量化对Steering的影响
**目标**: 回答「量化后steering向量还管用吗？」
**工作量**: 8小时
**步骤**:
1. 用CodeBERT对50个代码片段编码 → FSQ量化到各码本大小(4,8,16,32) → 计算量化噪声
2. 在未量化的隐空间训练「简洁性steering」向量（取长代码和短代码的差异向量）
3. 在量化后的隐空间施加同一steering向量 → 测steering效果衰减
4. 结果：如果steering效果衰减 < 20% → 量化对steering可容忍；如果 > 50% → 需在量化空间重新训练steering

### 实验2号: EasySteer代码Steering原型
**目标**: 回答「steering在代码场景是否有效？」
**工作量**: 6小时
**步骤**:
1. 在DeepSeek-Coder上部署EasySteer（已有vLLM集成）
2. 构造两个对照steering向量：(a) 简洁性 (b) 安全性（不生成危险代码）
3. 各测50条prompt → 计算成功率
4. 结果：如果成功率达标的prompt数 > 70% → steering方案可行

### 实验3号（备用/条件执行）: 多轮auto-encoding误差曲线
**目标**: 回答「语义滚雪球压缩的误差累积有多快？」
**工作量**: 2小时（如果有实验0的结果）
**步骤**:
1. 对10个代码片段做3轮auto-encoding
2. 每轮后计算累积edit distance
3. 结果：如果每轮误差增量 < 5% → 多轮压缩可行；如果 > 20% → 滚雪球机制不可行

## 成功/失败判断标准

| 实验 | 成功标准 | 失败标准 |
|------|----------|----------|
| 实验0 | AST等价率 ≥ 70% | AST等价率 < 50% |
| 实验1 | steering衰减 < 30% | steering衰减 > 50% |
| 实验2 | steering成功率 > 70% | 成功率 < 40% |
| 实验3（条件） | 每轮误差增量 < 10% | 每轮误差增量 > 20% |

**最小可信结论所需实验数**: 1 + 2 = 必须完成实验0+实验2。实验1和3可选但强烈推荐。
