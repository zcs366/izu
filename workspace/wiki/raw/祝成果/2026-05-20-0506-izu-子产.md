# 子产 · 需求判断与研究方向

## 需求判断：该不该做？

**该做。** 基于三个独立信号：
1. **Agent Skills革命已发生**（arXiv:2602.12430—62K GitHub star，4个月成为标准）。izu不内置技能支持将在6个月内过时。
2. **记忆系统已标准化**（LoCoMo/LongMemEval/BEAM），没有基准支持的记忆系统无法评估进展。
3. **自改进Agent已有可工作实现**（HyperAgents跨领域转移，imp@50=0.630），izu的自我进化路线已被外部验证。

**不做会怎样？** 6个月后，izu与开源Agent框架的差距将从"领先"变为"追赶"。

## 关键问题与假设

### 关键问题
1. **技能如何与izu现有记忆架构融合？** SKILL.md → 加载到izu的工作记忆中，还是作为独立索引？
2. **自改进循环的频率与触发条件？** 实时（每个response后评估）还是周期（每日总结）？
3. **安全门放在哪？** 26.1%社区技能含漏洞——izu如何过滤？

### 核心假设
- **假设1**：izu的技能系统应基于SKILL.md开放标准，而非自造协议
- **假设2**：自改进的最佳节奏是"事前（skill加载） + 事后（session总结）"，而非实时元认知（实时元认知太消耗上下文）
- **假设3**：Mem0的层次化记忆架构（decay-weighted + BM25+HNSW）是izu记忆系统的最佳参考

### 研究方向定位
**短期（2周）**：在izu中实现SKILL.md标准的技能加载器 + MCP工具桥接
**中期（6周）**：接入Mem0类记忆系统 + LoCoMo基准评估
**长期（12周）**：实现每日自改进循环（session日志→模式发现→skill更新）
