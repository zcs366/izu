# 惠施 — 概念辨析官

## 核心概念的操作性定义

### 1.「代码语义」(Code Semantics)
- **不可接受的定义**: "代码的含义"、"程序的行为"
- **操作性定义**: 给定一个代码片段 C，其语义 = 在指定输入 I 下执行 C 产生的输出序列 O。更精确地说，语义通过 round-trip 一致性测量：`encode(decode(encode(C))) ≈ encode(C)` 的编辑距离/输出等价性。
- **可测量**: 用 CodeBERT 的 [MASK] 预测准确率变化、or 执行轨迹的 bisimulation 距离

### 2.「理解」(Understanding)
- **操作性定义**: 一个压缩模型 M 对代码片段 C 的「理解」= M 的隐空间表示 h(C) 保留了多少可预测下游任务性能的信息。
- **测量方法**: 线性探针 (linear probe) 在 h(C) 上对bug检测/代码搜索/变量重命名三类任务的 F1 分数
- **拒绝模糊说法**: "模型理解了代码" → "模型隐空间在 bug 检测任务上线性可分 F1=0.85"

### 3.「Steering 成功」(Steering Success)
- **操作性定义**: Steering 成功 = 在隐空间施加方向向量 d 后，模型输出行为发生可预测的改变，且改变方向与 d 的理论方向一致。
- **测量**: Steering 向量 δ 作用于 h(C) 后，输出 O' 中目标属性 A 的变化 ∆A / ||δ||。比值 > 1.0 为有效 steering。
- **黄金标准**: 端到端测试——steering 后代码补全中特定 bug pattern 出现率从 p% 变为 q%。

### 4.「压缩」(Compression)
- **非模糊定义**: 压缩率 R = 原始 token 数 / 压缩后 token（或 bit）数。但仅压缩率无意义——必须绑定语义保留率。
- **率失真边界**: 对于代码序列，率失真函数 R(D) 给出在失真度 ≤ D 下的最小比特率。代码的特殊性在于其语义是离散的（正确/错误二元），不同于自然语言的连续语义空间。
- **关键问题**: 代码压缩的失真度量 D 应该是什么？执行等价性？输出等价性？还是 token-level BLEU？

### 5.「可证伪」(Falsifiability)
- **操作性定义**: 一项主张可证伪 = 存在一个有限实验，其否定结果能使主张的置信度下降超过 50%。
- **对本研究的意义**: 每轮合议的输出必须具备可证伪性，否则不进入下一轮。
