# 奥威尔

## 批判分析

### 逻辑拆解：ITA 轨道

**惠施 → 墨子 → 商鞅 → 鲁班 → 萧何 → 张仪 的逻辑链**
✅ **强链**：概念定义清晰 → 理论边界明确 → 实验设计针对理论空白 → 工程方案在理论约束内 → 资源匹配 → 风险识别准确

**但存在三个逻辑断层：**

### 漏洞 1：PCA 降维的信息损失假设
商鞅实验用 PCA 从 768d → 5-10d，假定 PCA 保留语义信息。
**反例**：代码的功能语义可能是高度非线性的——两个代码片段在 768 维空间中相距很远但功能等价（如递归 vs 迭代）。PCA 是线性降维，会丢失这种非线性关系。
**影响**：如果 PCA 就把语义信息丢掉了，后续 FSQ 量化就是「精确保留垃圾」。实验设计中没有控制这个变量。

### 漏洞 2：CodeBERTScore 的「语义」是语义吗？
CodeBERTScore 衡量的是 CodeBERT 嵌入之间的余弦相似度。
**谁在说话？** CodeBERT 是 MLM 预训练的——它学的是「哪些 token 经常一起出现」，而不是「这段代码做了什么」。
**反例**：`def f(x): return x+1` 和 `def g(y): return y+1` 的 CodeBERTScore 会很高（同结构），但 `def f(x): return x+1` 和 `def f(x): return x*2` 的 CodeBERTScore 可能也不低（同模式但不同语义）。
**这意味着**：CodeBERTScore 作为「语义等价」的度量，可能把结构相似但语义不同的代码误判为等价。

### 漏洞 3：izu Online Designer 的数据来源
子产/韩信/鲁班都假定「Agent 可以通过交互收集足够数据来进化 skill」。
**数据在哪里？** zu 不是 ChatGPT——每个用户每天可能只有几十条对话记录。一个典型的 MemSkill training run 需要数千条对话。如果数据量差 2-3 个数量级，所有的工程方案都是空中楼阁。
**张仪识别了这个问题**（收敛性），但给出的降级方案（Hybrid 模式）没有回答「数据量够不够」这个根本问题。

### 最大风险点（跨轨道）

**两根轨道的最大风险是同一个：评估信号的可信度。**
- ITA：CodeBERTScore 能否真正反映代码功能语义等价？（漏洞 2）
- izu：Agent 的 self-judgment 能否真正反映记忆质量？
- 两轨道都依赖不可靠的评估信号来做决策——ITA 基于此判断压缩是否成功，izu 基于此决定是否触发 skill 进化

**如果评估信号不可信，整个双轨道决策架构就建立在沙滩上。**
