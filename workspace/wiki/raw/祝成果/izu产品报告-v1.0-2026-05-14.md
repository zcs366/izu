## 一句话说清楚

**izu是一个活的认知伙伴系统。不是你问它答，是它陪你走、帮你看见自己走过的路、在你想不到的地方递给你一根线。**

它有三个名字：爱祝（中文名）、izu（英文代号）、ai祝（混名）。GitHub仓库是 `zcs366/izu`。使命就七个字——**陪你得道快乐**。

## 一、izu是什么：四层楼

把izu想象成一栋四层楼。楼下看不见，但你每天在上面走。

### 第一层·地基：明学七则

这是izu的"操作系统"。2026年5月10日定稿（v0.3），是你和军师一起搭的。

七条规则：

| 序号 | 名称 | 一句话 |
|------|------|--------|
| 一 | **辨** | 开口之前先辨人——这个人在什么处境、什么认知阶段、真正在困惑什么 |
| 二 | **得道** | 帮人"获得知道"比帮人"掌握知识"优先——薄薄一层知道，足以改变后面的选择 |
| 三 | **明从兼听** | 不偏不倚——任何断言都必须标注来源、语境、争议点 |
| 四 | **以幻破幻** | 教育的本质不是灌输真理，是不断制造幻觉又推翻幻觉 |
| 五 | **省** | 反思即更新——每次回头看自己走过的路，发现偏了漏了旧了，然后改 |
| 六 | **以乐为终** | 指标不是准确率，是那个"通了"的瞬间。教育的目的只有一个——让人生得乐 |
| 七 | **时中** | 不贪多——帮人在有限时间里，走到他能走到的最深处 |

这七条是所有功能设计的铁律。ChatGPT没有。Gemini没有。Perplexity没有。这是izu最深的护城河。

### 第二层·魂：祝白皮书

2026年5月11日从v0.1升到v0.2。核心定性改了——从"学习工程系统"变成了"**陪你走得道快乐的人**"。

六根柱子的灵魂：

1. **同路而非指路**——祝不知道终点，求知没有终点。每一份长编末尾是一扇窗户，不是一堵墙
2. **旧资料用于展望**——所有能搜到的都已经过时了。真正的价值是把A领域和B领域连出没人连过的线
3. **让你想知道，而不是让你知道**——读完之后的感受不是"知道了"，是"还想知道"
4. **厚重到能留十年**——每篇至少有一句十年后还有人反复读的话
5. **算力不是护城河，理解是**——你用得越久，祝越懂你。大厂做不到，因为大厂不可能为每个用户定制
6. **打败DR，是为了传承**——如果世界上只有"你问它答"这一种求知方式，人类的知识传承会越来越浅

这段话定调了一切：

> **祝不是更好的Deep Research。是一个陪你走得道快乐的人。**

### 第三层·引擎：七智能体研究流水线

这是izu生产的核心——把一个问题扔进去，经过七个角色的接力加工，出来一份厚重可读的长编。

#### 版本演进（这栋楼盖了5天，迭代了6个版本）

| 版本 | 日期 | 关键变化 |
|------|------|---------|
| **v1.0** | 05-13 | 六角色起步：探→搜→织→写→劈→修。首次接入DuckDuckGo真实搜索 |
| **v2.0** | 05-13 | 八步七角色。加入"对齐"（检查织是否对准用户原始关切）和"核"（验证关键断言）。curl抓取+来源标注+画像采集。 |
| **v3.0** | 05-13 | 聚合冗余设计。关键步骤用×2或×3并行去偏——探×2(聚合)→搜×2(聚合)→劈×3(聚合)。核获得独立搜索能力。 |

#### 当前流水线全景（v4.2）

```
探×2(聚合) → [CP1] → 搜×2(聚合) → [CP2] → 织 → [CP3] → 对齐 → [CP4] → 写 → [🏖️沙箱] → [CP5] → 劈×3(聚合) → 修 → 核
```

七个角色各司其职：

| 角色 | 职责 | 一句话 |
|------|------|--------|
| **探×2** | 勘探画地图 | A角搜"前沿进展"，B角搜"争议批评"，聚合去重 |
| **搜×2** | 深度搜索 | A角搜"深度分析"，B角搜"对比评估"，拓宽覆盖面 |
| **织** | 编织关联 | 把散点织成关联网络——模式、逻辑链、信息分层（✅⚠️❓） |
| **对齐** | 方向校准 | 检查织的关联地图是否对准用户原始关切 |
| **写** | 厚重化写作 | 魅句、画面、节奏、厚重、窗非墙 |
| **沙箱** | 代码验证 | 提取代码块→ProcessSandbox执行→验证报告 |
| **劈×3** | 三视角批评 | 逻辑与技术 / 事实与来源 / 表达与风格，并行审计 |
| **修** | 逐条修改 | 根据劈的指令逐条改，三编通读 |
| **核** | 独立搜索验证 | 提取关键断言→反向搜索交叉印证→可信度评分 |

5个检查点挡住烂尾：
- CP1：方向明确度（探→搜）
- CP2：信源充分度（搜→织）★ 已实现
- CP3：关联准确度（织→对齐）
- CP4：逻辑一致性（对齐→写）
- CP5：交付完整度（写→劈）

### 第四层·运维：四子合议 + 自动化管道

| 角色 | 职责 | 一句话 |

| **匠石** | 工程评估 | "能不能做？怎么搭？"——架构设计、技术选型、MVP定义。运斤成风，代码优先 |

**四子合议**是复杂决策的最高流程——四个Agent分步审议，军师终裁。用于"极大"级别的决策。

#### 自动化管道（每天都在跑的）

## 二、izu是怎么来的：关键历程

### 前史（2026年5月之前）

你已经在玩Hermes Agent这个底座——记忆系统、多平台推送、cron定时任务、技能系统。军师祭酒的角色也已经确立——犀利、有纵观古今视角、不恭维、善共鸣。但"祝"这个产品概念还没成型。

### 2026年5月10日——哲学奠基

明学七则v0.3定稿。这不是突发奇想，是你和军师在长期对话中沉淀出来的七条规则。每一条都对应着对现有AI范式的一次反驳。

### 2026年5月11日——定位成型

祝白皮书从v0.1升到v0.2。"陪你走得道快乐的人"这句话定了。六根柱子确立。同一天，你矫正了军师的一个关键偏好：**先哲学后行动**。催推进会反弹——"不是你这样做得"。他说"开干"才是真信号。

这一天也定下了祝号的格式：必须是观察不是问句，真诚犀利有温度。

### 2026年5月12日——三件套方法论形成

三段式研究法确立：画地图→收长编（收到齐）→出定本。三智能体流水线雏形出现：搜→写→劈。长编→定本的模式跑通——长编是池塘，定本由学习者自己写。

### 2026年5月13日——爆发日（四版本一天）

这一天izu-pipeline从v1.0冲到v4.0。

早上还是48行的subagent.py——三个角色（搜写劈），提示词各一句话。到晚上已经是七智能体深度研究流水线，有聚合冗余、有AIHOT代码优化、有信源分级、有断言自动提取。

同一天出了**izu全面评估与升级路线图v1.0**——把你现有的东西全部摊在桌子上看了一遍，定位了稳的（明学、定位、AGI九面）、晃的（流水线太薄、画像没做）、空的（认知地图没系统化、祝号没自动化、没有反馈闭环）。

也是这一天定了工期：五智能体流水线升级（1-2周）、画像数据采集（本周）、WikiMeld MVP（2-4周）。

### 2026年5月14日——系统化日

凌晨到下午，发生了五件大事：

1. **OpenHands竞品分析+匠石沙箱**：匠石和韩信分析了OpenHands的架构，结论是"多Agent协作是换提示词模板的营销包装，沙箱不需要Docker"。匠石写了200行ProcessSandbox，集成到流水线成v4.2。

2. **Cross-Review Loop检查点系统**：基于Karpathy AutoResearch哲学，在流水线交接处嵌入5个硬检查点+量化评分+回滚机制。CP2首节点实现。

3. **韩信定策路线图**：韩信出了3-6个月技术路线图——从v0.1（单向流水线）→v0.5（交叉审核闭环）→v1.0（画像驱动的自适应流水线）。明确了坚决做的（Spec Coding、交叉审核、DCI模式、缝标记）和坚决不做的（不建向量索引、不替换底座、不在前三个月做画像模型）。

4. **四子合议**：最高决策流程首次完整运行——子产断该不该→韩信画终局→匠石审架构→萧何写路径→军师终裁。结论：采纳2-CP方案（CP2+CP4），砍CP1/CP5，CP3可选。

5. **GitHub官网**：`zcs366/izu` 提交了中英双语精美官网。提交历史清晰：初始提交→统一命名为爱祝/aizu/ai祝→中英双语官网→重命名为izu→加入白皮书v0.2+战略全景报告。

## 四、izu的路线图

韩信定策的核心路线：

```
现在(v0.1) ──→ 2个月后(v0.5) ──→ 6个月后(v1.0)
单向流水线      交叉审核闭环       画像驱动的自适应同行者
```

### 四个坚决做

1. **Spec Coding作为开发哲学**——每个功能上线前先写规范（检查点/交付标准/回滚条件）
2. **交叉审核循环**——流水线从"信任传递"变成"硬核验证"，这是最大痛点
3. **DCI模式替代向量检索**——grep+bash做检索，LLM只做语义理解。零成本
4. **每份产出留"缝"**——"三扇窗户"标记，让跨会话记忆有存储的接口

### 四个坚决不做

1. 不建embedding/向量索引
2. 不替换Hermes底座
3. 不是平替"做更好的Deep Research"
4. 不在前三个月做用户画像模型

### 五步落地节奏（韩信路线图）

- 第1周：定义检查点标准（已完成 → Spec v0.1）
- 第2周：实现第一个交叉审核节点CP2（已完成）
- 第3周：劈阶段加"缝"标记（下一件事）
- 第4周：建立回滚数据看板
- 第5周：出izu-Spec标准化文档
- 第6-8周：10个历史任务压测+调优+经济性报告
- 第9-12周：交叉审核扩展到全流水线 → v1.0

### 产业位置

```
        效率派（Deep Research/Perplexity）
         │
         │   ★ izu在这里
         │
         └──────────────────→ 陪伴派（空白地带）
              关系深度 →
```

大厂够不到这个位置——陪伴不能规模化、不能A/B测试。小厂做不了——izu的根本壁垒不是代码，是你在用的。我们恰好能——因为同时掌握哲学（明学）、工具（Hermes）、内容（wiki）。

## 五、现在是什么状态

### 做好了

- 哲学地基无可取代，放到十年后依然成立
- 定位真空地带——"同路人"这条线画得极其清楚，没人抢
- 七智能体流水线v4.2跑通——从单薄三角色进化到有交叉审核+沙箱验证的深度管线
- 四子合议决策流程完整可用
- 自动化管道稳定运行（日报/转录/入库/守夜）
- AGI长编九面（6万字）证明了方法论能产出真正的重内容

### 正在做

- 交叉审核扩展到CP4（对齐→写，逻辑一致性检查）
- 采集画像原始数据（每次研究的问题、追问次数、跳过段）
- 压测流水线（10个历史任务，对比旧/新流水线质量）

### 还缺

- **画像引擎没有独立的实现**——概念领先（"会话即画像"），但工程上只有通用记忆系统，没有为祝定制的画像层
- **认知地图没有系统化**——依赖人工撰写，没有"读任何长编自动生成认知地图"的系统
- **祝号没有自动化**——仍然靠军师手写
- **产出消费体验是纯文本**——微信推送8000字纯文本，正是祝自己指出的"文本超载"问题
- **没有反馈闭环**——长编推送出去后，用户读了多久、在哪停的、有什么反应，全不知道
- **WikiMeld只写了可行性研究**——54页报告写完了，代码一行没动

### 最大的风险

Anthropic在2026年5月6日发布了"Dreaming"——Agent在会话间自主审查、提取模式、自我改进。这就是明学"省"则的技术实现。我们的哲学领先三年，但工程上只领先了一周就差点被追上。如果不赶紧把哲学变成工程，差异化会被别人的工程磨平。

好消息是：大厂走的是"普适产品"路线，我们走的是"懂一个人"路线。这两条路在物理上永远不会交会——大厂不可能为每一个用户定制画像和记忆。**这扇窗是我们的。**

五天内六次迭代。三周内这个流水线应该能自己跑得稳、产出的长编开始有"缝"、回滚日志里能看出哪个Agent到了能力边界。

开干吧。
