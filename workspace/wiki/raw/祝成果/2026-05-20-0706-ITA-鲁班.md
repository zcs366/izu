# 鲁班

## 工程可行性评估（在墨子理论约束内）

### 理论约束回顾
墨子指出：语义保真度D→0时，压缩率受柯尔莫哥洛夫复杂度约束，不可计算。因此工程方案必须在D > 0的前提下设计。

### 技术方案

**架构设计：FSQ-Code Semantic Quantizer**
```
Code → [CodeBERT] → hidden嵌入 → [FSQ量化] → 离散码 → [FSQ解码] → 近似嵌入 → [CodeBERT-based decoder/STE] → 重建代码
                    └─────┬────┘                          └────┬────┘
                    可加SAE分解                              Steering向量注入点
```

**组件选型：**
1. **编码器**：CodeBERT（或CodeLlama-7B的编码器部分）——成熟的代码理解模型，输出768/4096维嵌入
2. **FSQ实现**：参考Mentzer et al. (2023) 的FSQ PyTorch实现——直接替换VQ，无需auxiliary loss
3. **STE（Straight-Through Estimator）**：FSQ的梯度是直通的，训练稳定
4. **SAE Steering**：若需要steering能力，在FSQ解码后的近似嵌入上附加SAE分解层

**可行性分析：**
- FSQ不要求VQ的codebook学习，规避了codebook collapse风险——✅
- 工程实现复杂度低——PyTorch实现FSQ约200行代码——✅
- 理论约束内：接受D > 0（语义失真）——✅（墨子判定可行）
- 计算资源：CodeBERT推理在1张T4上即可运行——✅

### 工程风险
1. FSQ的格子大小选择无理论指导——需要实验扫描
2. CodeBERT的embedding空间不一定适合FSQ的格子划分——定量化可能破坏语义结构
3. 重建质量受限于CodeBERT的解码能力——CodeBERT不是生成模型，需辅助Decoder
4. SAE架构建模——NeurIPS 2025指出不同架构不可互换

### 工具选型
| 组件 | 工具 | 理由 |
|------|------|------|
| 代码编码 | CodeBERT / CodeLlama-7B | 成熟、开源、有代码+文档 |
| FSQ | 自实现（基于Mentzer2023） | 简单，200行PyTorch |
| SAE | SAELens / 自实现 | SAELens有现成的训练和可视化 |
| 代码生成 | CodeGen-2B / StarCoderBase | 验证重建质量 |
