# 商鞅

## 背景：墨子的理论约束

墨子判结：单个 FSQ 向量无法编码整个函数（容量 ≤ 50 bits，函数熵约 300-600 bits）。
可行方向：FSQ token 序列化编码（等价于新 tokenizer）。

## 最小可行实验设计

### 实验名称
**CodeBERT-RTC 基线实验**

### 目标
在 20 工时内回答一个问题：**现有代码模型的隐空间（CodeBERT embedding）能否通过 FSQ 量化后保持 round-trip 语义一致性？**

### 实验步骤（共4步）

#### Step 1：数据集选取（2小时）
- 从 HumanEval 中随机抽取 20 个函数
- 每个函数准备 3 种等价写法（不同变量名、不同控制流但等价）
- 总量：60 个代码片段

#### Step 2：嵌入 + 量化（6小时）
- 用 CodeBERT（microsoft/codebert-base）对每个代码片段提取 768 维嵌入
- 用 PCA 降维到 d = {3, 5, 8} 三种配置
- 对降维后的向量做 FSQ 量化：每维 n = {4, 8, 16} 三种配置
- 总计 3×3 = 9 种量化配置

#### Step 3：RTC 评估（8小时）
- 对每个量化后的 FSQ 码本向量：
  - 解量化 → PCA 逆变换回 768 维
- 从 CodeBERT 嵌入空间还原后，通过 CodeBERTScore 计算与原始嵌入的余弦相似度
- 关键问题：量化后还能区分语义等价 vs 不等价的代码吗？
- 用原始 vs 量化嵌入分别做「代码对是否语义等价」的二分类比较

#### Step 4：分析报告（4小时）
- 绘制率失真曲线：dimension vs n vs CodeBERTScore
- 回答：在什么量化参数下保真度 ≥ 0.90？
- 回答：量化后的嵌入还能区分语义等价代码吗？

### 成功判断标准

| 指标 | 成功 | 部分成功 | 失败 |
|------|------|---------|------|
| CodeBERTScore ≥ 0.90 | d≥5, n≥8 可达 | 仅 d=8, n=16 可达 | 任何配置都达不到 |
| 等价代码可区分性 | 量化后 AUC ≥ 0.85 | 0.70 ≤ AUC < 0.85 | AUC < 0.70 |
| 总工时 | ≤ 20h | 20-25h | > 25h |

### 为什么这个实验就够了

这个实验不是最终方案，而是**信息量最大的最小实验**。它直接回答：
1. 代码的 KL 散度嵌入空间是否容得下 FSQ 量化？（信息论）
2. 量化后的嵌入是否仍保留语义区分能力？（信息论+语义学）
3. 率失真曲线上哪个点值得深入？（工程可行性）

如果 Step 4 显示 d ≥ 5, n ≥ 8 就能保真 ≥ 0.90，那 FSQ tokenizer 在代码域就是可行的。
如果不满足，要么放弃代码隐空间压缩，要么需要更大的码本或不同的编码器。

### 可复现性
- CodeBERT：HuggingFace 加载，零成本
- FSQ 量化：numpy 实现，50 行代码
- RTC 评估：DeepMind 开源代码可用
- 总 GPU 成本：< $20（CodeBERT 推理即可，不需训练）
