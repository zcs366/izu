# 子产 —— 需求判断/研究方向

## 需求判断

**该不该做？** 该做。

**为谁做？**
- 张成市个人陪伴/知识助理Agent——每天1小时使用，需要「记得我是谁」「记得上次聊了什么」「越用越聪明」
- 不需要通用智能，需要**持续性**和**个性化**

**不做会怎样？**
- izu会停留在「每次对话重新认识你」的状态——有提示词缓存但没有跨会话学习
- 2026年Agent记忆已经是必选项（Mem0, MemRL, Agent Memory Survey），不做就落后

## 研究方向定位

### 关键问题
izu的核心困境：**在日均1h、单用户场景下，记忆系统应该多复杂？**

### 假设
最简单的基线（对话历史缓存 + 向量检索）已经能满足80%的记忆需求。剩余的20%（跨会话推理、知识更新、个性适应）需要增量投入。**不要一开始就造MemRL那么复杂的东西**。

### 方向定位

**方向A（推荐）: 渐进式记忆架构**
- Phase 1: 对话历史缓存 + 简单向量检索（Mem0 API调用，1天搞定）
- Phase 2: 实体链接 + 知识图谱（在Mem0基础上叠加，2-3天）
- Phase 3: 经验提取 + 行为模式学习（参考MemRL的思想但不复制其复杂性，5-7天）
- 为什么？因为张成市日均1h → 观察周期长 → 有3-7天的自然周期来迭代

**方向B（不推荐）: 自进化Agent**
- MemRL / AgentEvolver 虽然效果好，但需要运行时RL训练
- 实现复杂度与单用户场景的收益不成比例
- **保留作为远期目标**（3-6个月后）

**方向C（待定）: 记忆压缩**
- ITA的code压缩技术如果证实行之有效，可直接应用于izu的记忆压缩
- 这是个交叉机会——如果在izu中用ITA的压缩方法存储记忆token
- 但依赖ITA先行验证 → 不急于现在投入
