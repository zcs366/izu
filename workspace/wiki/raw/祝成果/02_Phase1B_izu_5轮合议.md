# Phase 1B: izu 5轮合议
**主题**: LLM元认知能力——知道-做鸿沟与外部脚手架
**日期**: 2026-05-20

---

## Round 0：子产（需求判断+研究方向）

**需求判断**：LLM Agent的元认知缺陷是当前从"聊天机器人"跃迁到"可信自主Agent"的核心瓶颈。

**核心需求**：
- 用户需要的不是更聪明的AI，而是知道自己什么不知道、并据此行动的AI
- 关键用例：自主编程Agent的错误检测、医疗诊断Agent的决策边界管理、金融交易Agent的风险熔断
- 当前的"解决方案"（更长的思维链、更好的prompt）只是掩盖而非解决知道-做鸿沟

**研究方向建议**：

| 方向 | 核心问题 | 高/低风险 |
|------|----------|-----------|
| **A: 外部元认知脚手架** | 如何设计强制模型在不确定时选择退出的架构约束？ | 低风险，Mirror已证明有效 |
| **B: 自我知识通道** | 能否通过特殊训练让模型拥有更准确的自我校准？ | 高风险，Mirror发现提供校准分数无效 |
| **C: 元认知技能训练** | 能否用RLHF奖励元认知行为（如"正确时自信、错误时怀疑"）？ | 中高风险，训练信号难定义 |
| **D: 混合人类-系统元认知** | 何时人工介入？如何让AI自主申请人工介入？ | 中风险，工程可行但需要HCI设计 |
| **E: 跨领域迁移的元学习** | 如何让元认知知识跨领域迁移？ | 极高风险，Mirror TII仅0.019-0.175 |

**推荐**: 方向A（外部脚手架）为主攻，方向C（元认知技能训练）为平行探索。其他方向在A有阶段性成果后再跟进。

## Round 1：韩信（技术远景）

**远景构想**：构建一个**可证明的元认知安全层**——位于LLM之上、独立于LLM的元认知监控系统。

**技术架构远景**：

```
用户请求 → [元认知监控器] → LLM推理 → [元认知检验器] → 输出
              ↑                          ↓
          [不确定性估计] ← [领域分类器] ——
              ↓
          [风险熔断/人工路由]
```

**核心组件**：
1. **领域分类器**：将输入映射到预定义领域（数学/编码/医疗/法律/常识），利用模型本身的表征空间
2. **不确定性估计器**：多通道不确定性估计——token级熵、语义不确定性（投票分歧度）、以及Mirror的5通道行为测量
3. **元认知监控器**：基于LTL或有限状态机的安全约束——当不确定性超过领域特异性阈值时，强制模型进入"谨慎模式"
4. **元认知检验器**：事后审计——检查输出中的自信失败模式，反馈微调阈值

**长期影响**：
- 如果成功，将建立一套独立于模型能力的**安全基线**——不依赖模型"诚实"，而依赖架构约束
- 可推广到多Agent系统——每个Agent有自己的元认知监控器，Agent间交换"置信度证书"
- 最终目标是元认知安全层的**形式化可证明性**——e.g., "在领域D中，模型在不确定性>θ时选择退出，已知误退率<ε"

**里程碑**：
- 3个月：基于已有模型（DeepSeek/Claude API + 不确定性计算）搭建原型监控器
- 6个月：在AgentBench或GAIA基准上验证CFR降低效果
- 12个月：发表基准结果 + 建立领域特异性阈值的实验性证据

## Round 2：鲁班（工程可行性）

**工程可行性拆解**：

| 组件 | 可行度 | 依赖 | 备选方案 |
|------|--------|------|----------|
| 领域分类器 | ✅ 高 | 现有分类器或LLM自分类 | 直接用LLM zero-shot分类（已足够好） |
| 不确定性估计 | ✅ 高 | 语义熵计算（Kuhn et al., 2023） | Jake组已开源实现；也可用LogProb直接估算 |
| 元认知监控器 | ✅ 高 | 有限状态机/LTL引擎 | AgentVerify的运行时监控可直接复用 |
| 领域特异性阈值 | ⚠️ 中 | Mirror实验证据 + 额外数据收集 | 先在2-3个领域拟合，逐步扩展 |
| 元认知检验器 | ⚠️ 中 | 需要定义"自信失败"的自动标注 | 可基于正确答案自动标注，但覆盖域受限 |

**工程约束**：
- **延迟预算**：不确定性估计通常需要多次采样（5-10次推理），延迟增加5-10x。优化方案：(a) 预计算常见任务的校准曲线，(b) 仅在初始不确定性高时触发全采样
- **API成本**：多次采样×多次验证，成本放大。初步估计：在监控模式下，额外成本约2-3x推理成本
- **模型相关**：不同模型的不确定性表征差异大。方案通用性需在≥3个模型系列上验证

**实现路径**：
1. Week 1-2: 封装不确定性计算模块（语义熵 + token级熵）
2. Week 3-4: 用AgentVerify框架搭建LTL监控层
3. Week 5-6: 在3个基准（数学推理、编码、问答）上收集CFR基线
4. Week 7-8: 实现和比较3种阈值策略（固定/领域自适应/动态滑动窗口）
5. Week 9-10: 整合成原型系统，端到端验证延迟和成本

|------|------|------|------|

## Round 4：张仪（最强攻击）

**对"元认知外部脚手架"方案的最强攻击与辩驳**

**攻击1："元认知脚手架只是在LLM外面套了一层硬编码规则——如果规则够简单，为什么还需要LLM介入？如果规则够复杂，又回到了LLM内省的不可靠循环。"**
- 辩驳：这个二分法是错误的。规则层的任务不是代替LLM做推理，而是**判断LLM的推理是否可信**。类比人类审计员——审计员不需要懂被审计者的全部专业知识，只需要懂得检测错误信号（异常交易、不一致陈述）。规则层同样——它不需要理解内容，只需要理解置信度的统计特征。

**攻击2："Mirror基准显示提供校准分数无效。如果连提词都改不了行为，外部监控更不可能改变模型内部状态。CFR降低的76%来自强迫选择退出——这本质上就是'不让模型做高风险决定'，和元认知没任何关系。"**
- 辩驳：攻击者在战术上正确但战略上错误。确实，外部约束本质上是"不让模型做某事"，但这正是可行方案的路径——**与其追求让模型"知道"自己做不出，不如从架构上约束它别做**。这就像安全带：不是在优化司机的判断力，而是物理约束行为。元认知安全层的价值不在于改造模型心智，而在于提供模型不可绕过的安全边界。

**攻击3："多通道不确定性估计在5-10次采样下才能工作，成本增加5-10x。没有商业产品承受得起——等于方案自动被市场否决。"**
- 辩驳：成本问题需要区分解和部署。在开发阶段（调试、审计自动化），5-10x成本是合理的。部署阶段可以：(a) 使用small-to-large级联——小模型做初筛，高风险请求才调大模型+全采样；(b) 预计算浅层问题的不确定性映射；(c) 很多任务（如重要医疗诊断、金融交易）本就需要高质量保障，2-3x成本在商业场景下是可接受的。

**攻击4："领域特异性阈值意味着每个领域都需要标注数据——这不可扩展。"**
- 辩驳：不一定需要标注。可以用模型在few-shot或zero-shot条件下的正确率作为标签，建立无监督校准关系。核心洞察是：**模型的相对不确定性（在领域A内哪些问题更不确定）比绝对不确定性（在全局benchmark上的校准得分）更重要**。相对不确定性可以从模型内部状态直接提取，无需外部标注。

**最终判定**：方案工程可行、理论支撑强，CFR降低76%的经济价值巨大（每避免一次自信失败可能节省$10K-$1M+）。但需要在**成本效率**和**领域可扩展性**上给出更明确的工程路径。建议将10周原型的第1个交付物聚焦于用最小采样（2-3次）实现最大CFR降低，探索成本-安全的Pareto前沿。
