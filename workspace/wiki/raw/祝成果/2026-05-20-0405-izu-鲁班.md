# 鲁班 — 工程可行官

## 工程可行性判断

### 问题1：能否做？ 
✅ **能，但需要拆成独立模块，不要动现有架构**

### 方案：记忆增强模块（Memory Enhancement Module, MEM）

MEM是一个插件式模块，不改Hermes现有代码：

```
┌──────────────────────────────────────┐
│          Hermes Agent (现有)         │
│  MEMORY.md  USER.md  ContextCompressor│
└──────────┬───────────────────────────┘
           │ read/write
┌──────────▼───────────────────────────┐
│   Memory Enhancement Module (新)     │
│                                      │
│   ┌─────────┐  ┌──────────────────┐  │
│   │记忆分类器 │→│ 语义编码器(ITA)  │  │
│   │(重要vs. │  │ (FSQ/layer-prune)│  │
│   │ 临时)   │  └────────┬─────────┘  │
│   └─────────┘           │            │
│                         ▼            │
│   ┌──────────────────────────────┐   │
│   │ 结构化记忆存储 (SQLite/JSON)  │   │
│   │ episodic | semantic | procedural│ │
│   └──────────────────────────────┘   │
│              │                       │
│   ┌──────────▼──────────────────┐   │
│   │ 多信号检索器 (Multi-Signal  │   │
│   │  Retriever: 语义+时间+频率) │   │
│   └─────────────────────────────┘   │
└──────────────────────────────────────┘
```

### 有没有重复造轮子？
- Mem0已经做了商业级记忆系统 → **不要自己写记忆存储层**，复用或借鉴
- 但没有做语义级代码压缩 → **这个是新轮子**
- FSQ在代码领域的应用 → **是新轮子**
- **结论**：60%新轮子（语义压缩+结构化记忆分层），40%借鉴（Mem0的检索策略、Hermes现有memory接口）

### 需要造的装备

| 装备 | 复杂度 | 优先级 |
|------|--------|--------|
| 记忆分类器（重要vs临时） | 低（规则+LLM打分） | P0 |
| 语义编码器适配层 | 中（依赖ITA Phase A） | P1 |
| 结构化存储（3层） | 中（SQLite schema设计） | P0 |
| 多信号检索器 | 中（语义+时间+频率融合） | P1 |
| 集成测试 | 低（pytest + mock） | P2 |
