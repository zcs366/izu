## 一、🔴 技能版本回滚 (Skill Version Rollback)

### 现状
Skills 有 version 字段（如 `version: 1.0`），但无回滚机制。Curator 可归档/删除，不能回退到指定版本。每次 `skill_manage(action='edit')` 直接覆盖原文件，无历史备份。

### 方案
建立 **`skill-backup` 脚本系统**：

```bash
# 每次 skill 修改前自动备份
~/.hermes/scripts/skill_backup.sh backup <skill-name>
# 回滚到指定版本
~/.hermes/scripts/skill_backup.sh rollback <skill-name> <version>
# 查看版本历史
~/.hermes/scripts/skill_backup.sh history <skill-name>
```

备份存于 `~/.hermes/skill_backups/{skill-name}/v{timestamp}/`，保留最近20个版本，超出自动清理。

### 实施状态 ✅ 已完成

## 二、🔴 日志回放 (Log Replay)

### 现状
日志系统完善（`agent.log` / `errors.log` / `gateway.log`），`hermes_state.py` SessionDB 保存完整会话历史并有 `replay` 概念引用，但无面向用户的会话回放工具。

### 方案
构建 **`session-replay` 工具**：
- 从 SessionDB 提取指定会话的完整消息链
- 按时间轴回放：user prompt → tool calls → tool results → assistant response
- 输出格式：时间线 + 令牌消耗 + 工具调用明细

### 实施状态 ✅ 已完成

## 三、🔴 上下文预算可视化 (Context Budget Visualization)

### 现状
v0.13.0 已在状态栏显示 compression count。底层有 `iteration_budget`、`max_iterations`、`token_count` 追踪。但缺少**实时百分比仪表盘**：用户看不到当前上下文填了多少、还剩多少、压缩减掉了多少。

### 方案
在 CLI/TUI 状态栏增加完整上下文仪表盘：
```
[ctx: 47% | 23K/49K tok | comp: -18% | iter: 5/90]
```

### 实施状态 ✅ 已完成（仪表盘脚本 + TUI 建议方案）

## 四、🔴 工具结果缓存 (Tool Result Caching)

### 现状
仅 OpenRouter 支持 response-level 缓存。`model_tools.py` 中无通用工具结果缓存。每次相同工具调用（如 `web_search("Hermes Agent")`）都重跑。

### 方案
在 `model_tools.py` 的 `handle_function_call` 处插入哈希键缓存：
- 对**纯查询类工具**（web_search, web_extract, bing_search）启用 TTL 缓存
- 缓存键 = `(tool_name, json.dumps(args, sort_keys=True))`
- TTL 默认 300 秒
- 写操作类工具（write_file, patch, terminal 等）不缓存

### 实施状态 ✅ 已完成

### 评估
上游已覆盖核心功能。建议在**使用层面**做一件事：创建一个 `hermes multi` 指令，显示当前模型的多模态能力矩阵。
