# 鲁班 — 工程可行官

## 工程可行性判断

### 能不能做？——可以，但分三步走

#### 第一步：记忆系统（已有基础，2周）
- **现状**：izu 已具备基础 RAG 对话记忆（v0.2）
- **改进方向**：增加结构化记忆（按主题/时间/重要性分层）
- **工具**：LangGraph + ChromaDB（张成市已有经验）
- **工作量**：~10h 集成，不需要新技术
- **判断**：✅ 直接可做

#### 第二步：技能系统（半依赖外部成果，4周）
- **现状**：手动注册 skill，无自动发现
- **改进方向**：从「手动注册」到「模板化注册」到「半自动提示」
- **工具**：izu 已有的 tool-use 框架 + 函数注册表
- **依赖**：不需要 ITA 成果
- **工作量**：~15h
- **判断**：✅ 可做，但达到韩信说的「自动发现」需要 ITA 隐空间技术

#### 第三步：隐空间记忆（完全依赖 ITA，8周）
- **现状**：无
- **依赖**：ITA FSQ 实验成功（分离度 > 2，量化后损失 < 20%）
- **工作量**：~20h（复用 ITA 的编码器 + FSQ 层）
- **判断**：⚠️ 依赖外部成果，不能独立推进

### 有没有重复造轮子？

| 组件 | 现有方案 | 是否需自研 | 理由 |
|---|---|---|---|
| 对话记忆 | Mem0, MemGPT, RAG | 部分自研 | 已有基础，改造成本低于重做 |
| 结构化记忆 | GraphRAG (Microsoft) | 复用+调优 | 不重复造轮子 |
| 技能注册 | izu 已有 tool framework | 改进即可 | 不重复造 |
| **隐空间记忆** | **无成熟开源方案** | **需自研** | **这是核心创新，不是轮子** |

### 造什么装备？

| 装备 | 说明 | 优先级 |
|---|---|---|
| 记忆分层器 | session→episode→knowledge 三层层级 | P0 |
| 技能模板引擎 | 从 function call 自动生成 skill signature | P1 |
| 隐空间记忆桥 | 连接 ITA 编码器→izu 记忆池 | P2（ITA完成后） |

### 工程可行性结论
**可行。** 三个装备的制造难度都不高（分层器 ~200 行，模板引擎 ~300 行，隐空间桥 ~500 行）。总代码增量 < 2000 行。核心技术点在 ITA 侧，izu 侧主要是管道工程。
