# 墨子

## 核心主张的形式化翻译

**主张**：可以用 FSQ 把代码压缩到低维离散隐空间，保持语义不变。

**形式化命题**：
存在编码器 E: code → z ∈ Z （Z = 有限离散集，|Z| = ∏ᵢⁿ₁ nᵢ，n ≤ 10，nᵢ ≤ 32），
和解码器 D: Z → code'，使得对随机采样的输入 x 和原始代码 f，
P_{x}( D(E(code))(x) ≠ code(x) ) < δ，其中 δ 是允许的失真率。

---

## 率失真理论下界

### 1. 信息论下界
设代码空间的熵为 H(code)。率失真定理要求 R ≥ H(code) - δ 的某个函数。

FSQ 的码本大小 |Z| = n^d（n 为每维量化值数，d 为维数）。
最大编码容量 = log₂|Z| = d × log₂(n) bits。

**约束**：log₂|Z| ≥ H(code) - ε，否则无论如何都无法在 δ 失真内编码。

### 2. 代码的熵有多大？
- 对于一个函数定义，假设平均 50 个 token，每个 token 约 16 bits（词表 65536）
- 但代码并非最大熵分布——语法约束降低实际熵
- 估计 H(code_per_function) ≈ 300-600 bits（受写法多样性和语法约束影响）
- 那么 log₂|Z| = d × log₂(n) 需要 ≥ 300-600 bits

### 3. FSQ 的参数约束
如果 d=5, n=8（FSQ 论文典型设置）：
log₂|Z| = 5 × 3 = 15 bits ← 远小于 300 bits

如果 d=10, n=32：
log₂|Z| = 10 × 5 = 50 bits ← 仍然远小于 300 bits

### 4. 两种出路

**出路 A（序列化编码）**：
不是把整个函数压缩成一个 FSQ 向量，而是用 FSQ 作为 tokenizer，把代码变成 FSQ 离散 token 序列。
- 每个 token = d 维 FSQ 向量，每维 n 个值
- 每个 token 承载 log₂|Z| bits
- 需要 H(code) / log₂|Z| 个 token
- 以 d=5, n=8 为例：每 token 15 bits，一个函数需要 20-40 个 token
- 这等价于用 FSQ 做代码 tokenization，而非一向量一函数

**出路 B（分层/条件编码）**：
不是编码整个函数，而是编码函数在某个输入下的执行轨迹/行为签名。
- 更小的熵：单个执行路径的 H(trace) << H(code)
- 可以做到高保真，但丢失了函数本身的通用性

---

## 理论可行性判结

| 方案 | 率失真边界 | 可行性 |
|------|-----------|--------|
| 整个函数→单个FSQ向量 | ❌ 理论不可行（容量差1-2个数量级） | 除非函数极短（< 5 tokens） |
| 整个函数→FSQ token序列 | ✅ 理论可行（等价于新tokenizer） | 但需要训练序列模型 |
| 执行轨迹→单个FSQ向量 | ✅ 理论可行（熵小得多） | 丢失通用性，但可做行为签名 |

**墨子结论**：如果把「代码语义压缩」理解为**用 FSQ tokenizer 替代现有 tokenizer**（类似 VQ-VAE 对图像的离散化），理论可行。如果理解为**一个函数压缩成一个向量**，理论下界排除。
