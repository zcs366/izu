# Phase 3 — 可证伪预测

## 预测声明

> **到2027年6月30日之前，至少有一家部署了生产级AI Agent（月活>100万用户或管理>100万美金资产/日）的科技企业，将因Agent的一次可预防的可靠性事故（非能力不足以单独失败，而是因Agent未在确认边界后执行危险操作）而遭受直接经济损失超过100万美金。**

### 预测的4个组成部分

**（1）可观察指标**
- 公开报道的事件（科技媒体、监管披露、公司公告）
- 或未公开但可通过行业渠道验证的事件

**（2）可测量阈值**
- 直接经济损失 ≥ $1,000,000 USD
- Agent月活 > 1M 用户 OR 日管理资产 > $1M
- 事故分类：可靠性事故（vs 能力不足：模型无法完成任务是两个不同类别）

**（3）假说支撑链**
```
模型缺乏元认知（ITA假说）
   → Agent无法识别自身的操作边界
     → 在超出能力阈值时仍继续执行
       → 系统级安全护栏设计不足（izu缺口）
         → 可预防事故 → $1M+损失
```

**（4）证伪条件**
- 如果到2027年6月30日没有此类事件发生，则以下至少一项为假：
  - (a) Agent部署规模未达到预期（如果Agent未广泛部署，则事故概率低）
  - (b) 工程界已系统性解决了Agent可靠性问题（对izu框架需求降低）
  - (c) 模型的推理崩溃现象被有效缓解（对ITA假说提出了挑战）
  - (d) 企业部署Agent时普遍引入了足够强的安全护栏
- **最关键的证伪路径**：(b)或(c)——如果其中一项为真，则本研究的根本前提需要重新审视

### 检验时间线
- **2026年12月**：中期检查——是否有类似Replit规模的Agent事故（不一定要$1M损失）
- **2027年3月**：预检——如果到此时仍无重大Agent事故报告，预测可能不准
- **2027年6月**：终检——正式验证

### 预测的"研究价值"——即使错了也有价值
- 如果预测正确：为Agent可靠性工程提供了紧迫性的直接证据
- 如果预测错误：揭示了工程界在Agent可靠性上的进步程度，或Agent部署节奏比预期更保守
