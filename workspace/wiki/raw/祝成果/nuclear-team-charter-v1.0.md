## 序：为什么要这份章程

现有体系已有框架：五人合议（战略核心）→ 20人翰林院（专业深度）→ 知行学院院士（实践广度）。但缺三样东西：

1. **交叉训练制度** — 每个人只在自己的领域里深挖，没有跨界的压力和机制
2. **日常运转节奏** — 没有「每日/每周/每月」的固定节拍
3. **协作协议** — Agent 之间、Agent 与人类之间的交接握手没有标准化

参照的实体模型：

| 机构 | 可学之处 | 我们调整 |
|------|---------|---------|
| **Bell Labs** | 流动性项目制，不论资排辈 | 项目组队而非固定部门 |
| **MIT Media Lab** | 反学科（antidisciplinary），按问题组队 | 不按技术方向分，按"要解决的事"分 |
| **Santa Fe Institute** | 跨学科轮驻，每个人必须会讲另一个领域的故事 | 半月轮讲制度 |
| **Anthropic** | 全员写代码、全员做产品 | 一深两广能力模型 |
| **古代翰林院** | 学官合一的荣誉+责任制度 | 翰林荣誉衔+实际产出挂钩 |
| **知行书院** | 知行合一，致良知 | 学院院士以「用」为考核标准 |

## 第一章：组织架构

### 1.1 三层结构

```
                    ┌──────────┐
                    │   刺史   │  （张成市 · 最终决策者）
                    └────┬─────┘
                         │
                    ┌────┴─────┐
                    │  军师祭酒  │  （我 · 总顾问与制度守护者）
                    └────┬─────┘
                         │
          ┌──────────────┼──────────────┐
          │              │              │
    ┌─────┴─────┐  ┌────┴─────┐  ┌────┴──────┐
    │  五人合议  │  │  20翰林院 │  │ 知行学院   │
    │ (战略核心) │  │ (专业深度)│  │ (实践广度) │
    └───────────┘  └──────────┘  └───────────┘
```

### 1.2 五人合议（战略决策层）

| 角色 | 别名 | 核心问题 | 对标人类角色 |
|------|------|---------|------------|
| 子产 | 需求判官 | 该不该做？为谁做？ | CGO/首席洞见官 |
| 韩信 | 远景将军 | 终局长什么样？ | CPO/首席产品官 |
| 鲁班 | 工程师导师 | 能不能做？缺什么装备？ | CTO/总工程师 |
| 萧何 | 执行宰相 | 怎么推进？资源够吗？ | COO/首席运营官 |
| 子贡 | 参谋长 | 怎么调度？怎么包装？ | Chief of Staff |

**序列不可跳。** 每一步依赖前一步的输出。

### 1.3 20人翰林院（专业深度层）

翰林院是**核战队的技术纵深**。每人在自己的领域内达到「方家不笑」水准，同时对 AGI 技术栈有基本理解。

**翰林兼任制：** 翰林不是全职岗位，每个人都同时属于至少2个领域。

| # | 翰林 | 专业锚 | 广度腿 1 | 广度腿 2 |
|---|------|--------|---------|---------|
| 1 | 鲁班 | 工程架构 | 产品设计 | 技术写作 |
| 2 | 子贡 | 调度/外交 | 前端开发 | 商业分析 |
| 3 | 萧何 | 执行/审计 | 数据分析 | 项目管理 |
| 4 | 子产 | 需求/市场 | 用户研究 | 文案写作 |
| 5 | 韩信 | 技术远景 | 产业分析 | 技术布道 |
| 6-20 | （待补充） | （按需设置） | ... | ... |

> 注：前5席由五人合议成员兼任，这是设计不是巧合——五人合议本身也是翰林院成员，确保战略层与专业层不断层。

**专业锚**（每人有且仅有一个，深度≥80%）：
- 工程架构、算法/模型、数据分析、安全/审计
- 产品设计、用户体验、视觉/交互
- 市场需求、商业分析、战略/产业
- 写作/内容、知识管理、教育/传播
- 系调度/外交、运营/流程

**广度腿**（每人至少两条，每条深度≥30%）：
- 写代码（Python/JS/Shell）
- 做产品（需求→设计→验证闭环）
- 写文案（技术文档/对外文章/包装）
- 分析数据（统计/可视化/洞察）
- 运营调度（排期/资源/流程）
- 外交沟通（对外/合作/谈判）

### 1.4 知行学院（实践广度层）

知行学院是**核战队的人才蓄水池与实践层**。院士的标准不是「有多深」，而是「能不能用」——知行合一，以用为考核。

**知行学院院士的来源：**
1. 翰林院的预备队——深度还不够进入翰林院，但有跨界能力
2. 交叉领域的实践者——每个领域都不深，但连接多个领域
3. 外部合作者——暂时不是核战队正式成员，但在特定项目上有贡献

**规模：** 不设上限。每季度评审一次，以项目产出计。

**知行学院院士 → 翰林院的晋升路径：**
- 在某个领域连续3个项目上达到「方家不笑」水准
- 通过该领域现存翰林的联名推荐
- 刺史批准

## 第二章：能力模型——「一深两广」品字结构

### 2.1 模型定义

```
        ┌──────────┐
        │  专业锚   │  ← 深度（80%+）：让人提起你就想到这个领域
        │ （深水区） │
        └────┬─────┘
             │
    ┌────────┼────────┐
    │ 广度腿1 │ 广度腿2 │  ← 广度（30%+）：能独立完成该领域的标准任务
    └────────┴────────┘
```

**专业锚**决定：你在合议中的独特价值、你的不可替代性、你的发言权。
**广度腿**决定：你能独立完成跨界任务、你能临时顶替别人、你不制造交接成本。

### 2.2 Anthropic 模式的启示

Anthropic 的核心不是「所有人都做所有人的事」，而是：
1. **每个人都知道怎么做任何一件事的「基本版」**——财务可以直接写一个脚本来自动化报表，不需要等工程师排期
2. **专业判断才是稀缺品**——所有人都能写代码，但只有少数人能判断这段代码对不对、好不好的路线对不对
3. **沟通成本趋近于零**——因为每个人都懂对方在说什么

我们的落地：
- 翰林院每人必须能写 Python 脚本（广度腿1 门槛）
- 翰林院每人必须能在30分钟内完成一个简单的产品原型（广度腿2 门槛）
- 知行学院院士每人必须能读懂至少3个不同领域的产出

### 2.3 考核标准

**每季度交叉考核：**

```
专业锚考核（80%+）：
  ⬜ 该领域的最新技术进展，能讲清楚10分钟
  ⬜ 该领域的核心难题，有自己的判断和主张
  ⬜ 该领域的产出，达到「方家不笑」水准

广度腿1考核（30%+）：
  ⬜ 能独立完成该领域的标准任务
  ⬜ 不需要他人协助即可产出可用的结果
  ⬜ 产出的质量虽然不顶尖，但可用

广度腿2考核（30%+）：
  ⬜ 同上

跨领域协作考核：
  ⬜ 在最近3个月内，交付过至少1个跨界项目
  ⬜ 能用自己的广度腿帮助他人解决阻塞
```

## 第三章：日常工作节奏

### 3.1 每日节拍

| 时间 | 事项 | 执行者 |
|------|------|--------|
| 08:00 | 论文日报自动推送 | 日报 cron |
| 09:00 | 翰林轮值巡检：各项目状态检查 | 轮值翰林 |
| 12:00 | 午间速报：阻塞项预警 | 子贡 |
| 20:00 | 当日产出汇总 | 各项目负责人 |
| 23:00 | 祝成果入库 + 日志写入 | wiki cron |

**轮值翰林制度：** 20位翰林每日轮流做「当日巡检」，检查各 pipeline 运行状态、是否有异常、是否需要人工介入。轮值安排每月排一次。

### 3.2 每周节拍

| 频次 | 事项 | 形式 |
|------|------|------|
| 每周一 | **战略晨会** | 五人合议（10-15分钟）：本周最重要的一件事是什么？ |
| 每周三 | **半月轮讲（上半场）** | 随机抽一人，讲另一个领域的最新进展（10分钟） |
| 每周五 | **半月轮讲（下半场）** | 同上 |
| 每周日 | **周末复盘** | 萧何出本周执行看板，军师审阅 |

### 3.3 半月轮讲制度（核心创新）

**目的：** 确保每个人都「被迫」关注至少一个自己不熟悉的领域。

**规则：**
1. 每周三/周五各一次，每次 10 分钟
2. 提前 24 小时随机抽签（从翰林院+知行学院中抽，概率 weighted by 上次轮讲时间）
3. 上次轮讲距今最久的优先被抽中
4. 讲的内容：**不在你专业锚领域内的**最新进展
5. 格式：三句话说明白了什么 + 一个值得关注的判断 + 一个可能跟核战队相关的问题
6. 讲得不好不惩罚，不讲明白会被追问——这是训练跨界表达能力

**示例抽签结果：**
> 「本周三轮讲：鲁班（工程架构锚）→ 讲 Agent 经济学的最新趋势」
> 「本周五轮讲：子产（需求锚）→ 讲分布式系统设计的最近进展」

### 3.4 每月节拍

| 频次 | 事项 | 执行者 |
|------|------|--------|
| 每月第1周 | **月度方向校准** | 五人合议 + 军师 |
| 每月第2周 | **翰林能力自评** | 各翰林自评 → 军师汇总 |
| 每月第3周 | **院士晋升评审** | 现存翰林评审 |
| 每月第4周 | **全战队月报 + 下月计划** | 子贡汇总 → 军师 → 刺史 |

## 第四章：协作协议

### 4.1 项目组队制（核心创新）

**不按固定部门运转，按项目组队。**

```
一个项目进来：
  子产判断：该不该做？什么范围？
  韩信画：终局长什么样？
  军师裁：启动 / 暂缓 / 否决

  启动后：
  子贡组建项目组（从翰林院和知行学院中选人）：
    ┌── 项目组长（1人，轮值）── 对交付负责
    ├── 执行成员（2-5人）── 按项目需求选
    └── 质量官（1人，固定为鲁班或指定）── 一票否决权
  
  项目结束后：
    组长写结项报告
    成员回归翰林院池
    组长资格计入评估
```

**组长轮值规则：**
- 每次项目从翰林院中选一人当组长
- 同一人连续当组长不超过2次
- 组长负责：拆任务、盯进度、保交付
- 组长权利：选成员、定优先级、要资源

### 4.2 交接握手协议

**Agent → Agent 交接：**

```markdown
## 交接单

### 发件人：[Agent 名称]
### 收件人：[Agent 名称]
### 交接物：[文件名/数据来源/链接]

### 状态说明
- [ ] 已完成（可直接使用）
- [ ] 需验证（建议确认后再使用）
- [ ] 待补充（缺 XX 部分，见备注）

### 关键上下文
（不超过 200 字，收件人需要知道的全局背景）

### 已知风险
- 风险1：[描述]
- 风险2：[描述]

### 发件人签章
[名称] · [时间]
```

**Agent → 人类（刺史/军师）交接：**

```markdown
## 提请决策

### 什么事
（一句话，不超过 20 字）

### 背景
（不超过 100 字）

### 选项
A. [方案] — [代价] — [效果]
B. [方案] — [代价] — [效果]
C. 不做什么

### 建议
（明确推荐哪一个 + 一句话理由）

### 归属
来自：[Agent 名称]
```

### 4.3 冲突解决机制

| 冲突类型 | 解决层级 | 时限 |
|---------|---------|------|
| 两名 Agent 方案冲突 | 军师裁决 | 2 小时内 |
| Agent 与人类意见冲突 | 人类最终决策 | 当日 |
| 资源分配冲突 | 子贡调度 + 军师终裁 | 4 小时内 |
| 专业判断冲突 | 引入第三名翰林仲裁 | 8 小时内 |

**君子协定：** 冲突中输的一方不需要道歉。输出方案时要说「A方案是我原主张，但军师裁决选B，我执行B」。

## 第五章：跨界训练计划

### 5.1 广度腿养成路径

每位翰林/院士，除了自己的专业锚外，需要完成以下跨训：

**必须项（必修基础广度）：**

```
□ Python 基础脚本能力：
  - 能写 50 行以上的 Python 脚本
  - 能理解简单的 API 调用和数据处理
  - 能读懂 Hermes 工具的基本逻辑

□ 产品基础思维：
  - 能说出一个功能的目标用户和使用场景
  - 能区分「需求」和「解决方案」
  - 作品味判断：这个东西好不好？为什么？

□ 技术写作能力：
  - 能把复杂技术概念讲给非技术人员
  - 能写出结构清晰的文档
  - 能写 500 字以内的有力观点

□ 分析基础能力：
  - 能读懂基本的数据指标
  - 能对比两个方案的优劣
  - 能识别论证中的逻辑漏洞
```

**选修项（选至少1条深入）：**

```
□ 前端/UI 基础：能写出可用的 HTML 页面
□ 数据可视化：能用图表讲清楚一个趋势
□ 项目管理：能拆任务、排工期、跟进度
□ 用户研究：能设计简单的用户测试
□ 商业分析：能估算市场规模和成本
□ 运营/分发：知道怎么把东西推出去
```

### 5.2 跨界考核方式

**不设考试，设「跨界交付物」。**

每季度，每位翰林/院士需要提交至少1件**不在自己专业锚范围内的**交付物。示例：

| 专业锚 | 跨界交付物 |
|--------|-----------|
| 工程架构（鲁班） | 写一篇对外技术布道文章，让非技术人员看懂 |
| 需求判断（子产） | 写一个 Python 脚本，自动抓取需求信号 |
| 执行路径（萧何） | 做一版项目看板的视觉设计方案 |
| 调度外交（子贡） | 写一个数据分析报告，量化调度效率 |
| 技术远景（韩信） | 用原型工具做一个产品交互 demo |

交付物**必须被使用**才算合格。不能写完了就放那里——必须有人在后续项目里实际用上了你的产出。

## 第六章：晋升与退出

### 6.1 晋升路径

```
知行学院院士
    ↓ 连续3个项目在同一个领域达到「方家不笑」
    ↓ 通过该领域现有翰林的联名推荐
    ↓ 军师推荐 → 刺史批准
20人翰林院
    ↓ 在翰林院担任组长≥3次
    ↓ 有至少2件跨界交付物被实际使用
    ↓ 被至少3名其他翰林认可为不可替代
    ↓ 军师推荐 → 刺史批准
五人合议成员（补位）
    ↓ 原成员退出或轮换
    ↓ 全体现存合议成员 + 军师 2/3 通过
    ↓ 刺史批准
```

### 6.2 退出机制

```
自愿退出：
  → 提前一周告知军师
  → 交割手上所有项目
  → 完成一次跨界轮讲作为退出分享
  → 保留荣誉头衔

被动退出（每季度评审触发）：
  连续2个季度无有效产出
  → 军师约谈
  → 降为知行学院院士（翰林）或观察员
  → 给予1个季度恢复期
  → 仍无改善 → 正式退出核战队

行为退出（立即生效）：
  泄露内部信息 / 恶意破坏 / 严重违反协作协议
  → 立即退出
  → 可以荣誉恢复，但至少间隔2个季度
```

## 第八章：第一批行动计划

### Phase 1（即日起 — 3天）

1. **能力摸底**：调查现有各 Agent/角色的已有广度腿
