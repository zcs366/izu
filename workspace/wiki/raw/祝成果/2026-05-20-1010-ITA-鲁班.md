# 鲁班·工程可行性报告

## 理论约束回顾（墨子结论）
- 率失真下界不构成约束：FSQ码本容量(8^16=2^48)远超所需(2^14)
- 关键风险在"编码器语义对齐质量"，不在理论极限

## 技术实现方案

### 整体架构
```
代码片段 → CodeBERT → [768-dim embedding] → 降维(可选) → FSQ量化 → 量化索引 → 解码 → 重建代码
                                                                       ↓
                                                              steering方向干预
```

### 组件选型

| 组件 | 方案 | 理由 |
|------|------|------|
| 编码器 | CodeBERT (microsoft/codebert-base) | 开源、预处理完代码、768维隐空间 |
| 降维 | PCA 768→16/32 | 降低FSQ维度以控制码本大小，PCA可逆不影响功能信息 |
| FSQ量化 | 自定义实现，每维度k=8级别 | 参考Google FSQ论文实现，< 50行代码 |
| 解码器 | (a) CodeBERT MLM head 或 (b) 简单线性投影+束搜索 | 先试(b)简单方案，4工时验证可行性 |
| 功能等价测试 | HumanEval + RTC | 标准化评估，可复现 |
| Steering | 隐空间方向向量计算+插值 | 线性代数操作，无模型修改 |

### 工程约束检查

**约束1：是否超出理论边界？**
- FSQ码本大小 8^16 = 2^48 ≈ 2.8×10^14，编码需求 2^14 ≈ 16,384
- 冗余率 2^34 倍，远远满足
- ✅ 未超出理论边界

**约束2：计算资源？**
- CodeBERT推理：1000个样本 × 2次（编码+重建）× 0.5秒 ≈ 17分钟
- PCA拟合：< 1分钟
- FSQ量化：纯CPU操作，< 1秒
- 线性探测训练：< 5分钟
- ✅ 1块T4 GPU足够

**约束3：现有轮子？**
- HuggingFace transformers 有 CodeBERT
- torch PCA 实现存在
- FSQ参考实现存在（Google Research）
- ⚠️ 唯一需要手写的：代码重建部分（从量化嵌入生成代码文本）
- ✅ 整体方案可行

### 不可行性警示
**如果以下条件不满足，方案不可行：**
1. CodeBERT的隐空间是否对齐代码功能语义？（未知，需要商鞅实验验证）
2. 代码重建从降维后的量化嵌入是否可能？（需要实验验证）
3. PCA降维到16维是否丢弃了功能相关信息？（需要实验验证）

### 工具链建议

```
Python 3.10+

```
