# 墨子 · 形式化验证官

【惠施概念定义】
- 代码语义等价 = 输入-输出行为等价（测试覆盖≥90%分支）
- 理解 = 摘要BLEU≥0.5 + 行为预测≥95% + bug检测F1≥0.8
- Steering成功 = 行为偏移显著 > 随机扰动
- 失真函数 d = 0/1（语义等价即0失真）
- codebook大小估算~300-1024个语义类

## 核心主张的形式化

**主张P1**：FSQ/VQ-VAE可以在离散隐空间中保真编码代码语义（失真率趋近于0）。

### 可证伪翻译
P1 ⇔ 存在量化器 Q: Code → Latent 和解码器 D: Latent → Code，使得：
∀c∈C_test, semantic_equivalent(D(Q(c)), c) = true

**率失真边界分析**：
- 设代码空间C有N个语义等价类，每个类需要log₂(N) bits表示
- 惠施估算N≈300-1024 → 需要9-10 bits/表示
- FSQ的典型配置：每个维度2-8个格子 → 对代码语义的d>1的FSQ需要足够维度
- d=2, levels=8 → 8²=64种编码，不够覆盖300个等价类 ❌
- d=3, levels=8 → 8³=512种编码，勉强覆盖300类 ⚠️
- d=4, levels=6 → 6⁴=1296种编码，可覆盖1024类 ✅

**结论**：理论下界不排除可能性。使用4维度、每维6-8级的FSQ即可在理论上容纳语义等价类的数量。但需要注意：
1. 真正风险不在比特率——在"语义等价类"是否真的存在可学习的嵌入映射
2. 如果代码语义类在嵌入空间中不是凸的（即同类代码分散在隐空间各处），FSQ的格子量化会失败

**主张P2**：SAE steering可以定向修改代码模型的行为。

**可证伪翻译**：
P2 ⇔ 存在稀疏特征 f₁, f₂, ..., fₖ，对每个 fᵢ 进行激活干预后，模型在特定代码任务上的输出偏向已知方向。

**理论限制**：SAE的稀疏性假设（每个代码概念由少量latent表示）在代码模型上存疑。代码的"加法"概念可能不是稀疏的——它可能分布在多个SAE特征上。需要实证验证sparsity level。

## 理论可行性结论

**能（有条件）**：
1. FSQ在d=4维度下理论支持 >= 300语义等价类的编码
2. SAE steering在原理上可迁移到代码模型

**条件**：
- 必须实证验证代码语义类在隐空间中的分布是"可分簇"的
- 如果语义类在隐空间中重叠（同一个region编码了多个不相关的语义），FSQ无法分离
