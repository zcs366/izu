# 鲁班 · 工程可行性

## 能不能做？

**能做。** 三个组件都有开源实现可作为起点。

### 技能系统（Step 1-2）

| 组件 | 状态 | 工作量 |
|------|------|--------|
| SKILL.md解析 | Anthropic已发布格式规范，只需YAML/JSON解析器 | 2h |
| 技能加载 | 在工作记忆区开辟"技能上下文"区 | 4h |
| MCP桥接 | 已有Python SDK（mcp-client） | 4h |
| 信任评分 | 基于来源的4层权限模型（参考arXiv:2602.12430） | 6h |
| **合计** | | **16h** |

**是否重复造轮子？** SKILL.md和MCP都是开放标准，izu不应自造协议。直接实现协议客户端即可。

### 记忆系统（Step 3）
- Mem0开源（AGPL），可自托管
- 或用LangMem（MIT）+
- 或自实现：BM25 + HNSW + decay权重（~300行Python）
- **推荐**：按Mem0论文（arXiv:2504.19413）描述的算法自实现轻量版，避免AGPL污染

### 自改进循环（Step 4）
- 模式：izi已有WORKING.md记忆系统作为基础
- 新增：session日志分析与模式匹配
- 不依赖外部库，纯Python字符串+向量

## 造什么装备

```
izu-skills/
├── skills/                    # 技能目录
│   └── SKILL.md               # 格式示例
├── src/
│   ├── skill_loader.py        # SKILL.md解析+加载
│   ├── mcp_bridge.py          # MCP协议客户端
│   ├── trust_scorer.py        # 来源信任评分
│   └── memory_engine.py       # 向量记忆（BM25+HNSW）
├── benchmarks/
│   └── locomo_runner.py       # LoCoMo基准自测
└── self_improve/
    ├── session_logger.py      # session日志
    ├── pattern_miner.py       # 模式发现
    └── skill_updater.py       # 自动skill修正
```
