# 鲁班

## 工程可行性判断

### 核心问题：能不能做？

**能，但需要范围收缩。**

MemSkill 本身已经开源（GitHub: ViktorAxelsen/MemSkill），核心代码可重用。问题在于：
1. MemSkill 的 designer 组件（skill 进化）是 offline 的——需要提前收集 hard cases
2. zu 的场景是纯在线——Agent 每天只有少数几次交互
3. 现有 CodeBERT 嵌入环境已就绪（与 ITA 共享）

### 是否重复造轮子？

**部分重复，部分创新。**

重复部分：
- 如果直接复现 MemSkill 的 LoCoMo/LongMemEval 实验 → 纯重复
- 替代方案：跳过纯复现，直接复用 MemSkill 的 skill bank 架构

创新部分：
- MemSkill 的 online 化（paper 未做，开源代码未包含）
- 跨 Agent skill 共享（paper 未做）
- 与 zu 的现有 Agent 框架集成（需要适配）

### 造什么装备？

**工程方案：zu-MemSkill 适配层**

```
zu Agent Memory 接口
  ↕ 适配层（新造：约 200 行）
zu Skill Bank（MemSkill 架构 + zu 的 skill 定义格式）
  ↕ 控制器（MemSkill 的 controller 复用）
  ↕ 执行器（LLM-based executor，复用 MemSkill）
  ↕ 设计师（新造：online active learning 替代 offline review）
```

#### 组件 1：Skill Bank 适配（4 小时）
- 将 MemSkill 的 skill 定义转换为 zu 可执行的规则格式
- 初始 seed：10 个基础 skill（summarize_conversation, extract_entities, track_preferences, ...）

#### 组件 2：Controller 集成（3 小时）
- MemSkill 的 controller 是一个学习选择器的简单 MLP
- 复用 Pretrained weights（MemSkill 开源的）
- 适配 zu 的输入/输出格式

#### 组件 3：Online Designer（创新组件，8 小时）
- 替代 MemSkill 的 offline designer
- 核心逻辑：当 Agent 自我评估发现低质量记忆 → 收集该 case → 触发本地 LoRA 微调
- 不需要全量重训练，只需要在 skill bank 中新增或修改一条 skill

#### 组件 4：技能评估器（5 小时）
- 用 CodeBERTScore 或 RTC 评估 skill 执行质量（与 ITA 共享）
- 评估结果 → 反馈到 designer → 决定是否进化

### 总工程量
4 + 3 + 8 + 5 = **20 工时**（与 ITA 实验同量级）

### 工具选型

| 组件 | 选择 | 理由 |
|------|------|------|
| LLM 基底 | Qwen2.5-7B（或 zu 现有模型） | 跨模型已验证 |
| 微调 | LoRA (peft) | 轻量，适合在线 |
| 记忆存储 | ChromaDB / FAISS | 轻量，可本地运行 |
| 控制器 | MLP（MemSkill 开源的） | 复用 |
| 评估 | CodeBERTScore | 与 ITA 共享 |

### 工程风险
1. Online active learning 的收敛性——没有文献支撑，需要实验验证
2. 日均 1h 约束下，20 工时需要 2-3 周
3. 需要与 ITA 竞争 GPU 资源（若都需 GPU）
