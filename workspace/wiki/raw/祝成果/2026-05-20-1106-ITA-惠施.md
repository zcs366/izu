# 惠施 —— 概念辨析官

## 核心概念的操作性定义

### 「代码语义」
**不可接受的定义**: "代码的含义"、"程序的意思"
**操作性定义**: 给定一段代码C和输入I，代码语义 = 执行轨迹T(C, I) + 输出O(C, I)。两个代码片段语义等价当且仅当 ∀I ∈ 合法输入域: T(C₁, I) = T(C₂, I) 且 O(C₁, I) = O(C₂, I)。

### 「理解」
**不可接受的定义**: "模型知道代码在做什么"
**操作性定义**: 理解 = round-trip保真度。对任意代码片段C，正向编码E(C) → 隐空间表示z → 反向解码D(z) = C'。理解程度 = 1 - edit_distance(C, C') / |C|。当且仅当C'与C的抽象语法树等价时视为"完全理解"。

### 「Steering成功」
**不可接受的定义**: "输出变了"
**操作性定义**: 施加steering向量v后，输出分布从P_original变为P_steered。Steering成功 = KL(P_steered || P_target) < ε，其中P_target是在目标行为下由监督数据定义的参考分布。对于代码场景：steering成功 = 施加"简洁编码"steering后，输出的代码行数减少≥20%且通过相同测试用例。

### 「压缩」
**不可接受的定义**: "变小了"
**操作性定义**: 压缩率 = 原始比特数 / 压缩后比特数。但仅此不够——压缩后的语义保真度由round-trip重建误差界定。给定率失真函数R(D)，压缩在率R下可行当且仅当失真D ≤ D_acceptable。D_acceptable = 代码AST等价所需的最高可容忍失真。

### 「率失真边界」
**操作性定义**: R(D)的下界由信源的信息率失真函数给出。对代码域，信源是代码token序列的分布P(code)。理论最小比特率 = H(code) - D·log(|code_alphabet|)，其中H(code)是代码的熵。如果目标重建精度需要D < 0.01·H(code)，则理论下界可能排除99%精度的实现方案。

### 关键裁定
**「代码语义」≠ 「自然语言语义」**。代码语义有**机械等价性**标准（相同输入→相同输出+执行轨迹），而自然语言语义是概率性的。这意味着ITA的压缩标准必须比NLP压缩更严格——round-trip必须是确定性的，而不是近似的。
