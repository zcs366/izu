# 终端Agent上下文压缩策略

> 基于 #8 论文（观察上下文压缩驱动Agent进化，Terminus-2框架）  
> 定位：v0.5与ReVeal进化引擎融合，先出方案

---

## 一、核心问题

Agent长期运行后，上下文窗口被历史观察淹没问题：
- 每次任务产生大量中间输出（搜索摘要、中间推理、错误重试日志）
- 直接全塞进下一次调用 → token膨胀 → 成本飙升 → 模型注意力稀释

**#8的核心思路**：不是丢弃旧信息，是**选择性压缩**——保留"对未来决策有用的观察"，压缩"已完成使命的冗余信息"。

---

## 二、压缩策略三层架构

```
┌──────────────────────────────────────────────┐
│              上下文管理器                      │
│                                              │
│  Layer 1: 即时观察（当前任务，不压缩）         │
│  ↓ 任务结束后                                  │
│  Layer 2: 近期历史（最近N次任务，结构化摘要）    │
│  ↓ 超过N次任务后                               │
│  Layer 3: 长期记忆（永久知识库，仅存结论）       │
└──────────────────────────────────────────────┘
```

### Layer 1：即时观察（不压缩，全量保留）

| 保留 | 丢弃 |
|------|------|
| Agent当前思考轨迹 | 重复的自我纠正 |
| 关键搜索结果URL+摘要 | 相同的搜索结果（去重后） |
| 工具调用输入/输出 | 失败的中间尝试（只保留最终成功路径） |

**实现**：代码层去重。用匠石铁律——代码比较文本相似度，重复率>80% → 丢弃。

### Layer 2：近期历史（结构化摘要）

任务结束后，将完整交互压缩为结构化摘要：

```
{
  "task_id": "xxx",
  "summary": "研究GraphRAG优化方案，搜索10源，合并为3个方向，最终推荐依赖解析路线",
  "key_findings": ["依赖解析可替代94%LLM建图", "RRF融合检索优于纯向量"],
  "errors_encountered": ["arxiv链接失效×2"],
  "agent_performance": {"tan": 0.85, "xie": 0.72},
  "evolution_hints": ["xie在技术类写作需加强引用准确性"]
}
```

**压缩率**：~90%（从完整15K token压缩到~1.5K token）

### Layer 3：长期记忆（仅存结论）

超过阈值（如20次任务后）的Layer 2摘要再次压缩：
- 只保留结论性的知识条目
- 汇入wiki知识库（作为永久节点）
- 从Agent上下文中移除

**实现**：由依赖解析GraphRAG自动挂载到知识图谱，作为图节点。

## 三、冗余检测算法（代码化）

```python
def is_redundant(new_obs: str, existing_obs: list, threshold: float = 0.8) -> bool:
    """用文本相似度检测是否冗余。匠石铁律：代码做，不用模型。"""
    from difflib import SequenceMatcher
    for obs in existing_obs:
        ratio = SequenceMatcher(None, new_obs[:500], obs[:500]).ratio()
        if ratio > threshold:
            return True
    return False
```

**关键设计选择**：不用embedding做相似度（需要模型），用difflib字符串匹配（纯代码）。虽然不如embedding精确，但零成本，够用。

---

## 四、与ReVeal进化引擎的融合点

| 压缩机制 | 进化引擎联动 |
|---------|------------|
| Layer 2 的 `errors_encountered` | 直接喂给进化引擎的weakness检测 |
| Layer 2 的 `agent_performance` | 更新Topology API的performance_history |
| Layer 3 的结论性知识 | 依赖解析GraphRAG自动构建节点+边 |

**融合时机**：v0.5将压缩+进化作为同一个生命周期管理器实现。

---

## 五、MVP范围（v0.5时实现）

- [ ] Layer 1冗余检测器（difflib去重）
- [ ] Layer 2结构化摘要生成（LLM调用一次，不是每次）
- [ ] Layer 2阈值触发：最近10次任务保留摘要，超出的进入Layer 3
- [ ] 与Topology API联动：摘要数据自动更新Agent表现

### 不做的事

- ❌ 不做实时embedding相似度（成本）
- ❌ 不做Layer 3自动知识图谱挂载（v1.0的事）
- ❌ 不做跨会话压缩（当前一次会话内处理）

---

## 六、预期效果

| 指标 | 未压缩 | 压缩后 |
|------|-------|--------|
| 平均上下文token | ~15K | ~3K |
| 冗余信息占比 | ~40% | <10% |
| 关键信息遗漏率 | 0 | <5% |
| LLM注意力稀释 | 高 | 低 |

> **设计哲学**：压缩不是为了让Agent记住更多——是让它忘掉该忘的，才能专注该记住的。
