# 鲁班 — 工程可行官

## izu 记忆基础设施可行性判断

### 能不能做？✅ 能做

### 但需要注意：不要重复造轮子

现有可复用工具：
| 组件 | 可用方案 | 评估 |
|-----|---------|------|
| 向量存储 | Mem0 (ECAI 2025, MIT) | 成熟，92.5 LoCoMo |
| 会话摘要 | GPT-4o 自然摘要输出 | 现成，但需设计 prompt |
| 用户画像构建 | 结构化 JSON 存储 + SQLite | 简单，izi 自己的 |
| 遗忘调度 | 自定义实现（~100行 Python） | 艾宾浩斯曲线公式化 |
| 图关系存储 | NetworkX + SQLite | 轻量，无需图数据库 |

### 造什么装备？

izu 需要自造的只有两个组件：

1. **记忆整合模块**（⚡ 关键装备，8工时）
   ```
   class MemoryIntegrator:
       - ingest(conversation: list[Message]) → SessionSummary
       - extract_entities(summary) → EntityGraph
       - update_profile(user_id, entities) → UserProfile
       - forget(user_id, threshold=0.3) → None  # 遗忘调度
   ```
   - 这个模块连接记忆提取和用户画像，是 izu 独有的设计点
   - 不能直接用 Mem0——Mem0 是通用框架，izu 需要知识陪伴特化

2. **记忆触发系统**（4工时）
   ```
   class MemoryTrigger:
       - on_new_message(msg) → [relevant_memories]
       - should_proactively_mention() → bool
       - what_to_ask() → str  # 主动追问
   ```
   - 决定「什么时候提起旧事」——这是陪伴感和「真记住」的分水岭

### 依赖关系
```
记忆整合模块 ──→ 需要 → 向量存储 (Mem0) + SQLite
记忆触发系统 ──→ 需要 → 记忆整合模块的输出
```
**必须按序开发**：先做整合模块，再做触发系统。

### 工程风险
1. **Mem0 集成复杂度**: 如果 Mem0 API 变化频繁，锁定版本
2. **token 消耗**: 每次记忆整合都会消耗 token，日均 1h 约束下需要限制每次整合 ≤2K tokens
3. **遗忘策略设计的心理学复杂度**: "AI 该记住什么" 非纯工程问题，需要用户研究
