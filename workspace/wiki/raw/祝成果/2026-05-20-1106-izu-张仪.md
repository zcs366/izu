# 张仪 —— 最强攻击官

## 单点失败分析

### 最可能导致izu记忆项目失败的一个点: 记忆检索噪音导致对话质量下降

**为什么是它，而不是其他？**
- 记忆系统最容易出现的情况不是「记不住」而是「乱回忆」
- 当izu的对话上下文中混入了10条不相关的旧记忆，回答质量会明显下降——不是变好，是变差
- 用户对「Agent变笨了」的感知极快——一次糟糕的回答就可能丧失信任
- 相比之下，安装Mem0本身几乎不可能失败（pip install就行）

**其他候选失败点的排除理由**:
- Mem0集成失败 → 概率趋近于零，文档成熟
- 实体抽取不准 → 可以fallback到纯语义搜索
- 记忆膨胀 → 有TTL机制，且默认配置就能用
- 算力不够 → CPU可跑

### 失败场景推演

```
Day 1-3: izu加入了记忆，用户觉得不错
Day 4-7: 记忆越来越多，检索开始混入弱相关结果
Day 8: 用户问A，izu拿B的记忆来回答，答非所问
Day 9: 用户觉得izu退步了，关掉记忆功能
```

**核心问题**: 记忆的边际收益曲线在某个点之后变成**负值**——不是不够多，是太多了。

### 失败概率估算: ≈ 40%（高于ITA的30%——因为这是实际用起来的问题，不是理论问题）

## 降级方案

**A级降级（检索阈值控制）**:
- 在Mem0的search中设置relevance_score阈值（默认0.5），调高到0.7
- 代价：牺牲部分召回率，但保证回答质量不下降
- 实现：3行代码

**B级降级（选择性回忆）**:
- 不让所有记忆都进入上下文
- 只在用户明确提到「还记得上次...」时触发回忆
- 代价：记忆变得更被动，但用户不会感到「变笨」

**C级降级（记忆关闭开关）**:
- 提供一个「/forget」或「/noforget」切换命令
- 用户感觉记忆质量下降时手动关闭
- 这不是失败——这是给用户留了一条安全出口

### 预警信号

对话质量评分（LLM自评）连续3次下降 → 触发A级降级
用户明确抱怨 → 触发B级降级
用户长时间不用 → 触发C级降级（自动关闭记忆恢复基线能力）
