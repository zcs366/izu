# 鲁班 — 工程可行官

## 工程协调意见

### 两轨道矛不矛盾？
**不矛盾，但在资源上有争抢。**
- ITA 需要 GPU（1x A100 12h，约 $30）
- izu 需要 API tokens + SQLite + 开发时间
- 争抢的是张成市的**日均 1h 的注意力**，不是计算资源

### 可以一起推进吗？
**可以，但有先后顺序建议：**

#### 第一优先: ITA Phase 0（基线测试，8天）
```
原因:
1. CodeBERT round-trip 是「验证性实验」——要么成功要么失败，没有中间态
2. 基线结果直接影响 ITA 后续决策（4x 压缩可行？需要 SAC？）
3. 8 天可交付可证伪结论
4. 不需要等 izu 的任何组件
```

#### 第二优先: izu Phase I（记忆基线，8天）
```
原因:
1. 与 ITA 无依赖关系，可以独立推进
2. 8 天可交付「跨会话回忆」能力，用户可感知
3. 如果 ITA P0 失败（CodeBERT baseline 太低），izu 的交付可以补充 momentum
```

#### 如果时间冲突: 交替推进
``` 
Week 1-2: ITA P0 (基线)               ████░░░░
Week 3-4: izu Phase I (记忆)           ░░░░████
Week 5-6: ITA P0.5+P1 (FSQ+SAC)       ████░░░░

```

这样两轨道都不停滞，且每两周有一个可交付成果。
