## ITA Round 4: 萧何
### 资源路径

基于鲁班的三个工程阶段，给出实际的资源需求、执行路径和时间线。

### 1. 资源需求总览

| 资源类型 | 阶段一 | 阶段二 | 阶段三 |
|----------|--------|--------|--------|
| **开发工时** | 1-2天 | 3-5天 | 2-4周 |
| **API配额** | 每查询+1次LLM调用（验证器） | 每查询+1~3次LLM调用（重规划） | 保持 |
| **存储** | 无新增 | ~100KB/次（执行日志） | ~500KB/次（含依赖图） |
| **外部依赖** | 无 | 无 | MCP SDK + A2A库 |
| **测试用例** | 5-10个 | 30-50个 | 100+个 |

### 2. 分阶段执行路径

**阶段一：验证器前置（本周可完成）**
```
Day 1:
  - 创建独立的验证器模块 /utils/verifier.py
  - 设计验证评分标准（完整度1-5，来源质量1-5，逻辑一致性1-5）
  - 在delegate_task返回后插入验证步骤
  - 验证结果写入工作记忆

Day 2:
  - 编写5个验证测试用例
  - 对比有/无验证器的输出质量差异
  - 调优验证Token预算和Prompt
```

**阶段二：重规划循环（2周内）**
```
Week 1:
  - 实现ReplanManager：接收验证结果→生成补计划→调度执行
  - 设置最大重规划次数（默认2）
  - 防无限循环保护（时间/Token双限）

Week 2:
  - 状态管理：维护执行上下文，防止重复计算
  - 日志：追踪每轮循环的输入/输出/得分
  - 30个集成测试
```

**阶段三：DAG调度+协议标准化（1个月）**
```
Week 1-2:
  - DAG依赖图构建器（基于子任务输出/输入分析）
  - 拓扑排序执行器
  - 并行调度优化

Week 3-4:
  - MCP Server搭建（Python SDK）
  - 工具调用从自定义JSON迁移到MCP格式
  - A2A端点设计（Agent间通信）
  - 旧协议逐步退役
```

### 3. 关键依赖和前置条件

1. **阶段一无前置依赖**，但需要确认验证器模型选择（同API不同模型 vs 不同API）
2. **阶段二依赖阶段一**（需要验证器评分数据作为重规划触发条件）
3. **阶段三依赖**：
   - MCP官方Python SDK的稳定性（需检查当前版本）
   - A2A协议规范是否已发布稳定版
   - 现有工具调用的接口文档完整度

### 5. 加速路径（可选）

- **并行化阶段二和三**：如果团队有2名以上开发者，可在阶段二进行的同时启动MCP协议调研和工具接口文档整理
- **降低复杂度**：阶段三的DAG调度可用"依赖优先级队列"替代完整拓扑排序，降低实现复杂度约60%
- **跳过阶段三**：如果MCP/A2A在Hermes场景下的收益不显著（通过实验2验证），可直接跳过
