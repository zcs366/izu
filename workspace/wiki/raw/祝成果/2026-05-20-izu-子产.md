# 子产

## 需求判断：该不该做？

**该做。**

izu 当前面临的核心瓶颈：Agent 记忆系统停留在「手工规则操作」阶段——MemoryBank/A-MEM 等系统每轮对话后执行固定流程提取记忆。MemSkill（2026）的突破性进展表明，**可学习、可进化的记忆操作（skill）** 是下一代 Agent 记忆系统的方向。

**不做会怎样？**
- zu 的记忆系统将卡在「规则驱动」阶段，无法自适应不同任务
- 新 Agent 框架（如 Letta、CrewAI）正在加速迭代，3-6 个月后 zu 现有架构将落后
- 自进化是 zu 的核心差异化——不做记忆 skill 进化，就失去了自进化的关键一环

**为谁做？**
- 核心受益者：zu Agent 本身（更好的长期记忆 → 更好的故事线延续 → 更好的用户陪伴）
- 间接受益：ITA 的代码语义压缩成果可以反哺 Agent skill 的表示压缩

## 研究方向定位

### 关键问题
**Agent 如何从交互历史中自动提炼可复用的、跨场景的记忆操作（skill），并持续进化？**

### 核心假设
Agent 的记忆不需要依赖大量手工调参的记忆规则。如果提供一个带初始化 skill bank 的轻量框架，通过在线交互的反例自动进化 skill，就可以在不需要重训练的情况下持续改善记忆质量。

### 假设正确性评估
- MemSkill 的跨模型泛化实验（LLaMA→Qwen 迁移成功）强支撑该假设
- 但 MemSkill 需要 offline 的 hard case 收集和 designer 重训练 → 与 zu 的在线进化有差距
- 需要验证：能否在纯在线场景下实现 skill 进化？

### 研究方向建议
**izu 应优先关注 MemSkill 框架的在线化适配**，而非从头发明新架构。原因是：
1. MemSkill 开源（代码已可用）
2. 核心架构已经验证（3 个基准 + 分布外迁移成功）
3. 空白点：MemSkill 的 designer 需要定期 review hard cases → 能否替换为在线主动学习？

### 与 ITA 的交叉点
子产注意到 ITA 的「代码语义压缩」研究与本方向的一个深层交叉：
- Agent skill 本质上就是「可执行的代码片段」
- 如果 ITA 找到代码语义压缩的方法，Agent skill 的存储和检索成本可以大幅降低
- 反之，izu 的 skill 进化经验可以为 ITA 的「代码理解」提供行为层面的信号
