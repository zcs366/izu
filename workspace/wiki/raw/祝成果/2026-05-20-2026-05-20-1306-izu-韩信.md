# 韩信（技术远景官）

## 对izu 3-6个月方向的影响

### 本轮发现如何影响izu的技术路线

**子产的方向修正：izu核心 = 轻量级记忆系统 × 知识陪伴界面**

这个判断与当前搜索发现一致，但需要更具体的技术阶梯。

### 技术阶梯（3-6个月）

```
Month 1-2: 记忆层搭建
  └ 选型Mem0/GitMemory做底层 → 剪枝到个人开发者的最小可用集
  └ 重点：记忆衰减机制 + 混合检索（BM25+向量+HNSW）
  └ 输出：可用于izu的知识库API

Month 3-4: 交互层建设
  └ 知识陪伴对话框架（基于zu系已有交互）
  └ 自然会话中记忆的写入/读取/更新
  └ 输出：用户可与izu日常对话，izu自动积累记忆

Month 5-6: 记忆优化与技能萌芽
  └ 基于ITA的实验结果（如果20天后出结果）决定能否做语义压缩
  └ 记忆的自动分类和优先级排序
  └ 输出：技能系统的基础——基于记忆模式识别
```

### 需要纳入的新技术路线

1. **混合检索（Hybrid Search）**：BM25 + 向量检索 + 图检索的三层架构
   - Mem0的架构设计值得借鉴
   - Corgi（87.8% LoCoMo）的decay-weighted策略是当前SOTA
   
2. **记忆衰减模型**：不是简单的LRU/时间衰减
   - 基于ITA率失真分析的最优衰减曲线
   - 用户交互频率作为衰减调节因子
   - 重要记忆（用户明确标记的）不衰减

3. **知识图**：简单的实体-关系图
   - 不需要Neo4j级别，JSON-based Property Graph即可
   - 支持"你上周三提到了XX项目"这类关联查询

### 终局画像调整

**原终局**：izu是一个全能的个人Agent
**调整后终局**：izu是一个**知道你的过去、能自然聊天、该忘的会忘**的知识陪伴Agent

关键变化：
- 从"全知"到"刚好知道"——记忆不是越多越好
- 从"任务完成"到"陪伴中帮忙"——交互基调变化
- 从"技能进化"到"记忆中成长"——自动从对话中学习用户偏好

### 技术风险

| 风险 | 影响 |
|------|------|
| 混合检索的延迟在个人设备上不可接受 | 需剪枝到2层（BM25+向量） |
| 知识图构建需要大量结构化数据 | 先用简单标签替代 |
| ITA实验失败导致语义压缩不可用 | 记忆衰减只能靠启发式规则 |
