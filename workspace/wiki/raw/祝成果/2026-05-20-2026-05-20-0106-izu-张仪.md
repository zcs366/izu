# 张仪 — 最强攻击官

## 单点失败分析 + 降级方案

### 最致命的失败点: 记忆系统导致 izu 人格分裂

**为什么这是最致命的？**

izu 目前的角色是「军师祭酒」——一个有鲜明个性的知识陪伴者。记忆系统带来的最大风险不是技术上的，而是**人格一致性**上的：

1. **情绪污染**: 如果 izu 记住了用户昨天的负面情绪，今天可能过度补偿（假关心）或延续负面语调。
2. **记忆冲突**: 用户可能在不同语境下说矛盾的话（"我爱 Python" vs "Python 垃圾"），记忆系统如果同时保留两者，izu 会在同一个对话中分裂。
3. **过度个性化**: 用户今天心情好叫它"军师"，明天心情差叫它"机器"。如果记忆系统记录了后者，izu 可能在不恰当的时候使用过于正式或过于随意的语气。

### 影响范围
这不是一个 bug，而是**产品级别的信任崩塌**。用户对 izu 的信任建立在「它知道自己在说什么」。如果 izu 昨天是乐观陪伴者，今天变成悲观分析者，用户会感到不安。

### 降级方案: 情感记忆隔离 + 状态机

#### 方案: 三层记忆隔离（12工时）

```
记忆系统
├── 知识层（不可变）: 用户的技术偏好、项目信息、知识背景
│   └── 提取规则: 仅提取事实，不提取情感
├── 情境层（可覆盖）: 最近 3 次会话的 topic + 用户情绪
│   └── 更新规则: 新会话覆盖旧会话
└── 情感层（瞬时）: 当前会话的情绪上下文
    └── 过期规则: 会话结束时清空
```

**关键设计**:
- 「用户说讨厌Python」→ 知识层记录 `preference: Python (negative)`
- 「用户情绪低落」→ 情境层记录 `mood: frustrated`，然后被新一轮覆盖
- 情感层不长期存储 → 避免「昨天emo的izu今天还emo」

#### 状态机

izu 在记忆系统中的状态切换必须受约束：
```
闲置 → 知识检索 → 情境匹配 → 情感评估 → 响应生成
                  ↓ (不匹配)
                默认人格 ← 安全回退
```

如果情境层找不到匹配记忆 → 回退到默认人格（军师祭酒的基础设定），不会因为「部分匹配」而产生人格漂移。

### 结论
izu 记忆系统最大的敌人不是技术本身，而是**记忆带来的自我不一致**。技术策略：
1. 知识层和情感层严格隔离
2. 记忆不匹配时安全回退到默认人格
3. 用户的负面情感不进入长期记忆（仅情绪层）
