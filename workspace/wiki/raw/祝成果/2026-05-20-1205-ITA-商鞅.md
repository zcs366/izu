# 商鞅 — 实验设计官

## 最小可行实验（20工时）

### 实验目标
验证 Semantic RD Theory 对代码压缩的基本前提能否成立：
**从代码的「irredundant core」能否恢复出原始代码的语义闭包？**

### 实验方案：三步走

#### Step 1：提取 irredundant core（4工时）
**工具**：Python 的 `ast` 模块 + `typing` 模块 + `control_flow_graph` 工具
**做法**：
1. 选取 MBPP 数据集 500 个函数（Python，含类型标注）
2. 对每个函数，用 AST 分析提取：
   - 类型签名（函数名 + 参数类型 + 返回类型）
   - 控制流骨架（if/else/loop 结构，去除具体表达式）
   - I/O 规格（从 docstring/assertion 中提取的前后置条件，如果有）
3. 将三者拼接为 irredundant core 的文本表示

**产出**：500个函数对应的 core 文本

#### Step 2：测试 core → 完整代码的恢复能力（8工时）
**方法A**：用 LLM（GPT-4o-mini 或同等）从 core 恢复完整代码，看能否通过原 MBPP 单元测试
**方法B**：用 CodeBERT 做完形填空——将原函数中变量名/常量值用 `<MASK>` 替代，core 作为 hint 输入，看预测准确率

**判断标准**：
- 成功：>60% 的从 core 恢复的代码能通过原 MBPP 测试
- 部分成功：30-60%，说明 proof system 需要增强（如加入条件语义）
- 失败：<30%，说明 core 的定义不对

#### Step 3：测量压缩率（6工时）
1. 计算每个函数的 Shannon 熵（token-level）
2. 计算每个函数的 core 熵
3. 计算杠杆因子 Λ = H(C) / H(core)
4. 对比不同类型（纯函数 vs 有状态 vs I/O 密集型）的 Λ 差异

### 失败判断标准
- 如果 Step 2 的恢复率 < 30%：说明代码的 proof system 不是类型系统+控制流骨架，需要重新定义（也可能代码语义压缩这条路走不通）
- 如果杠杆因子 Λ < 1.5：代码的语法冗余本就不多，语义压缩没有实践意义

### 所需资源
- 1 台 GPU（用于 CodeBERT 推理，可选 Method B）
- 数据集：MBPP（已有在线版）
- 工具链：Python + ast + typing + openai API（GPT-4o-mini 的 500 次调用 ≈ $2）
- 总成本估算：$5-10（含 API 调用）
- 总工时：18 工时（5 个工作日 × 日均 1h ≈ 4 天完成，预留 2 工时缓冲）
