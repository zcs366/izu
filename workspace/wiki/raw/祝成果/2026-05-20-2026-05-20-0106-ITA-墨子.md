# 墨子 — 形式化验证官

## 核心主张的形式化与率失真边界

### 主张 1: 代码可以通过隐空间压缩至原始体积的 1/10 而保留 95% 的语义信息
- **形式化**: 存在编码器 E: C → Z 和解码器 D: Z → C'，使得对任意代码 C ∈ C，```
  Pr[exec(C) = exec(C')] ≥ 0.95
  且 |Z| / |C| ≤ 0.1
  ```
- **率失真分析**: 代码的语义空间是离散的（正确/错误）。香农率失真定理 R(D) ≥ H(S) - H(D)。对于代码，语义源熵 H(S) 受限于可区分程序的数量。对于一条 100-token 的 Python 函数，可能的语义状态 ≤ 2^(100) 但有效语义状态远小于此（因为语法约束+类型约束）。
- **下界估计**: 在失真 D=0.05（95%准确率）下，理论最小码率 ≈ log2(N_有效语义) / 100。粗略估计，Python函数的有效语义熵约 2-4 bits/token → 理论最小压缩率约 25-50% 原始体积。**1/10压缩率可能低于理论下界，需要调整目标至 1/2 ~ 1/4**。

### 主张 2: Activation Steering 可以定向修改代码生成行为
- **形式化**: 存在方向向量 δ，使得对任意代码 C，```
  similarity(steer(E(C), δ), E(C_target)) > similarity(E(C), E(C_target)) + 0.3
  ```
- **验证实验**: 用已知 bug pattern（如 SQL 注入）训练 steering vector，测试生成代码中该模式出现率的变化。
- **理论约束**: Representation Engineering 论文表明 steering 的有效性受限于模型隐空间的线性可分性。代码 bug pattern 往往是高度非线性特征，steering 对此类特征的操控精度有限。

### 主张 3: FSQ 可以替代 VQ-VAE 用于代码隐空间量化
- **形式化**: FSQ 的码本利用率 = 100%（无坍塌），而 VQ-VAE 的码本利用率 ≤ 60%。
- **验证**: 在代码数据集上，FSQ 的 perplexity ≥ 0.95 × 码本大小，VQ-VAE 的 perplexity ≤ 0.6 × 码本大小。
- **理论下界**: FSQ 不包含指数移动平均或承诺损失，收敛速度理论上更快。但 FSQ 的标量量化会损失向量空间中的关联信息——这对代码语义是福是祸需要实验验证。

### 率失真边界结论
| 压缩率目标 | 理论可行？ | 所需失真容忍度 |
|-----------|-----------|--------------|
| 10x (1/10) | ⚠️ 低于理论下界 | 需接受 >5% 语义损失 |
| 4x (1/4) | ✅ 理论可行 | 可望 <2% 语义损失 |
| 2x (1/2) | ✅ 理论可行 | 可望 <0.5% 语义损失 |

**核心建议**: 将 ITA 压缩目标从「10x 压缩 + 95% 语义保留」修正为「4x 压缩 + 98% 语义保留」。
