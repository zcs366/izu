# 🧠 子产·情报合成

## 情报概要

本轮搜索覆盖三大方向，发现三项高度相关的最新突破：

### ITA方向核心发现
1. **Semantic Rate-Distortion Theory** (Xu, SJTU, arXiv:2604.11204, Apr 2026)
   - 首个以封闭保真度（closure fidelity）为标准的率失真理论
   - 核心发现：当 source 配备 proof system 时，零失真语义速率 = P_A·H(π_A) < H(P_O)
   - 冗余状态在语义保真度下对速率和失真"不可见"
   - **对代码的含义**：代码的编译器/类型系统/Turing完备性就是 proof system。如果压缩只要求保留代码的"可推导结论"而非逐比特精确，压缩率可以远高于无损压缩
   - 理论杠杆因子 Λ_∞ = log|S_O|/(P_A·H(π_A)) > 1

2. **Natural Language Autoencoders** (Anthropic, Transformer Circuits, May 2026)
   - 通过 RL 训练 Activation Verbalizer → Activation Reconstructor
   - 以自然语言为瓶颈压缩/重建残差流激活向量
   - **关键意义**：证明 latent space 可以通过语义瓶颈压缩而不丢失功能行为
   - 可用于 steering: 编辑解释 → AR 重建 → 获得 steering vector

3. **iFSQ/FSQ 进展**：图像域 FSQ 继续改进（残差量化变体），但代码语义域仍是空白

### izu方向核心发现
1. **EvolveMem** (UNC, arXiv:2605.13941, May 2026)
   - 自进化记忆架构：检索配置本身通过 AutoResearch 闭环进化
   - Evaluate–Diagnose–Propose–Guard 四步循环
   - LoCoMo 上 30.5% → 54.3% F1（GPT-4o backbone, 7轮进化）
   - 超越最强基线 25.7%
   - 配置跨 benchmark 正迁移（非过拟合）

2. **Mem0 2026**：LoCoMo 92.5, LongMemEval 94.4 @ ~6,900 tokens/query
   - 单次pass分层提取 + 多信号检索
   - 最大增益来自 temporal reasoning (+29.6) 和 multi-hop (+23.1)

3. **Benchmark标准化**：LoCoMo / LongMemEval / BEAM (1M-10M tokens) 三大标准

### 核战队交叉发现
1. **NLAs + Semantic RD Theory 的交汇**：两者指向——如果有正确的 proof system（即语义结构），压缩可以大幅超越 Shannon 无损边界而不丢失功能行为
2. **当前空白**：代码域尚无人将 Semantic RD Theory 应用于压缩基准测试
3. **评估基础设施空缺**：GAN / 困惑度 / BLEU 都不适合衡量代码的语义保真度

## 3个关键问题

1. **代码的 proof system 是什么？** 编译器类型检查？形式化验证？运行时动态语义？还是程序员的意图推理？→ **ITA 合议处理**
   - 这决定了 Semantic RD Theory 能否直接应用于代码压缩
   - 如果 proof system 是类型系统+编译器，则闭包的基数远小于源代码的比特数，压缩杠杆巨大

2. **NLAs 的技术能否直接借用到代码隐空间？** 代码的 activation verbalizer 应该输出什么？AST？伪代码？自然语言描述？→ **ITA 合议处理（鲁班工程评估）**
   - Anthropic 的 NLAs 针对自然语言，但代码的隐空间结构可能完全不同

3. **EvolveMem 的自进化回路能否移植到 izu？** 日均1h的工人如何维护记忆策略的自我进化？→ **izu 合议处理**
   - EvolveMem 的 AutoResearch loop 需要 LLM 驱动诊断+提案，GPU 成本如何控制在 $925 预算内？

## 可信度评估
- **Semantic RD Theory**：高。arXiv 2026年4月，有完整的数学推导，在 Datalog 实例上验证（24,000 base facts）
- **NLAs (Anthropic)**：高。Transformer Circuits 官方发布，在 Opus 4.6 audit 中有实际用例
- **EvolveMem**：高。开源代码，有完整 benchmark 报告
- **Mem0 scores**：中高。Mem0 是商业产品，但 benchmark 结果可复现
- **代码域 proof system 应用**：低。本文未讨论代码域，是理论推测
