# 萧何 · 执行路径官

【鲁班工程判断】
- Mem0集成（1-2天）
- 交互信号采集（1小时）
- 知识节点系统（30工时，3-4周后启动）

## 资源盘点

**人力**：张成市日均1小时（高峰日可2小时，低谷可0小时）
**时间窗口**：当前（5月）- 11月（6个月窗口）
**总可用工时**：~130小时（6个月 × 5天/月 × 5小时/周）

## 阶段拆解与排期

```
📅 第1周（5月第3周）→ 快速搭建记忆基础
   Mon-Tue: Mem0集成（2h）
   Wed: 交互信号采集埋点（0.5h）
   Thu: 记忆分层抽象接口（1h）
   Fri: 验证闭环跑通（1h）
   本周工时：~4.5h ✅ 单周可完成
   里程碑：izu开始记录对话 → 可在下次对话中引用上次内容

📅 第2-4周（5月底-6月中）→ 语义提取试点
   使用LLM从对话记录中提取知识节点（主体-客体-关系）
   人工验证提取质量 → 调整prompt
   每周工时：~3h（维护+提取+验证）
   里程碑：izu能够回答"上次我们聊到哪了"

📅 第5-8周（6月中-7月）→ 知识节点系统建设
   自建SQLite+Chroma存储 → 替代Mem0
   知识节点查询+召回接口
   skill提取MMV（最小可验证版本）
   每周工时：~5h
   里程碑：izu的知识检索完全自控

📅 第9-16周（7-9月）→ Skill自进化
   MemSkill思想借鉴 → 适配izu架构
   RL-based skill selection（可选，或先用规则）
   skill验证闭环
   每周工时：~5h
   里程碑：izu能自己学会新的交互模式

📅 第17-24周（9-11月）→ 陪伴质量调优
   收集的信号开始有统计意义 → 调整记忆遗忘策略
   A/B测试不同的记忆召回策略
   用户主动发起率监测
   每周工时：~2h维护
   里程碑：izu主动续接率达到有意义水平
```

## 关键路径

**第1周的Mem0集成是唯一的前置依赖**——所有后续步骤都建立在这个基础之上。

最大的时间风险在5月（日均1h的磨合期）：
- 如果连续3天无投入，第1周的4.5h目标会拖到第2周
- 建议：第1周集中投入（周末补2h），确保记忆基建不断裂

## ITA-izu交叉排期

ITA也建议在第1周启动（代码语义可分性实验），两者在第一周并行不冲突——ITA是离线实验（单独跑python脚本），izu是系统集成（改izu代码）。
