# 韩信 · 技术远景官

【子产的判断】
- 记忆系统是izu核心差异点
- 以知识节点为原子单位（主体-客体-关系-置信度-时间戳-来源）
- 先跑最小闭环，再考虑知识节点表示

## 技术远景：izu 3-6个月后

### 3个月远景（2026年8月）→ 记忆闭环跑通
- 底层使用Mem0（最快启动）+ izu专属的skill抽象层
- 实现最小闭环：对话记录 → 语义提取 → 验证 → 存储 → 召回使用
- 关键里程碑：用户能看到izu"记住了"上次对话的偏好（不仅是最后一段）

### 6个月远景（2026年11月）→ 自进化雏形
- 从Mem0迁移到（或自建）知识节点系统
- Skill提取半自动化（LLM提取质检 + 人工确认关键skill）
- 记忆的操作性定义从"所有历史"升级为"高信息密度节点"
- 关键里程碑：izu能在用户忘记的话题上主动续接（而非被动等待指令）

### 对当前的影响
**两件事现在就需要纳入**：
1. **记忆分层设计**：不要等产品成型再改架构——现在就把episodic / semantic / procedural的三层抽象定好。未来切换底层框架时只需重写storage层。
2. **交互信号采集**：从第一天开始记录用户行为信号（主动发起率、回复速度、话题切换频次），这些数据是6个月后训练"知识节点重要性"模型的训练集。

### 终局画像调整建议
izu的终局画像从"一个聪明的聊天助手"调整为"一个知道你在学什么、做到哪了、卡在哪的长期同行者"。后者需要记忆，前者只需要系统提示词。
