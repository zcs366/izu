# 张仪

## 单点失败分析

### 最可能导致项目失败的一个点

**CodeBERT 嵌入对代码「功能语义」不敏感的问题。**

### 问题展开

整个方案建立在 CodeBERT 嵌入能够捕捉代码的**功能语义**（而非表面形式）这个假设上。
但现有证据表明：

1. CodeBERTScore 论文的评估基于**生成代码与参考代码的比较**——在这个任务中，两段代码往往是同一算法的不同 token 序列。这不是真正的「不同算法但等价」场景。

2. 代码嵌入模型（包括 CodeBERT）的训练目标是 mask language modeling + replaced token detection——这些预训练任务**奖励的是对代码表层结构的学习**，而不是对代码执行行为的学习。

3. HumanEval 中的函数等价性指的是**执行等价**——给定相同输入产生相同输出。但 CodeBERT 嵌入没有见过任何执行信号。如果两个函数实现相同功能但用了完全不同的算法（如 bsort vs qsort 都是排序），CodeBERT 嵌入可能会把它们视为完全不同的代码。

### 致命场景

假设商鞅的实验结果：
- CodeBERTScore 保真度 ≥ 0.95（量化损失很小，好消息）
- 但等价代码分类 AUC = 0.65（量化后的嵌入**分不清**语义等价 vs 不等价的代码）

这意味着：FSQ 量化确实保留了 CodeBERT 嵌入本身的信息，但**CodeBERT 嵌入本身就不擅长捕捉代码的深层语义等价性**。整个方案变成了「精确地保留了一个不够好的表示」。

**这个失败是无法通过优化 FSQ 参数来修复的**——因为根因在编码器，不在量化器。

## 降级方案

### 降级路径 A（如果编码器是瓶颈）

不换量化方案，换**编码器**：

| 编码器 | 语义敏感性 | 代价 |
|--------|-----------|------|
| CodeBERT-base | 未知（本文的假设风险） | 免费 |
| CodeLlama-7B | 更高（更大模型，更多预训练数据） | 需要 GPU（$5-10 Colab） |
| Exec-CodeBERT（fine-tuned on execution） | 最高（见过执行信号） | 需要训练数据 |
| GPT-4 embedding API | 未知但通常更好 | 每次 $0.001/1K tokens |

建议：在商鞅实验中**并行加入 CodeLlama 嵌入作为对照组**。如果 CodeBERT 分类 AUC < 0.8 而 CodeLlama ≥ 0.85，问题出在编码器，降级方案就是换编码器。

### 降级路径 B（如果整个框架不可行）

放弃「代码本身 → 压缩」的范式，转向「代码行为 → 压缩」：

```
code + test_input → 执行输出 → LLM总结行为描述 → embedding → FSQ量化
```

这个范式：
- 绕过了对代码语义表示的学习难题
- 直接压缩的是行为签名（更本质）
- 缺点：输入相关，需要测试用例
- 但可以与 izu 的「Agent 行为记录」共享架构

### 降级路径 C（放弃压缩，转向表示学习）

如果压缩本身被率失真理论排除（墨子已有判断），放弃压缩目标，转向：

**代码语义表示学习**：训练 CodeBERT 的下游任务——代码等价性判别。不需要压缩，只需要更好的代码语义理解。这个成果可以反哺到 zu 的 Agent 代码分析和 ITA 的泛化研究。

---

## 张仪判结

**最大致命点**：CodeBERT 嵌入不够「语义」，导致整个 FSQ 量化方案在错误的表示空间上优化。

**兜底策略**：商鞅实验中增设 CodeLlama 对照组 + 等价代码分类 AUC 指标，早发现早换道。如果 AUC < 0.8，启动降级路径 A。
