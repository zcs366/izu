# 惠施 — 概念辨析官

## 核心概念的操作性定义

### 1. 「代码语义」
- **非操作性定义**：代码要表达的意思
- **操作性定义（惠施版）**：给定一段代码 C 和一组输入 I，代码语义 S(C) = { (i, o, t) | i ∈ I, o = eval(C, i), t = type(C, i) }，其中 eval 是可计算函数（运行时行为），type 是类型推导结果。对函数式代码，还应包含引用透明性和效果（effect）信息
- **关键分歧**：语义是 denotational（数学语义）、operational（运行时行为）还是 deductive-closure（可推导结论）？**本轮建议采用 deductive-closure 版本**，因为 Semantic RD Theory 以闭包为基础

### 2. 「理解」
- **非操作性定义**：模型"知道"代码在做什么
- **操作性定义**：模型对代码 C 的理解程度 = max(R(C), M(C))，其中：
  - R(C) = round-trip 一致性：code_to_latent(C) → latent_to_code(C') 后，C' 与 C 的语义等价率
  - M(C) = 下游任务准确率：根据 latent 编码做代码搜索/修复/补全的成功率
- **接受标准**：理解 = latent 编码保留了 deductive closure 的全部内容

### 3. 「Steering成功」
- **非操作性定义**：成功引导了模型行为
- **操作性定义**：在 latent space 中施加 delta v 后，模型在 N 个测试用例上的输出分布偏移与预期方向一致的比率。|P(output|C+δ) - P(output|C)| > ε 且方向正确
- **测量**：用 NLAs 方案——编辑 verbalizer 输出 → AR 重建得到 steering vector → 测下游行为偏移

### 4. 「压缩」
- **非操作性定义**：用更少的比特表示代码
- **操作性定义（语义压缩版）**：给定 proof system P，压缩算法 f: C → b 使得 b 的比特数 < H(C) 且 de·d(b) 的推导闭包 = de·d(C)。即压缩率取决于闭包中冗余信息的多少
- **率失真边界**：由 Semantic RD Theory 给出——零失真语义速率 = P_A·H(π_A)。如果代码的 irredundant core 很小，压缩率可以很大

### 5. 「代码的 proof system」
- 这是本轮最关键的概念澄清
- **候选1**：类型系统（Hindley-Milner / System F）。类型推导结果 = 闭包的一部分
- **候选2**：编译器（GCC/LLVM IR）。编译后的中间表示保留了所有运行时行为
- **候选3**：形式化规范（Coq/Lean 证明项）。最高要求
- **建议采用**：对实用目的，proof system = 类型系统 + 函数的 I/O 规格 + 控制流图。这是 Semantic RD Theory 中"proof system"的最小可行实例

## 关键结论
- 只有先把「代码语义」定义为 deductive closure，Semantic RD Theory 才能直接应用
- NLA 的 activation verbalizer 的输出可以是「代码的语义摘要」——即归约到 irredundant core 后的描述
- 测量压缩保真度的唯一正确方法是**闭包等价性测试**，不是 BLEU/Perplexity
