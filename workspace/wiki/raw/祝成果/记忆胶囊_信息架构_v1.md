## 壹 · 记忆胶囊是什么

记忆胶囊不是"聊天记录"。不是"历史存档"。不是"数据缓存"。

记忆胶囊是祝对一段求知道路的一次**快照封装**——把"当时问了什么、查到了什么、做出了什么判断、留下了什么疑问"，压缩成一个可检索、可回溯、可感觉"新鲜度"的单元。

每一个胶囊，是一次决策的琥珀。

### 2.2 胶囊类型

| 类型 | 含义 | 何时创建 | 决策链路字段 |
|------|------|----------|-------------|
| `decision` | 用户做出了明确判断 | 长编/追问产生"结论" | 必填 |
| `question` | 用户提出了新问题 | 追问、祝号产生"新入口" | 空/仅首步 |
| `scan` | 用户浏览但没有停留 | daily briefing 自动扫描 | 不存在 |

### 2.3 元数据详细规格（JSON Schema 等效描述）

```

  "cold_after_days": 30,                // 30天后进冷存储
  "cold_compress_threshold": 90,        // 90天未访问→压缩摘要

  "关联规则": {
    "auto_link": {
      "策略": "同画像锚点自动关联",
      "条件": "两胶囊共享 ≥2个画像锚点",
      "示例": "胶囊A锚点[AI Agent, LangGraph] + 胶囊B锚点[AI Agent, 编排] → 建立弱关联"
    },
    "manual_link": {
      "策略": "用户或祝主动标注关联",

  }
```


### 3.2 路径详解

**路径A：Daily Briefing — "今日决策回溯"**

```
每日08:00推送 ─── 第三区块（不是第一条，不是最后一条）

区块标题: "📌 今日决策回溯"
副标题: "你昨天在3个方向上做了判断，其中1条今天可能变了"

内容格式:
  1. [新鲜] AI Agent框架选型 → 建议LangGraph MVP
     └─ 状态: 仍有效（7天内判断）

  2. [银窗] 论文日报选稿逻辑 → 确定宁缺毋滥
     └─ 状态: 5天前，可考虑复验前提是否仍在

     └─ 状态: 10天前，前提可能已变化 (?)

  ┌─ 时效色标 + 胶囊标题（14字以内）
  │  摘要一行（30字以内）
  │  有效/需复验/可能过时
  └─ [查看链路] 按钮
```

### 5.2 时间线AI判断逻辑

```
新鲜度不是"创建时间 - 现在"这么简单。

有三件事影响新鲜度：

1. 时间衰减（基础分，占60%）
   score_time = max(0, 1 - hours_elapsed / 168)
   刚创建=1.0，168小时=0

2. 前提稳定性（加分/减分，占30%）
   score_premise = 前提中还有几条valid / 总前提条数
   全部有效=1.0，全部失效=0

3. 画像活跃度（微调，占10%）
   score_interest = 当前画像锚点匹配数 / max_possible
   匹配越多→说明用户还在关注这个方向→胶囊更有价值

最终新鲜度 = 0.6×score_time + 0.3×score_premise + 0.1×score_interest

阈值：
  ≥0.7 → fresh
  0.3~0.7 → warm
  0.1~0.3 → grey
  <0.1 → cold
```

### 5.3 冷存储压缩策略

```
90天未访问的胶囊 → 触发冷存储压缩

压缩前:
```

## 捌 · 与现有系统的接口

```
记忆胶囊系统不独立存在——它骑在现有三个系统之上：

┌──────────────────────────────────────────────────────────┐
│                   记 忆 胶 囊 系 统                        │
│                                                           │
│  消费 ←────────── 写入 ──────────→ 生产                     │
│                                                           │
│  ┌──────────┐    ┌──────────┐    ┌──────────────────┐    │
│  │ Daily    │    │ 画像引擎  │    │ izu-pipeline     │    │
│  │ Briefing │←───│ (判断锚点 │←───│ (写长编时自动    │    │
│  │ (展示)   │    │  新鲜度)  │    │  创建胶囊)       │    │
│  └──────────┘    └──────────┘    └──────────────────┘    │
│       ↑               ↑                       ↑          │
│       │               │                       │          │
│  ┌────┴────┐    ┌────┴─────┐         ┌───────┴──────┐   │
│  │ 长编    │    │ 自动推送  │         │ 追问展开     │   │
│  │ (颜色标记)  │ (画像驱动) │         │ (决策链路)   │   │
│  └─────────┘    └──────────┘         └──────────────┘   │
└──────────────────────────────────────────────────────────┘

数据流：
  1. izu-pipeline 写完长编 → 摘要关键判断 → 创建记忆胶囊
  2. 记忆胶囊写入 _capsules/ 目录（与 _profiles/ 同级）
  3. 画像引擎在 update_profile 时，读取胶囊新鲜度
  4. Daily Briefing 在渲染时，调用胶囊列表
  5. 长编在 markdown->html 渲染时，注入颜色标记
  6. 自动推送在用户阅读时，由画像引擎实时触发
```
