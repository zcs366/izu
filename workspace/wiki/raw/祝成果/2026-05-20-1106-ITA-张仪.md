# 张仪 —— 最强攻击官

## 单点失败分析

### 最可能导致项目失败的一个点: CodeBERT的隐空间不够「语义对齐」

**为什么是它，而不是其他？**
- 整个ITA方案建立在「CodeBERT的隐空间能捕捉代码语义」这一假设上
- 如果CodeBERT的隐空间只是表面模式统计相关（即墨子的「前向推理可通过模式匹配解决」所暗示的），那么：
  - 实验0的baseline会很低（< 50% AST等价）
  - RFSQ量化会进一步放大噪声
  - Steering向量建立在对齐不良的隐空间上 → 迁移性为0
  - 整个技术栈会因为底层编码器不行而全部失效

**其他候选失败点的排除理由**:
- RFSQ的工程实现 → 已有现成库，风险可控
- EasySteer的兼容性 → 有repeng作为成熟fallback
- 预算不足 → $925远足
- 时间不够 → 关键路径10h可控

### 失败概率估算: ≈ 30%

### 降级方案

**A级降级（三天内止损）**: 换编码器
- 从CodeBERT换到GraphCodeBERT（有AST结构信息）
- 如果还不行 → 用CodeLlama-7B（生成式Code LLM，隐空间更丰富）
- 代价: 额外2天 + GraphCodeBERT推理需GPU

**B级降级（放弃压缩，只做steering）**:
- 放弃压缩部分，只做EasySteer的代码steering
- 这仍然是有效的——steering本身就提供了可控性
- 代价: 失去压缩率优势，但仍保有steering核心价值

**C级降级（重新定义问题）**:
- 如果所有编码器的隐空间都不够「语义对齐」 → 接受「steering向量需要在原始空间（不压缩）操作」的事实
- 研究问题缩窄为：「在代码生成中steering是否有效」
- 这仍然是一个有价值的研究方向

### 预警信号

实验0中CodeBERT的round-trip AST等价率 < 50% → 立即触发A级降级
实验2中steering成功率 < 40% → 立即触发B级降级
