# 子产 — 需求判断 + 研究方向

## 需求判断

### 该不该做？
**该做。** izu 当前处于 Agent 能力扩展的关键阶段。当前核心问题：
- ❌ Skill 是文件级的静态定义，缺乏运行时自适应
- ❌ 记忆是 token 级的临时缓存，没有长期结构化记忆
- ❌ 自进化靠手动技能定义，没有自动化 skill acquisition

### 为谁做？
- **直接受益者**：izu 自身——自进化 Agent 是 izu 核心差异点
- **间接受益者**：用户——更聪明的 Agent 意味着更好的研究辅助体验
- **不做会怎样？**：izu 停留在「工具调用 Agent」，永远无法成为「自进化知识伙伴」

### 不做会怎样？
3-6 个月内，如果其他 Agent 框架（MCP生态、Claude Code Skills）具备自进化能力而 izu 没有，izu 将被边缘化。不做 = 慢性淘汰。

## 研究方向定位

### 关键问题
1. **Skill 如何自动化获取和进化？** 当前 skill 是人工定义的，需要 AI 自动从使用中提取和优化
2. **记忆如何从 token 级升级为结构化长期记忆？** 当前只有对话级记忆
3. **MCP 与 Skill 的竞合关系？** MCP 提供工具，Skill 提供知识，两者如何协同？

### 核心假设
> Agent 的自进化能力 = 技能获取（Skill Acquisition） × 记忆组织（Memory Organization） × 反馈循环（Feedback Loop）

### 假设验证
- 这个三乘积模型是否完备？可能缺了「环境建模」（World Knowledge）这个维度
- 验证方法：调查现有自进化 Agent 框架（SAGE, SEAgent），看它们的架构组件是否覆盖了这三个维度

### 研究方向推荐
**短期（1-4周）**：Skill Retrieval Augmentation —— 从外部 skill 库检索+适配
**中期（1-2月）**：自进化循环 —— Agent 从历史对话中自动提取新 skill
**长期（3-6月）**：隐空间记忆 —— 将经验压缩到隐空间，实现高效检索和学习
