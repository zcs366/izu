# 鲁班 — 工程可行官

## 能不能做？

**能做。但需要选择正确的轮子。**

### 不要重复造的轮子
- **记忆存储**：Letta（原 MemGPT）是 MIT 开源的三层记忆系统，直接可复用
- **RAG 基础**：LangChain / LlamaIndex 社区版
- **进化回路**：EvolveMem 已开源（github.com/aiming-lab/SimpleMem），可以直接 clone 后裁剪

### 需要造的装备
1. **Failure Pattern Classifier**（2 周）
   - 功能：读取对话日志，分类"这次记住了" / "这次没记住" / "记住了但检索错了"
   - 方案：用 GPT-4o-mini 做分类（成本低），或训练一个 DistilBERT 分类器
   - 成本：$10-15 API 调用

2. **诊断→提案映射表**（1 周）
   - 功能：failure pattern → 检索参数调整方案
   - 方案：不用 LLM 实时生成，预定义 5-6 种 pattern 对应的调整策略
   - 成本：$0（纯工程工作量）

3. **回滚保护（Guard）**（1 周）
   - 功能：每次配置更新后，与上周的 recall F1 对比，下降则自动回滚
   - 方案：离线运行测试集（用 LoCoMo 子集测试），20-30 min 完成一次测试
   - 成本：$0

### 重复造轮子检查
| 组件 | 已有轮子 | 需要改进？ |
|------|---------|-----------|
| 三层记忆 | Letta / MemGPT | 需要简化为纯文本+向量（izu 场景不需要函数调用） |
| 进化回路 | EvolveMem | 需要精简掉 GPT-4o runtime，换成规则+小模型 |
| 诊断模块 | EvolveMem 有 diagnose，但太重 | 需要重写为 pattern-based classifier |
| 检索策略 | Mem0 多信号检索 | 可以抄思想，不用抄代码 |

### 工程可行性结论
✅ **可行**。总工程负载约 4 周（日均 1h = 20 工时）。核心假设是「EvolveMem 的进阶可以在不依赖 GPT-4o 的情况下实现」。如果此假设不成立（需要 GPT-4o 级模型才有诊断质量），则需重新评估。

### 关键工程决策
- **选择 Letta 还是 SimpleMem？** → SimpleMem。因为 SimpleMem 更轻量，且是 EvolveMem 的基础版本，平滑升级
- **向量库选型** → ChromaDB（本地运行，零成本）。如果 BEAM 规模不够再换 Qdrant
