# 张仪

## 单点失败分析

### 最可能导致项目失败的一个点

**Online Designer 的收敛性问题。**

### 问题展开

MemSkill 的成功依赖于一个**受控的 offline 训练循环**：
1. 收集大量交互日志
2. 人工/自动标注 hard cases
3. designer 基于 hard cases 提炼新 skill / 修改旧 skill
4. 验证修改后的 skill bank 在所有历史数据上的效果

在 zu 的在线场景中，这个循环被打破了：

**场景 1：信号稀疏**
Agent 一天可能只有 3-5 次交互，其中满意/不满意的记忆质量信号极少。online designer 可能在一个月内都收集不到足够多的「失败 case」来触发有意义的 skill 进化。

**场景 2：灾难性遗忘**
假设第 3 次交互触发了 skill 修改——设计的 online designer 用 LoRA 微调了 skill bank。如果第 4 次交互的场景与第 3 次完全不同，修改后的 skill 可能破坏之前第 1-2 次交互学到的模式。在线学习的经典问题。

**场景 3：评估信号不可靠**
izu 没有「ground truth 记忆质量」——Agent 的自我评估（"这个记忆好吗？"）完全基于 LLM 的 self-judgment。如果 LLM 的自我评估不准（约 70% 准确率），online designer 会基于错误信号做出错误修改。

### 致命公式

```
低交互频率 × 不可靠自评信号 × 灾难性遗忘风险 = online skill 进化可能不收敛
```

这个失败路径是无法通过「增加数据」或「调参」来解决的——因为根因是数据生成速率太慢（日均 3-5 次交互）导致在线学习信号不足。

---

## 降级方案

### 降级路径 A（推荐）：Hybrid 模式

不追求纯在线学习，而是采用 **offline 初始化 + 在线微调** 的混合模式：

1. **Offline 初始化（第 1-2 周）**
   - 用 MemSkill 源码在公开数据（LoCoMo/LongMemEval）上训练一个通用 skill bank
   - 这个 skill bank 对通用对话场景已经足够好（论文已验证）

2. **在线微调（第 3 周起）**
   - 只在两种情况下触发 online designer：
     a. 连续 3 次 Agent 自评"记忆质量差"
     b. 用户明确反馈"你忘了"
   - 触发后不做 LoRA 全量微调，只做 skill 权重调整（减少参数变化量）

3. **安全机制**
   - 每次修改前备份 skill bank
   - 如果修改后评估指标下降 > 5%，自动回滚
   - 设置「学习率」——每次最多修改 1 条 skill，每周最多触发 1 次

### 降级路径 B：放弃在线学习，专注 offline 迁移

如果路径 A 的收敛性仍然存疑，放弃 online designer 创新：
- 直接复用 MemSkill 的离线训练框架
- 每 2 周收集一批 zu 的交互日志
- 集中一次 offline 训练新 skill bank
- 对 zu 来说，2 周更新一次 skill bank 已经足够好

### 降级路径 C：降低目标

如果上述都不可行，回到更简单的方向：
- 不用 MemSkill，用更轻量的方案——基于规则的记忆操作 + 加权选择
- 初始 skill 手工设计，不进化
- 只做 3 件事：保留、摘要、遗忘——用三个固定规则

### 张仪判结

**最大致命点**：Online skill 进化在低交互频率场景下可能不收敛。

**兜底策略**：采用 Hybrid 模式（降级路径 A），offline 初始化做保底，online 微调做探索。每次修改必须可回滚。如果 2 周后 skill 质量无明显提升，降级到路径 B（纯 offline + 定期更新）。
