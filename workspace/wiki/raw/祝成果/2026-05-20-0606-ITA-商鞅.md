# 商鞅 — 最小可行实验设计

## 核心问题
**代码语义在隐空间中是否线性可分？线性 steering 能否有效控制代码行为？**

## 实验设计（20工时以内）

### 实验1：代码行为线性探针（8工时）
- **目标**：验证代码功能等价类在隐空间中线性可分的程度
- **数据**：CodeXGLUE 代码搜索子集 + 自构建功能等价对（排序算法、搜索算法、数据结构操作各20对）
- **方法**：
  1. 用 CodeBERT 或 starencoder 提取代码嵌入
  2. 训练线性探针（logistic regression）对功能类别分类
  3. 报告准确率、混淆矩阵、PCA可视化
- **成功标准**：线性探针准确率 > 85% 说明代码语义在隐空间中具有线性结构；< 60% 说明需要非线性方法
- **工具**：CodeBERT（huggingface）、scikit-learn 线性分类器

### 实验2：PCA 代码语言 steering 原型（8工时）
- **目标**：复现 Goncharov et al. (2025) 的核心结果，验证其对代码生成的影响
- **数据**：Python ↔ JavaScript 翻译对 50 组 + Java ↔ Python 翻译对 50 组
- **方法**：
  1. 用 Llama-3.2 或 Qwen2.5 提取平行翻译对的隐表示
  2. PCA 计算语言方向
  3. 在代码续写任务中施加 steering（α 从 0.5 到 2.0 扫描）
  4. 测量语言准确率 + 功能保真度
- **成功标准**：语言准确率 > 90% + 功能保真度 > 80%

### 实验3：FSQ 对代码嵌入的 round-trip 测试（4工时）
- **目标**：验证FSQ量化对代码语义的保真度
- **方法**：
  1. 用 CodeBERT 提取代码嵌入 z
  2. 用 FSQ 量化到不同 bit 率（2-8 bits/维度）
  3. 从量化后的嵌入重构代码（用解码器或最近邻搜索）
  4. 测量重构代码的功能等价比例
- **成功标准**：8 bits/维度下功能保真度 > 90%

## 总工时分配

| 实验 | 工时 | 优先级 |
|------|------|--------|
| 实验1：线性探针 | 8h | P0（必须先做） |
| 实验2：PCA steering | 8h | P0 |
| 实验3：FSQ round-trip | 4h | P1（依赖实验1结果） |
| **合计** | **20h** | |

## 失败判断标准

| 结果 | 结论 | 行动 |
|------|------|------|
| 线性探针 < 60% | 代码语义非线性 | 放弃线性steering，改非线性方法 |
| 线性探针 > 85% + steering > 90% | 理论+工程双可行 | 推进到产品原型 |
| 线性探针 > 85% + steering < 70% | 理论可行但工程难 | 需要更好的方向发现方法（非PCA） |
| FSQ round-trip < 80% | 量化损失不可接受 | 考虑 LFQ 或 soft quantization |
