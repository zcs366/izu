## 一、我们在做什么

想象这样一个场景：一个AI模型遇到一道难题。它先做一遍——错了。但它不等人纠正它，而是自己重新审视自己的解题过程，发现"哦，我第二步漏了验算"，于是改进思路再做一遍。这次对了。

这不是科幻。我们已经在廉价模型上跑通了。

核心命题很简单：**不依赖更大的模型、更贵的训练——只靠Agent系统自身的反思和实验，能不能持续变强？**

答案是：能。

下面是我们实打实跑出来的两个实验。

## 二、TRT：递归思考——让模型自己和自己下棋

### 2.1 算法

TRT（Test-time Recursive Thinking）的核心循环只有四步：

```
第N轮：
  1. 生成：基于"已知教训"+"探索策略"，生成3个候选解答
  2. 自排序：模型自己当裁判，选出最佳解答
  3. 蒸馏：对比最佳vs其他，提取"这次学会了什么"
  4. 策略更新：把学到的教训转化为下一轮的探索策略
```

1-2-3-4，循环往复。每一轮，模型都带着上一轮学到的教训重新出发。

**关键：** 整个过程不需要外部验证器、不需要ground truth、不需要训练。零训练，纯上下文驱动。

### 2.2 实验

我们在DeepSeek（deepseek-chat）上跑了4个难度级别的测试：

| 难度 | 题目 | TRT答案 | 标准答案 | 结果 |
|------|------|---------|---------|------|
| 简单 | 60km/h×2h + 80km/h×1h | 200公里 | 200公里 | ✅ |
| 中等 | 20%折扣后240元，原价？ | 300元 | 300元 | ✅ |
| 困难 | 三连续正整数平方和=194 | 7, 8, 9 | 7, 8, 9 | ✅ |
| **AIME** | **中国剩余定理 n<500** | **157, 472** | **157, 472** | ✅ |

4轮递归，4级难度，全部做对。AIME级题目（三重同余方程）也正确收敛。

**成本：** 单题约¥0.05（$0.007），模型deepseek-chat。

### 2.3 学到的教训（来自TRT的知识蒸馏）

在实际跑的过程中，模型每一轮都在学习。以下是从AIME题目的4轮递归中蒸馏出的真实教训：

> - "分步计算并验证，检查单位与结果合理性"
> - "最佳答案通过分步计算和常识检验确保过程清晰可靠"
> - "下次遇到分段问题，应分步计算并验证中间结果"

这些教训不是人类写进去的——是模型自己从对比分析中提取的。

### 2.4 工程实践：答案提取的坑

说实话，TRT最难的环节不是推理——是**答案提取**。

模型有时候输出"好的，我们将按..."这样的说明文字，而不是干净的数字。我们试了5个版本才把提取准确率从约70%推到100%：

- v0.1：基础正则，噪音多
- v0.2：加三层fallback，约75%
- v0.3：鲁班修复，LaTeX清理
- v0.4：过滤太激进，降到69%
- v0.5：换FINAL_ANSWER格式，在TRT多rollout场景下失效
- **v0.6**：回到鲁班三层fallback + 修复单数字过滤 + 次佳fallback → **100%干净率**

教训：让模型输出就是比后处理解析靠谱。但在无法保证格式的场景下，鲁棒提取需要多次迭代。

## 三、LSE：代码辅助进化——让prompt自己变聪明

### 3.1 问题

TRT解决的是"同一道题，递归思考变强"。LSE想解决更难的问题：**"不同的题，prompt能不能自己进化？"**

最初的尝试是：让模型分析自己的错误，自己改写prompt。结果——不行。模型能解AIME题，但无法可靠地回答"我的prompt哪里不好，应该怎么改"。这是**元认知瓶颈**。

### 3.2 突破：代码做决策，模型做生成

我们的解决方案是匠石原则的一次实战应用：

```
代码层（不用模型）：
  1. 分析每道题的错误类型（FORMAT/COMPUTE/OTHER）
  2. 根据错误分布选择修复模板
  3. 决定进化方向

模型层：
  1. 根据选定的修复方向，生成具体的prompt文本
```

代码决定"改什么"，模型负责"怎么改"。

### 3.3 实验

初始Skill是一个刻意弱化的prompt："请解答数学题。用 [答案: X] 格式输出。"

5轮进化后的结果：

```
基线:  训练集50% | 测试集0%
第3轮: 测试集50% (+50pp) ← 格式修复生效
第5轮: 测试集75% (+25pp) ← 二次修复
最终:  测试集75% (+75pp)
```

**诊断日志（代码层产出，不使用模型）**：
- 第1轮：检测到2个FORMAT错误 → 触发"强化格式"模板 → 生成格式修复Skill
- 第3轮：修复生效，训练集涨到75%
- 第5轮：进一步修复，测试集涨到75%

## 四、为什么这很重要

### 4.1 与前沿研究的对比

微软在2026年2月发表了TRT论文（arXiv 2602.03094），在闭源模型上展示了类似效果。我们是独立复现的——在开源廉价模型上。

LSE论文（arXiv 2603.18620）使用RL训练了专门的进化策略模型。我们走不通RL路线（没有GPU集群），但用**代码辅助**的方式达到了类似的进化效果。

### 4.2 方法论意义

这两个实验共同说明了一件事：

> **Agent自我迭代不需要更大的模型。它需要更好的设计。**

TRT的递归思考、代码辅助进化的决策分离——这些不是"模型更强了"，是"结构更聪明了"。

### 4.3 "低成本AGI"的可能性

这个方向的核心吸引力在于：如果Agent能自己改进自己，那么：

- 不需要等GPT-6
- 不需要万卡集群
- 只需要好的Agent架构 + 自我迭代机制

你今天用的模型可能不够强——但如果它能学会"怎么让自己变强"，天花板就不同了。
