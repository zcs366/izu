# 韩信（技术远景官）— izu Round 1

## 技术远景：izu 3-6个月后长什么样？

### 基于子产判断的技术路线

**当前状态**: izu = 纯对话Agent，无记忆，无技能积累，每次会话独立
**3个月目标**: izu = 带记忆的助理Agent，能记住用户偏好和关键决策
**6个月目标**: izu = 自进化Agent，能自动从对话中提取技能并复用

### 技术阶梯

```
Month 1-2: 记忆层落地
├── 本地向量数据库 (Chroma/LanceDB)
├── 短期记忆: 对话上下文摘要
└── 长期记忆: 关键决策/用户偏好持久化

Month 3-4: 技能框架
├── 从repeated patterns自动提取"技能草稿"
├── 技能注册: 结构化存储 (名称+触发条件+执行步骤)
└── 技能召回: 语义匹配触发

Month 5-6: 自进化闭环
├── FIX模式: 手动优化技能
├── DERIVED模式: 自动泛化技能
└── CAPTURED模式: 自动从用户行为学习
```

### 终局画像

```
izu 6个月后 = 一个能在对话中不断积累经验的Agent系统：
  - 对重复性工作，每次比上次更快更好
  - 记住用户的编码习惯、决策偏好、常用工具
  - 在新任务中可以自动检索和适配已有技能
  - 完全自托管，无外部API依赖
```

### 需要纳入的新技术路线

1. **OpenSpace 的核心思想**: 技能作为一等公民，自动提取+注册+复用
   - 不需要完整复现OpenSpace（它比较重），提取其核心抽象
2. **Interlat 的潜前缀**: 如果izu两个Agent之间需要协作（如research_agent + code_agent），潜空间通信可以大幅降低token开销
3. **CoLaR 的动态压缩**: 对长对话历史的压缩检索，而非简单截断

### 技术远景判断

✅ **可行且值得投入**。OpenSpace已证明自进化架构的可行性和效果（46% token效率提升）。izu走轻量级自托管路线，方向正确，但需要：
- 在"能力边界"和"自托管约束"之间找到平衡
- 优先确保记忆层的基础设施（这是所有上层建筑的前提）
