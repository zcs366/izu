# 鲁班 — 工程可行官（核战队终审）

## 工程协调意见

### 两轨道互相矛盾吗？
**在字面意义上不矛盾，但在工程优先级上存在隐含冲突**。

ITA轨道：集中资源做Phase A（隐空间分析），如果成功就做FSQ压缩。
izu轨道：等ITA结果，同时先做阶段1+2（分类器+结构化存储）。

**隐含冲突**：
- 张成市日均1h的情况下，如果ITA Phase A在5月24日成功，那么5月25日起ITA Phase B和izu阶段1会争抢时间
- 1h/天只能支持一个方向全力推进

### 推进顺序建议

```
Week 1 (5月20-24日): ITA Phase A ONLY
  - izu: 0h（只做Mem0调研，不写代码）
  - ITA: 5h（测试集+CodeBERT推理+分离度分析）
  理由：Phase A决定两条路线走向，必须优先

Week 2-3 (5月25日-6月1日): 分情景
  情景A: ITA Phase A成功（分离度≥2.0）
    - ITA Phase B: 2.5h/周
    - izu 阶段1+2: 2.5h/周
    - 平分时间

  情景B: ITA Phase A弱信号（1.0-2.0）
    - ITA Phase B缩减为纯调研: 1h/周
    - izu 阶段1+2全力: 4h/周
    - 方向逐渐偏向izu

  情景C: ITA Phase A失败（<1.0）
    - 中止ITA压缩方向
    - izu 降级A（规则压缩）+ 降级B（Mem0集成）: 5h/周
```

### 优先级矩阵
| 方向 | 现在做 | 产出价值 | 风险 |
|------|--------|---------|------|
| ITA Phase A | ✅ 立即 | 决定方向 | 低（20h以内） |
| ITA Phase B | ⏳等结果 | 中（代码压缩） | 高（依赖A） |
| izu 阶段1 | ⏳等结果 | 高（记忆分类） | 低（独立） |
| izu 阶段2 | ⏳等结果 | 高（结构化存储） | 低（独立） |
| izu 阶段3 | ⏳等ITA | 中（语义压缩适配） | 很高（双重依赖） |

### 最终结论
**先做ITA Phase A，同时izu调研Mem0但不写代码。Phase A结果出来后再分路。这是最优工程决策。**
