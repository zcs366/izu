# 萧何·执行路径报告（izu轨道）

## 资源盘点

| 资源项 | 状态 | 备注 |
|--------|------|------|
| 人力 | 张成市日均1h | 核心约束 |
| 基建 | WSL + conda | izu已有运行环境 |
| 开源框架 | OpenSpace (HKUDS) | 完整开源，MIT协议 |
| 技能存储 | izu已有memory | 可扩展为skill存储 |
| Python版本 | izu运行在3.10+ | 与OpenSpace兼容 |

## 阶段拆解（以日均1h = 12周完成）

### 阶段0：OpenSpace调研与验证（1周，5h）

- 阅读OpenSpace文档与代码 (2h)
- 本地搭建OpenSpace demo (1h)
- 验证OpenSpace能否处理izu的日志格式 (1h)
- 决定：用OpenSpace还是自建 (1h)

### 阶段1：技能发现链路打通（2-3周，10h）

- 技能适配层编码 (2h)
- 将izu的交互日志格式化为OpenSpace输入 (2h)
- 技能存储对接izu memory (2h)
- 测试闭环：izu交互 → 技能发现 → 技能存储 (4h)

### 阶段2：技能运行时（4-5周，10h）

- 技能匹配器编码 (3h)
- 技能执行器编码（复用izu tool call机制）(2h)
- 技能选择策略（多个匹配时怎么选）(2h)
- 端到端测试：izu遇到情况 → 匹配技能 → 执行技能 (3h)

### 阶段3：技能进化（6-8周，8h）

- 技能失败检测 (2h)
- 技能自动微调（基于失败经验的模式修正）(3h)
- 相似技能合并 (2h)
- 冗余技能清理 (1h)

### 阶段4：稳定化与观察（9-12周，8h）

- 长期运行测试 (4h，分散)
- 技能库成长监控 (1h)
- 性能优化 (3h)

## 关键路径
```
阶段0(1w) → 阶段1(2-3w) → 阶段2(4-5w) → 阶段3(6-8w) → 阶段4(9-12w)
                                                  ↓
                                         并行准备ITA实验(CP1)
```

**最关键的里程碑**：阶段1结束 = 技能发现是否真的能从izu的日志中工作。
如果阶段1失败，整个路线需要重新评估。
