# 鲁班 —— 工程可行官

## 能不能做？

**能。** 方案A（Mem0集成 + 渐进式记忆）的实现成本极低。

## 有没有重复造轮子？

**没有。** Mem0是将近生产级的框架（20种向量数据库、21个Agent框架集成、92.5/94.4基准分）。用Mem0作为izu的记忆层不会造成重复建设。

但需要区分清楚：Mem0是一个**记忆存储/检索服务**，不是**Agent记忆系统**。izu仍然需要自己实现：
- 什么时候触发「记住」？
- 什么时候触发「回忆」？
- 如何把检索到的记忆融合到回答中？

## 造什么装备？

### Phase 1: Mem0集成（1天）

```
izu对话 → [Mem0 add()] → 记忆存储
izu对话 + 上下文 → [Mem0 search() + memory injection] → 回答
```

**实现要点**:
- pip install mem0ai
- 在izu的对话循环中插入memorize/remember钩子
- 配置：使用Qdrant（本地轻量向量数据库），也可用内置SQLite
- 成本：Mem0的API调用在单用户场景下 ≈ $0/月（全本地）

### Phase 2: 实体链接（2-3天）

在Mem0的entity linking上叠加：
```
对话 → 实体抽取(LLM调用) → Mem0 search(entity) → 融合式检索
```

**关键组件**: 用izu自身的LLM做实体抽取，不需要额外模型

### 工程风险

| 风险 | 级别 | 缓解 |
|------|------|------|
| Mem0集成侵入izu现有架构 | 低 | Mem0的API设计为add/search，与任何架构兼容 |
| 实体抽取的LLM成本 | 低 | 单用户每天几十次调用 |
| 记忆膨胀 | 中 | 需设置TTL或重要性衰减机制 |
| 跨会话ID管理 | 中 | 需持久化session ID到本地文件或云端 |

### 硬件要求

无需GPU。全部在CPU上运行（Memo用FAISS/Qdrant，实体抽取用izu的底层LLM API）。
