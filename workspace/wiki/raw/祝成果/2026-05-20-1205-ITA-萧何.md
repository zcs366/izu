# 萧何 — 资源协调官

## 资源盘点

### 可用资源
- **人力**：张成市日均 1h（≈ 30 工时/月）
- **预算**：$925（总额，含所有轨道）
- **GPU**：无独立 GPU，需用云服务（Lambda / RunPod / 或 GPT API 替代）

### 本轨道成本估算

| 项目 | 工时 | 费用 | 备注 |
|------|------|------|------|
| Step 1: core 提取脚本开发 | 4h | $0 | 纯 Python 本地运行 |
| Step 1: 在 MBPP 上跑提取 | 0.5h | $0 | 500个函数，本地几秒 |
| Step 2A: GPT-4o-mini 恢复测试 | 2h | $5 | 500次调用 × $0.01/次 |
| Step 2B: CodeBERT 掩码预测（可选） | 4h | $10 | Lambda GPU $0.5/h × 4h + 存储 |
| Step 3: 压缩率计算 | 2h | $0 | 本地计算 |
| 分析报告 + 决策 | 2.5h | $0 | |
| **合计** | **15h / 4 工作周** | **$15** | 预算余量：$910 |

### 关键路径
```
Week 1:  开发 core 提取工具 + MBPP 采样测试（5h）
Week 2:  GPT-4o-mini 恢复实验（2h）+ 初步结果分析（1h）
Week 3:  CodeBERT 掩码预测（4h，可选，视 Week 2 结果）
Week 4:  综合分析 + 报告 + 决策是否推进完整版（3h）
```

### 瓶颈分析
- **最长时间瓶颈**：GPT-4o-mini API 调用（500次，受速率限制约 2h 完成）
- **最高风险点**：MBPP 函数过短，core 提取不出有效压缩空间
- **去风险策略**：如果 MBPP 不行，换 HumanEval（更长函数，但仅 164 题——需要数据增强）

### 资源建议
1. **ITA 轨道占月预算的 1.6%**（$15/$925）——极其节省，应该先做
2. 不要并行推进 ITA 和 izu。先做 ITA 的 Step 1-2（核心验证），再做 izu
3. 如果 ITA Step 1 发现 core ≈ 原代码（即代码几乎无冗余），应**立即终止 ITA 轨道**，将资源集中到 izu
