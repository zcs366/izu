# 韩信

## 技术远景：3-6 个月后 izu 长什么样？

### 终局画像（3 个月）
```
zu User ←→ Agent
  ↕ 记忆层（MemSkill 在线版）
  ↕ skill bank（自动进化，跨模型泛化）
  ↕ 轻量控制器（动态选择最佳 skill 组合）
```

### 技术阶梯（按优先级排列）

**阶梯 1（第 1-2 周）：MemSkill 离线复现**
- 在 zu 的 Agent 框架上部署 MemSkill（现有开源代码）
- 目标：验证 skill-conditioned memory 在 zu 场景的有效性
- 关键指标：LongMemEval 风格的长对话记忆召回率

**阶梯 2（第 3-4 周）：在线化改造**
- 将 MemSkill 的 offline designer 替换为在线主动学习
- 核心方案：当 Agent 自我评估发现记忆不满意的 case 时，触发本地 skill 微调
- 工具：LoRA + 轻量 LLM（如 Qwen2.5-7B）
- 风险：在线学习的稳定性需要监控（灾难性遗忘）

**阶梯 3（第 5-8 周）：跨 Agent skill 迁移**
- 多个 zu 实例之间的 skill bank 共享
- 核心问题：不同用户的 zu 是否共享 skill 的底层模式？
- 猜想：是的——记忆操作（如何 summarization、如何提取实体关系）是跨用户通用的
- 验证：在 3 个不同场景下训练 skill bank，交叉验证

**阶梯 4（第 9-12 周）：Skill→代码语义映射**
- 与 ITA 交叉：将 skill（可执行规则）编码到隐空间
- 目标：Skill 的跨用户去重、自动压缩、语义搜索
- 成果：Agent 可以通过隐空间相似度推荐相关 skill

### 对 zu 现有架构的影响

| 现有组件 | 变化 | 影响 |
|---------|------|------|
| MemoryBank 风格记忆 | 被 MemSkill 替换 | 更好，但需迁移现有记忆 |
| 固定记忆操作 | → 动态 skill 组合 | 更灵活但不确定 |
| 无跨 Agent 共享 | → skill bank 可共享 | 需隐私保护设计 |

### 风险提示
1. 在线进化的收敛性未经验证（MemSkill 是 offline 训练的）
2. 日均 1h 的约束下，12 周的技术阶梯需要压缩到关键路径——不能都做
3. 跨模型泛化（MemSkill 验证了 LLaMA→Qwen）能否跨任务泛化？需要实验验证

### 韩信判结
最值得做的 3 个月目标：**izu 的 MemSkill 在线化适配 + 跨 Agent skill 共享实验**。这两个方向补上了 MemSkill 论文的空白，同时不依赖 ITA 的进度。
