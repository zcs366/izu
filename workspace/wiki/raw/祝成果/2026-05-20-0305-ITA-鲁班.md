# 鲁班 — 工程可行官

## 在理论约束内的工程可行性评估

### 理论约束回顾（墨子）
- 隐空间维度 d ≥ 64
- FSQ 在 d=64, L=16 时量化 MSE ≤ 1.04（~1%相对误差）
- 理想压缩率 11x 需接近最优编码
- FSQ 在 3-5 bits/dim 下可达 6-8x

### 技术方案

#### 方案 A：纯 FSQ 路线（推荐优先试）
- **编码器**：CodeBERT base → 768维 → 投影到 128维
- **量化器**：FSQ, 每维 levels=16 (4 bits), 总码本大小 16^128（稀疏访问）
- **解码器**：轻量 MLP (128→768) + CodeBERT decoder 或 小 Transformer
- **预估压缩率**：128×4=512 bits 编码一个函数（假设平均 100 tokens × 4 bytes = 3200 bits），压缩率 ≈ 6.25x
- **优点**：实现简单，一周可出原型
- **风险**：6x 不满足 10x 目标，但墨子已确认 10x 理论上可行——需要残差量化

#### 方案 B：残差 FSQ 路线（目标 10x）
- 在 FSQ 基础上增加残差编码层
- 第一层 FSQ 粗量化（d=64, L=8, 3 bits/dim = 192 bits）
- 第二层残差精化（d=64, L=4, 2 bits/dim = 128 bits）
- 总码率 320 bits，对 100-token 函数（3200 bits）→ 10x
- **优点**：达到 10x 目标
- **风险**：残差层的训练稳定性未知

#### 工具选型
| 组件 | 选型 | 理由 |
|---|---|---|
| 编码器 | CodeBERT / CodeT5+ | 开源，社区成熟 |
| 量化 | FSQ (自实现，100行) | 比 VQ 简单，无 codeword collapse |
| 解码器 | 小 Transformer (2层) | 够用，训练快 |
| 训练框架 | PyTorch + HuggingFace | 张成市熟悉 |
| 评估 | HumanEval + 自定义 round-trip | 标准 benchmark |

### 工程约束检查

| 约束项 | 状态 | 备注 |
|---|---|---|
| 理论下界允许 | ✅ | 10x 理论可行 |
| GPU 资源 | ✅ | T4 够用，训练 < 2天 |
| 代码量 | ✅ | < 2000 行 Python |
| 现有工具 | ✅ | 全部开源 |
| 团队技能 | ✅ | 张成市有 Transformer 经验 |
| 时间窗口 | ⚠️ | 2-3周出 First Light |

### 结论
**工程可行。** 推荐先走方案 A（纯 FSQ，6x）拿到基线，2 周出结果；如果保真度达标，再升级到方案 B（残差 FSQ，10x）。没有不可逾越的工程障碍。
