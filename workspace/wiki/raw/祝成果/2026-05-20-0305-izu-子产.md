# 子产 — 需求判断官 / 研究方向官

## 第一部分：需求判断

### 该不该做？——做。
izu（一个持续进化的 AI 知识陪伴/自进化 Agent）在推出后很快会面临两个核心痛点：
1. **记忆衰退**：session 之间的知识无法自然积累，每次对话从零开始
2. **技能固化**：Agents 不会自动学新技能，只能靠手动配置

如果 izu 不做长期记忆和自进化，它永远不会超越「增强版 ChatGPT」的定位。

### 为谁做？
- **直接用户**：张成市（核心测试者，日均使用 30+ 次）
- **次级用户**：DevRel 团队试用者（预计 50-100 人）
- **终极用户**：所有需要「越用越懂我」的 Agent 用户

### 不做会怎样？
1. izu 永远是一阶工具，无法成为二阶智能体
2. 与 Mem0、MemGPT 等技术差距只会拉大
3. 到 2026Q4 会被淘汰

## 第二部分：研究方向

### 关键问题
不是「要不要记忆」，而是 **「什么记忆结构能同时满足(1)低成本、(2)跨session、(3)自进化」**。

### 核心假设
- **假设1**：压缩的隐空间表示比原始文本更适合长期记忆存储（ITA 方向与 izu 的交叉点）
- **假设2**：Agent 的行为模式可以通过「技能向量」编码，而非存储每个例子的完整上下文
- **假设3**：自进化 = 记忆回放 + 技能抽象 + 价值选择的循环

### 研究方向是否正确？——方向对，节奏要调。
1. **短期（0-3个月）**：关注 Agent 记忆系统的基本架构——RAG 与记忆池的混合设计
2. **中期（3-6个月）**：关注技能习得——从记忆抽象出可复用技能（受 ITA 代码压缩启发）
3. **长期（6-12个月）**：关注自进化循环——技能发现→习得→选择→改进

### 情报交叉点（与ITA重叠）
ITA 的代码语义压缩研究对 izu 有直接启发：如果代码的「语义」可以被压缩进隐空间，那么 Agent 的「行为模式」也可以。两者共享同一个技术栈——FSQ/量化/隐空间操控。**izu 的学习进度不应领先于 ITA 的实验验证。**
