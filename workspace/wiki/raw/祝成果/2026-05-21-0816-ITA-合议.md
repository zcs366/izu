# Phase 1A — ITA 6轮合议（2026-05-21 08:16）

## Round 0 / 惠施：概念澄清

**核心定义**：信任传播（被动无边界）≠ 信任转移（零和迁移）≠ 信任委托（主动有边界可审计）。MCP的实际安全问题在于系统按"委托"模型设计却实际运行在"传播"模型下。

**"工具即通道"安全悖论**：接口契约保护数据格式而非语义安全。格式正确的恶意内容比格式错误的良性内容更危险。

**三种攻击面精确区分**：
- 内容注入（数据层/运行时）
- 指令注入（配置层/加载时）
- 工具投毒（基础设施层/供应链）

**"零信任工具交互"三层含义**：输入侧零信任、输出侧零信任、上下文零信任。

**最危险的五个等号**：接口正确=语义安全、认证通过=内容可信、加密传输=安全使用、信任传播=信任委托、工具隔离=沙箱执行。

## Round 1 / 墨子：形式化验证

设计了7状态安全状态机（IDLE → INPUT_SANITIZING → SANDBOXED_EXEC → OUTPUT_INSPECTING → TRUSTED_DELIVERY / QUARANTINED / REVOKED）。

**核心安全规则（TLA+风格）**：
1. 输入消毒不变量：内容不含指令标记
2. 能力域守卫：操作不超出声明域，不触碰特权操作
3. 输出隔离不变量：Agent影响在允许集合内
4. 信任单调递减：建立慢，毁灭快
5. 交互原子性：一次性不被并发污染
6. 投毒检测公理（不可证明的信任锚）

**可证明的性质**：输入注入阻断、输出语义隔离、信任非对称传播、交互无竞态。
**原则上不可证明**：语义意图完备性（Rice定理）、工具投毒零漏报、上下文操纵的语义等价攻击。

## Round 2 / 商鞅：规则治理

**4级信任模型**：L0 unverified → L1 partially_verified → L2 verified → L3 tainted（不可逆）

**3条治理规则**：
- G1（能力声明归一化）：上提制，变更需注册中心审批
- G2（变更传播链）：未确认变更自动降级
- G3（最小权限三原则）：时间粒度/操作粒度/数据粒度

**4个实验方案**：能力膨胀攻击、信任衰减链攻击、能力降级重用攻击、最小权限合规性测试。
**7个评估指标**：CIR≥99%, TDCR=100%, CCL≤5s, OBDR≥99.5%, FCR≥95%, FPR≤0.1%, RRT≥100/h。

## Round 3 / 鲁班：工程可行

**MRSF（MCP Runtime Semantic Firewall）六模块架构**：
1. 请求预处理器
2. CIDE：三级递进检测（正则~5ms + 语义~40ms + 上下文一致性~30ms）
3. CAG：能力域守卫（行为画像+声明比对）
4. TLM：信任等级管理器（滑动窗口积分制）
5. 响应后处理器
6. 审计日志系统（异步写入）

**性能预算**：同步部分~108ms（目标）/ 155ms（上限），满足<200ms硬约束。
**部署路径**：Phase 1（观察模式，2周）→ Phase 2（学习模式）→ Phase 3（激活拦截）→ Phase 4（全量，8周）。

## Round 4 / 萧何：资源路径

**成本估算**：小型（$1,200/月推理）+ 中型（$8,500/月）+ 大型（$55,000/月）。
**EU合规增量**：8-12周额外工作量，$40,000-$80,000一次性。
**7大风险**：L2/L3误判、信任养号、延迟超限、日志泄露、LLM依赖、协议演进、对抗样本。
**10周路线图**：Week 1-2基础→3-4智能→5-6深度→7-8可视→9-10硬化。

## Round 5 / 张仪：最强攻击

**三发重炮**：
1. **范畴错误**：把AI安全问题（prompt injection）套进传统网络安全形式化框架。"工具即通道"比喻诱导所有人去建"通道安全模型"，但真实风险在"通道两端的AI行为不可预测性"。
2. **延迟不可达**：CIDE语义检测层用LLM推理就不止108ms。六模块创造了6个"不是我的问题"的借口。
3. **信任体系空中楼阁**：信任等级谁评？无数据冷启动。G1/G2/G3用户在Host侧可绕过。

**替代方案**：放弃形式化→tool output sanitization + capability-based ACL + 本地信任记忆。放弃六模块→单层tool output firewall（规则引擎<10ms + LLM异步）。预算转向红队测试。

**底线**：值得做方向，不值得做方案。砍80%方案，保留20%核心防御。
