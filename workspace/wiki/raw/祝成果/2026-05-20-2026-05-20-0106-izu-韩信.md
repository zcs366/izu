# 韩信 — 技术远景官

## 对 izu 3-6 个月方向的影响

### 当前 izu 架构画像（2026-05）
- 对话级记忆（当前 session 的 messages）
- 无跨会话持久记忆
- 无 skill 自动提取
- 无用户画像渐进构建

### 3 个月后（2026-08）izv 应该长什么样？
```
izu v0.5 记忆架构:
├── 短期记忆: 当前对话 (in-context, 8K tokens)
├── 中期记忆: 最近 3 次会话摘要 (向量检索, 1K tokens/session)
├── 长期记忆: 用户画像 (结构化: 偏好/知识/经历图谱)
│   ├── 实体节点: 用户提及的人物/项目/技术/地点
│   └── 关系边: 评价/时间/情感极性
└── 遗忘调度器: 基于艾宾浩斯曲线 + 用户反馈频率
```

### 6 个月后（2026-11）izu 的终局画像
```
izu v1.0 自进化 Agent:
├── 记忆层 (同 v0.5，但自动压缩)
├── Skill 层: 从交互历史自动提取可复用 skill 模板
│   ├── pattern: "用户每周三问XX类问题 → 预生成回答模板"
│   └── action: "当检测到用户开始输入代码 → 主动打开分析模式"
├── 知识陪伴层:
│   ├── 主动追问: "你上周提到的那个项目进展如何？"
│   └── 情感感知: 根据历史交互判断用户情绪状态
```

### 必须纳入的新技术路线
1. **Mem0 的 hierarchical extraction** — 单遍层次化记忆提取，减少 token 消耗。izu 的日均 1h 时间约束使得 token 效率至关重要。
2. **结构化记忆 + SQL** — 反向量化趋势，但更适合 izu 的知识陪伴场景。实体-关系-时间三维存储。
3. **BEAM 基准** — 在 1M/10M token 规模下测试记忆系统，虽然 izu 当前不需要，但架构应预留扩展。

### 终局画像调整建议
**从「陪伴 + 问答 Agent」调整为「陪伴 + 记忆 Agent」**。陪伴的核心不是回答，是记住。如果 izu 能记住用户的经历、偏好和项目细节，它的价值将远超一个通用 LLM 封装。
