# 韩信·技术远景报告

## 对izu 3-6个月方向的影响

### 现有技术路线图（当前→3个月→6个月）

```
现在                   3个月后                   6个月后
├─ 基础记忆系统      ├─ 技能发现引擎         ├─ 完全自进化izu
├─ 手动配置技能      ├─ 技能存储库           ├─ 技能自动发现
├─ 单轮对话Agent     ├─ 经验驱动学习          ├─ 技能泛化出新手
                     ├─ 技能复用开始           │     能力
                     └─ 20+通用技能           ├─ 100+自动发现技能
                                            └─ 社区技能共享
```

### 新技术路线需要纳入

**必须是：OpenSpace技能引擎模式**
- 核心思想：Agent从历史交互中自动提取操作模式 → 编译为可复用技能
- 与izu的契合度：极高 —— izu本身就是一个执行环境的Agent，天然产生大量操作日志
- 实现方式：模式匹配 → 参数抽象 → 技能编译 → 测试验证

**建议纳入：Dual-Process认知架构**
- 快速系统1（直觉响应）：匹配已有技能模式，快速执行
- 慢速系统2（深度反思）：当没有匹配技能时，推理+事后抽象新技能
- 对izu的启示：技能引擎可以自然地实现双层认知结构

**可以考虑但非必须：记忆基础技能学习**
- 程序性记忆（procedural memory）—— 技能即记忆
- 如果izu的记忆系统设计得好，技能可以是记忆的子集

### 终局画像调整

**原终局画像**：一个有记忆、能持续对话、能执行工具的Agent
**调整后终局画像**：一个有记忆、能持续对话、能执行工具、**能自行从经验中抽象出新技能的Agent**。技能是izu的第二大脑——从决策的"副产物"变成"产物"。

### 技术阶梯

```
台阶1（1-3周）：接入OpenSpace或自建简单模式匹配技能发现
  ↓
台阶2（3-6周）：技能存储库——用结构化格式记录技能（输入模式→动作序列→输出模式）
  ↓
台阶3（6-8周）：技能匹配引擎——运行时将当前输入匹配到已有技能
  ↓
台阶4（8-12周）：技能泛化——合并相似技能，自动参数化
  ↓
台阶5（12周+）：技能进化——当技能频繁失败时自动调整
```

### 风险提示
- **技能粒度失控**：太细=垃圾技能太多，太粗=无法复用
- **技能冲突**：多个技能匹配同一输入时的选择策略
- **冷启动**：早期经验太少，没有足够模式可提取
