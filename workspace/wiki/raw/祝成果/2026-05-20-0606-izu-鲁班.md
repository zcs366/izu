# 鲁班 — 工程可行性

## 能不能做？

### 子产的路线 + 韩信的远景 → 工程可行性评估

| 项目 | 可行性 | 理由 |
|------|--------|------|
| Skill 兼容 SKILL.md 标准 | ✅ 容易 | 只是文件格式适配，无技术难度 |
| MCP 协议接入 | ✅ 容易 | MCP 有现成 SDK，API 调用即可 |
| Skill Retrieval Augmentation | ✅ 可行 | 基于现有搜索能力改造，无新基础设施需求 |
| 三层记忆架构 | ⚠️ 中等难度 | Working Memory 已有；Episodic/Semantic 需要新设计 |
| 自动 skill 提取 | ⚠️ 复杂 | 从对话中自动提取 skill 模板需要高质量聚类+泛化 |
| 隐空间记忆 | ❌ 高风险 | 依赖 ITA 路线成果，且工程复杂度高 |
| 自进化反馈循环 | ⚠️ 可行但有风险 | 反射循环容易加，但真 self-improvement 需要验证机制 |

## 有没有重复造轮子？

| 组件 | 现有方案 | 建议 |
|------|----------|------|
| SKILL.md 解析 | Anthropic skills 仓库 | 直接复用开源实现 |
| MCP 客户端 | MCP Python SDK | 直接接入，自研 client adapter |
| Skill 检索 | 搜索引擎 + 向量检索 | 在 izu 现有搜索架构上加一层 |
| Episodic 记忆 | MemGPT / Letta | 参考架构，不一定直接使用 |
| Auto-skill | SEAgent / Voyager 方法 | 参考启发式，izu 自研轻量版 |

## 造什么装备？

### 第一批工程（2周，~14h）
1. **Skill Standard Adapter** — 让 izu skill 兼容 SKILL.md 格式
2. **MCP Client** — 接入 MCP 工具协议
3. **Skill Retriever** — 从外部技能库检索匹配 skill

### 第二批工程（2周，~14h）
4. **Episodic Memory** — 会话摘要自动存储
5. **Reflection Loop** — 任务后自动反思 + 优化建议

### 第三批（4周，~28h）
6. **Auto-Skill Extraction** — 从历史对话自动提取 skill 模板
7. **Semantic Memory** — 跨会话知识结构化
