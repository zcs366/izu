# 张仪

## 最强攻击——单点失败分析

### 最可能导致失败的一个点：**技能进化导致的不稳定性和不可预测性**

**为什么是这个点？**
MemSkill的设计师机制允许技能集自动进化——在闭循环中，controller选择技能→失败→designer提出新技能→controller重新学习。这引入了"二阶学习"：不仅学习如何选择技能，还学习如何生成新技能。有两个致命风险：

1. **技能蠕变（Skill Creep）**：技能库不断膨胀，从8个增加到30+。controller的搜索空间指数增长，决策质量快速下降。张成市的日常使用中，90%的记忆需求可能只需3-4个核心技能，但system为覆盖边缘case不断添加新技能。

2. **反馈循环失控**：controller选择了不适当的技能 → designer认为"现有技能不够好" → 设计新的、覆盖面更广的技能 → controller在新技能之间更难选择 →更多失败。这是自指回路的典型问题——系统在"优化"中对自身制造噪声。

**核心矛盾**：自进化系统的目标是"适应多样化的交互模式"——但izu的交互模式在短期（2-4周）内就是固定的（张成市的日常使用）。对固定模式的自适应最优解是"稳定在几个最优技能上"，但designer机制的设计初衷却是"不断探测新技能"。

### 降级方案

**方案A：冻结技能库+人工进化（推荐）**
- 技能库在Phase 1初始化后**冻结**——不自动添加新技能
- designer不用于自动添加技能，而是用于**失败监控+周报**
- 每周review一次failure log，由张成市**手动决定**是否添加/修改技能
- 优势：避免了自指反馈循环，保持了系统稳定性
- 代价：进化速度降低，但日活用户只有1人，进化速度不是瓶颈

**方案B：技能预算封顶**
- 硬性限制技能库最大为15个
- 添加新技能时必须移除一个现有技能（active set control）
- designer必须通过"淘汰论证"——新技能的价值必须超过某个被淘汰技能的损失
- 用强化学习中的action pruning思想控制搜索空间

**方案C：分层技能架构**
- 划分为3个层级：
  - L1（3个核心技能）：不参与进化，始终可用
  - L2（5个常用技能）：可被替换，需要至少7天数据验证新技能更好
  - L3（2个实验技能）：designer自由添加/修改，但需要手动批准才能晋升到L2
- 这个"渐进部署"模式控制了不稳定的传播范围

**推荐降级路径**：先实施方案A（冻结+人工review），如果的确需要自动化，升级到方案C（分层）。
