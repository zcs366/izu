# 鲁班

## 工程协调意见

### 两轨道是否矛盾？
**不矛盾。相反，互补性极强。**

| 共享组件 | ITA 版本 | zu 版本 | 共享方式 |
|---------|---------|---------|---------|
| CodeBERTScore 管道 | 主要用户 | 次要用户 | ITA 搭建，zu 复用 |
| HumanEval 数据集 | 主要用户 | 可复用为 skill 测试 | 同一份数据 |
| Python 环境 | 纯 CPU | CPU + Qwen | 同一 WSL 环境 |
| FSQ 量化模块 | 主要开发 | — | ITA 产出的模块可被 zu 的 skill 编码参考 |

### 推进顺序

**第 1 周（并行）：**
- ITA：环境搭建 + 数据集准备（Phase A）
- izu：Fork MemSkill + 初始 skill 设计（Pre-Phase）
- **协调要点**：ITA 的环境搭建是第一优先级——izu 依赖 ITA 的 CodeBERTScore 管道

**第 2 周（ITA 优先）：**
- ITA：核心实验（Phase B）→ 回答「FSQ 在代码域是否可行」
- izu：Controller 集成（不依赖 ITA 部分）
- **协调要点**：如果 ITA Phase B 结果显示 CodeBERT 嵌入不够语义（AUC < 0.8），izu 的评估路径需要切换到其他编码器

**第 3-4 周（独立并行）：**
- ITA：Phase C 分析报告
- izu：Phase 1+2 评估迭代
- **协调要点**：两轨道可以独立交付最终报告

### 资源竞争

| 资源 | 竞争情况 | 解决方案 |
|------|---------|---------|
| GPU（若需要） | 两轨道都可能需要 | 初始阶段不需要 GPU；若需要，预算 $925 可在 Colab Pro 上错开使用 |
| 张成市的时间 | 不可扩展 | 按上述第二阶段错开排期，避免同一天做两个轨道 |
| CodeBERTScore 评估 | 共享使用 | ITA 封装 API，zu 调用即可 |

### 优先级建议

1. **P0（必须完成）**：ITA Phase A+B（CodeBERT→FSQ 基线实验）
2. **P1（高优先级）**：izu Pre-Phase（环境 + 初始 skill）
3. **P2（中优先级）**：ITA Phase C（报告） + izu Phase 1（集成）
4. **P3（低优先）**：izu Online Designer 创新组件（可降级）

### 鲁班判结
双轨道可以一起推进。第 1 周存在轻依赖（izu 等 ITA 的评估管道），之后完全独立。建议 ITA 先跑通评估管道，izu 同时做环境准备，第 2 周末会师对齐。
