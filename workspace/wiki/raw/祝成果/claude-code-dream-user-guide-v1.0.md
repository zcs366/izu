# Claude Code Dream — 用户操作指南

> **版本**：v1.0 | **类型**：模式B · 用户操作指南  
> **一句话**：让Claude像人一样睡觉做梦，把白天零散的记忆整理成干净的知识卡片

---

## 一、这是什么？

Claude Code **Dream**（做梦/梦境整理）是一个自动记忆整理系统。就像你睡觉时大脑会整理白天的经历一样——把重要的记住、不重要的忘掉、矛盾的理顺——Dream 对 Claude Code 的**记忆文件**做同样的事。

**没有 Dream 的 Claude Code 相当于一个长期睡眠不足的人**：笔记越记越多，旧的忘不掉，新的塞不进，到后来什么也记不准。

---

## 二、三步上手

### 第一步：检查你有没有这个功能

打开终端，进入任何一个 Claude Code 会话：

```
/memory
```

在输出中找一行：

```
Auto-dream: on
```

- ✅ 看到 `on` → 已经在用了，不用做任何事
- ❌ 看到 `off` → 功能还没对全量用户开放（服务器端灰度中）
- ⚠️ 什么都没有 → 你的版本可能还不够新（需要 v2.1.59+）

### 第二步：手动触发一次「做梦」

不管 Auto-dream 是否开启，你都可以**主动让 Claude 整理记忆**。在 Claude Code 会话中直接说：

```
/dream
```

或者用自然语言说：

```
帮我整理一下记忆文件
```

Claude 会启动一个**后台子代理**，花几分钟时间读你的记忆文件，做四件事：
1. 删掉过期的
2. 合并重复的
3. 矛盾的地方取最新的
4. 索引文件压缩到 200 行以内

### 第三步：看看效果

运行完 `/dream` 后，再跑一次：

```
/memory
```

看看记忆文件是不是整洁了。常用效果对比：

| 问题 | 整理前 | 整理后 |
|------|--------|--------|
| 索引超长 | `MEMORY.md` 280行 | `MEMORY.md` 142行 |
| 矛盾指令 | "用 Fastify" 和 "用 Express" 同时存在 | 只保留最新的一条 |
| 旧调试记录 | "删掉 src/old/ 的日志"——文件已不存在 | 自动删除 |
| 相对日期 | "昨天改了 API"——多段记忆都有 | 统一为 "2026-03-15" |

## 三、常见场景卡片

### 🟢 场景一：刚写完一个复杂功能，想整理记忆

```
帮我把刚才的调试心得和项目规范记下来，然后整理一下
```

Claude 会先记下你强调的要点，然后自动跑 `/dream` 做整理。

### 🟢 场景二：发现 Claude 总是记错同一个东西

```
为什么你总是不记得我们用 pnpm 而不是 npm？
——跑一下 /dream 把记忆整理干净
```

根源可能是记忆文件里积累了多条矛盾的记录，Dream 会把它们统一成一条正确的。

### 🟢 场景三：感觉记忆文件越来越臃肿

```
/memory
```
发现索引超长。直接说：

```
跑一次 dream
```

几分钟后索引就瘦下来了。

### 🔴 场景四：不想让 Claude 自动整理记忆

如果你不喜欢自动整理，可以手动关掉（在 `settings.json` 中添加）：

```json
{
  "env": {
    "CLAUDE_CODE_DISABLE_AUTO_MEMORY": "1"
  }
}
```

但注意：关了 Auto-memory，Auto-dream 也没有数据可以整理。

## 六、常见问题

**问：Dream 会改我的代码吗？**  
不会。Dream 只有**只读权限**访问项目代码，只能写 `memory/` 目录下的文件。

**问：同时开两个 Claude Code 会话会打架吗？**  
不会。Dream 有**锁文件**机制，一次只允许一个整理任务运行。

**问：多频繁跑一次 Dream？**  
默认至少间隔 24 小时、并且积累 5 次会话以上才触发。太频繁没有意义——零散的信息不值得整理。

**问：我关了 Auto-memory，还有必要用 Dream 吗？**  
Auto-memory 关掉就没有数据可整理了。Dream 是 Auto-memory 的伴侣功能，不是替代品。

**问：Dream 需要花多少时间？**  
重度项目（900+ 会话）大约 8-9 分钟。因为是后台运行，你感觉不到。

**问：我不喜欢这个功能怎么办？**  
目前 Auto-dream 是服务器端 feature flag（不开通就用不了），所以开不开不是你能控制的。但 `/dream` 手动命令随时可用。
