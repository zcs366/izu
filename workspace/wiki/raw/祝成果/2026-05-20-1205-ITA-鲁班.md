# 鲁班 — 工程可行官

## 在墨子给出的理论约束内评估

### 理论约束回顾
1. 完全 Turing 等价不可判定 → 语义压缩只能覆盖可判定子集
2. 强类型+纯函数式语言效果最好（杠杆 5-10x），动态类型效果一般（2-4x）
3. 冗余去除来自语法层面（注释、重命名、死代码），不是"理解意图"

### 工程可行性判断：「有条件可行，但需要重新定位目标」

#### 方案一：对 MBPP 做 core 提取实验（商鞅的设计）→ ✅ 可行
**工具选型**：
- AST 解析：标准 Python `ast` 库（zero install）
- 类型提取：`typing` 模块 + `inspect.get_type_hints()`（对标注良好的函数有效）
- 控制流骨架：`control_flow_graph` 或手写简单实现
- 从 core 恢复函数：`gpt-4o-mini`（成本低，够用）

**风险点**：
- MBPP 数据集函数较短（平均 3-8 行），core 可能比原代码少不了多少
- 类型标注覆盖率：MBPP 中约 40-50% 函数有完整类型标注
- **应对**：如果 MBPP 的杠杆因子不够，换 HumanEval（函数更复杂，或换用带类型注释的子集）

#### 方案二：完整语义压缩系统 → ❌ 现阶段不可行
- 需要自定义 proof system 和闭包计算引擎
- 对 Turing 完备语言的语义等价判定没有工程捷径
- 建议作为 Phase 2 目标，不是现在

#### 方案三：NLA 风格 Activation Verbalizer 用于代码 → ⚠️ 部分可行
- Encoder(activation→code_semantic_summary) 可以用 Transformer 微调实现
- Decoder(summary→activation) 对标 Anthropic 的 AR 模块
- **约束**：Anthropic 的 NLA 训练需要 1000+ GPU-hours，不在预算内
- **替代**：用 LoRA 微调一个小模型（DeBERTa-v3-base）做 activation→text
- **评估**：10 工时 + $20 云 GPU，可以作为 Phase 2 实验

### 工程结论
1. **商鞅的 20 工时实验完全可行**。这是最低成本的验证方案
2. 不要急着做 NLA 风格的 activation verbalizer——先确认代码的 irredundant core 存在且有用
3. 工具链去风险建议：`pip install tree-sitter` 替代纯 `ast`，覆盖更多语言
4. **建议起点**：先跑商鞅的 Step 1（core 提取）看 Python 函数的语义冗余到底有多少——如果 core = 原代码，这条路就断了
