# 张仪 — 最强攻击官

## 最可能导致项目失败的点

**单点失败：隐空间没有语义结构——CodeBERT的[CLS] embedding可能只捕获了"代码风格"而非"功能语义"**

### 攻击论证
1. **已有证据**：Expert Systems with Applications 2025论文已发现代码嵌入模型在捕获功能语义上的固有局限性。
2. **机制**：CodeBERT的MLM预训练目标使得embedding更关注token共现模式而非I/O行为等价性——两个功能不同但风格相似的函数可能在隐空间距离更近。
3. **后果**：如果Phase A的分离度 < 1.0，则：
   - 整个ITA代码语义压缩方向失去理论前提（没有语义结构 → 没有可压缩的语义信息）
   - 4x压缩+95%语义保留的目标变成不可能
   - 所有后续工程投入（Phase B/C）成为沉没成本

### 我的判断：这个失败点概率约65%

**为什么高**：
- CodeBERT预训练：MLM + NSP（next sentence prediction），没有显式的功能等价性信号
- 现有工作（功能一致性论文）已暗示这一点
- 20工时基线实验很可能暴露此问题

**为什么不是100%**：
- 隐含语义可能通过注意力机制间接编码
- CodeT5+的code review任务可能引入功能理解信号
- 更大模型（≥1B参数）可能涌现语义理解

## 降级方案

### 如果Phase A分离度 < 1.0（最可能场景）

**降级路径A：转向专家知识压缩（而非语义压缩）**
- 不压缩任意代码，而是压缩经过标注的"专家模式"
- 例如：设计模式（Singleton, Factory）、最常用的50个Python惯用法
- 每个模式有显式的语义标签 → 压缩简化为"模式ID + 参数"的编码
- 这不再是通用代码压缩，而是**领域特定压缩**——降低了理论难度但仍有实用价值

**降级路径B：用执行轨迹替代代码文本**
- 不压缩代码文本，压缩执行轨迹（trace）
- 轨迹天然包含语义（I/O行为）+ 控制流信息
- 用FSQ压缩trace embedding → 理论上有R(D)下界
- 这是方向调整而非放弃

**降级路径C：压缩对象从Python函数降级为SQL查询**
- SQL语义比通用代码更干净（声明式，副作用少）
- SQL的率失真边界更容易计算
- 更小的测试集（50个SQL查询 vs 50个Python函数）
- 工程复杂度更低

### 推荐优先级：尝试A → 如果A也不行走C → B作为远景储备
