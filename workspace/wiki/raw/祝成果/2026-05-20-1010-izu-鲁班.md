# 鲁班·工程可行报告（izu轨道）

## 能不能做？

**结论：能做，且已有现成框架可用。**

### 方案A：直接集成OpenSpace（推荐，快速路径）

**OpenSpace能力**：
- 自进化技能引擎，已开源
- 接入任何Agent → 自动从经验中捕获和复用模式
- 46% tokens节省，已被验证
- 造币能力：$11K in 6 hours（社区验证）

**集成可行性**：
```
izu → OpenSpace API → 技能存储 → 技能匹配 → 技能执行
              ↓
        交互日志输入
```
- 集成难度：低。OpenSpace设计为可插入任何Agent
- 工时预估：8-12工时
- 风险：低。开源、有文档

### 方案B：自建轻量技能引擎（可控路径）

**架构设计**：
```
[izu交互日志]
     ↓
[模式发现模块] — 从日志中提取重复操作序列
     ↓
[技能编译器] — 将模式编译为可调用函数
     ↓
[技能存储] — 向量数据库+版本控制
     ↓
[运行时匹配器] — 当前输入→技能匹配→执行
```

**是否重复造轮子？**
- 如果OpenSpace满足需求 → 是（重复造轮子）
- 如果izu需要定制（如izu特有的记忆格式、对话上下文） → 可能有必要

**建议**：先用OpenSpace（搭积木），遇到瓶颈再自建。不要重新发明车轮。

### 造什么装备？

#### 必要装备（必须造）
1. **技能适配层**：将OpenSpace或自建引擎的skill格式映射到izu的action格式（~50行代码）
2. **技能调用接口**：izu执行skill的runtime机制（~100行代码）
3. **技能版本管理**：skill进化的历史追踪（可复用izu的memory机制）

#### 可复用装备
- OpenSpace 的开源实现 → 不需要自己写技能引擎
- izu已有的memory系统 → 技能存储可直接建在memory上
- izu已有的工具调用机制 → 技能执行可复用工具调用接口

### 工程约束检查

| 约束 | 检查结果 | 备注 |
|------|----------|------|
| 张成市日均1h | ✅ 可行 | 方案A 8-12工时 = 2周下班时间 |
| 预算$925 | ✅ 可行 | OpenSpace开源免费，GPU不是必须 |
| 现有代码兼容 | ✅ 可行 | skills层与现有action体系正交 |
| 依赖 | ⚠️ 注意 | OpenSpace需Python 3.10+，确认兼容 |

### 不可行情况
❌ 如果izu的日志系统不完整（丢失操作上下文）→ 技能发现无法工作
❌ 如果izu的操作不在函数/工具调用层面（太抽象）→ 模式无法提取

### 综上
**工程可行性：高。** 建议方案A快速验证，2周内跑通skil发现pipeline，6周内izu开始自动从经验中学习技能。
