## 议题1：层选择与隐状态剪枝（#6）

### 1.1 问题定义

ITA编码器从Qwen2.5-Coder-1.5B的28层Transformer中提取隐状态作为语义编码的输入。关键问题：

- 哪一层的隐状态最"适合"作为ITA编码器的输入？
- 是否所有28层都需参与？能否剪枝到更少的层？
- 是否需要跨层融合（如拼接中间多层）？

### 1.2 现有知识

**模型架构基础**（Qwen2.5-1.5B，文献支撑）：
- 28层 Transformer decoder，hidden_dim=1536
- GQA：12个Q头，2个KV头 | RoPE位置编码 | SwiGLU激活 | RMSNorm
- 词嵌入与输出层共享（tied embeddings）
- 非嵌入参数：1.31B，总参数：1.54B

**中间层优于末层的普遍现象**（文献支撑，Skean et al., ICML 2025）：
- 在32个文本嵌入任务上，中间层（~50%-75%深度）一致优于末层，最高可提升16%
- 理由：末层过度适配预训练目标（next token prediction），语义泛化性下降
- 信息论视角：中间层在信息压缩与信号保真之间取得更优平衡

**Logit Lens 解释力**（文献支撑，nostalgebraist 2020; Belrose et al. 2023）：
- 前几层（0-8层）的隐状态与词汇空间对齐度低，不包含足够语义
- 末几层（24-27层）开始聚焦于局部token预测，全局语义逐渐"压缩"
- 中间层（约12-20层）包含最优的语义-语法混合表征

### 1.3 关键发现

| 发现 | 置信度 | 来源 |
|------|--------|------|
| 第12-18层（~40%-65%深度）是隐状态质量最佳区间 | 文献支撑 | Skean et al. + Logit Lens 理论 |
| 代码模型中，中层编码的语法结构更完整 | 推测（有间接证据） | CodeLLaMA probing 类似结论 |
| 末层（27-28层）因next-token bias不适合做语义编码 | 文献支撑 | 多篇层分析论文一致结论 |
| 前4层（0-3层）信息熵高但语义信噪比低 | 文献支撑 | Logit Lens 研究表明早期层信号模糊 |
| 跨层融合（如拼接12+18层）不一定优于单层最优 | 推测 | 部分任务中特征冗余导致维度灾难 |

**核心洞察**：Qwen2.5-Coder在代码任务上可能存在"语义集中层"——某几层承载了最完整的结构化代码语义信息，类似NLP中的"语法层"（约第2/3深度处）现象。

### 1.4 推荐方案

**推荐策略：单层最优 + 可选的两层融合门控**

阶段一（成本最低，推荐先做）：
```
层扫描 → 在12-22层范围内，每层固定提取最后一个token的隐状态
→ 输入ITA编码器，对比离散化后的恢复精度
→ 选出最优单层（预期在14-18层）
```

阶段二（如有余力）：
```
门控融合：将最优层 + 其前/后3层的隐状态通过轻量门控网络融合
公式：h_fused = α·h_opt + (1-α)·0.5·(h_opt-3 + h_opt+3)
α可学习或固定为0.7
```

**剪枝策略**：
- 不剪层（冻结模型无法物理移除层）
- 做"计算剪枝"：只在选定的1-3层提取隐状态，不遍历28层
- 通过缓存中间激活（reuse activations），前向传播成本不变

### 1.5 工时估算

| 任务 | 预估天数（日均1h） | 关键路径 |
|------|-------------------|----------|
| 层扫描实验 (12-22层 × 3次运行) | 5-7天 | 分析每层恢复精度曲线 |
| 最优单层确定 + 初步验证 | 2-3天 | 稳定性验证（不同seed） |
| 门控融合实验（可选） | 3-4天 | 调优α参数 |
| **合计** | **7-10天** | 保守估计含调试 |

### 1.6 下一步实验

**实验A（快速验证）**：
1. 用HuggingFace Transformers加载Qwen2.5-Coder-1.5B
2. 对一段500行代码做单次前向传播，注册hook采集每层最后一个token的隐状态（1536维）
3. 对每层隐状态做简单的语义相关性分析：与ground truth语义标签的余弦相似度，或同一代码不同变体的隐状态距离稳定性
4. 输出：层号 → 语义稳定性得分曲线

**实验B（ITA编码器输入筛选）**：
1. 将3层候选（如12/15/18层）的隐状态分别输入ITA编码器（先不要端到端训练）
2. 测量FSQ量化后的重建质量（重建损失 + 代码正确性）
3. 如果14-18层显著优于其他层，锁定单层方案；如果差异小，考虑跨层融合

## 议题2：Steering 语义漂移累积模型（#4）

### 2.1 问题定义

在ITA框架中，"Steering"指对离散编码后的latent vector进行方向性编辑/调整（如修改代码风格、修复bug语义）。问题：

- 每次Steering操作为什么会导致恢复代码逐步偏离原始语义？
- 漂移是线性积累还是指数级放大？
- 能否建模并控制漂移边界？

### 2.2 现有知识

**Steering 基本机制**（文献支撑）：
- Activation steering：向残差流隐状态添加方向向量 v_steer，使模型输出偏向目标方向
- CAA（Contrastive Activation Addition, Rimsky et al. 2024）：通过对激活差值取平均获得steering vector
- **本质问题**：steering vector容易捕获伪相关（spurious correlations）而非真实语义意图（Tan et al. 2024; Braun et al. 2025）

**STEERING OFF COURSE 发现**（文献支撑，ACL 2025）：
- 在36个模型、14个模型族上测试：Activation steering → 高度可变，大量模型无改善甚至退化
- 核心原因：steering methods 依赖的"内建机制假设"（如logit lens的早期层预测一致性）在许多模型上不成立
- 跨层一致性差 → 叠加多层steering → 噪声放大

**ITA场景特殊性**（区别于对话Steering）：
- ITA中Steering不是在推理时做，而是在离散latent空间中做（高维 → 量化后的有限集合）
- 离散latent空间中的"方向"不再是连续的 → 每个steering step都是量化误差产生点
- 每步操作后，恢复代码的微小变化可能被解码器放大

### 2.3 关键发现

| 发现 | 置信度 | 来源 |
|------|--------|------|
| Steering vector通过平均值捕获语义 → 天然包含噪声分量 | 文献支撑 | Tan et al. 2024; GER-steer 2026 |
| 跨层语义漂移（cross-layer semantic drift）是steering失效主因 | 文献支撑 | GER-steer (arXiv 2603.12298) |
| 漂移在低维离散空间中一定叠加，但非线性 | **推测**（需证实） | ITA场景独有 — FSQ量化阶梯产生边界效应 |
| 离散latent的steering → 漂移含"量化跳跃"（过界即跳到相邻码字） | **推测** | FSQ的round操作天然产生跳跃 |
| 漂移大概率是**亚线性/对数增长**而非指数放大 | **推测**（有间接证据） | 残差流本质是加法，不是乘法；但FSQ的离散性引入阈值效应 |

**漂移增长形态猜想**：

```
连续隐空间中的steering: Δ_accum = n·δ (线性)
离散latent空间中的steering: Δ_accum ≈ O(√n·δ) (亚线性)
                                  原因：round操作随机消除部分漂移
但遇到码本边界时: Δ_accum 出现阶跃 (非线性)
```

**关键点**：漂移不是指数级放大（因为在离散空间中每次round会"复位"部分误差到最近的离散点），但边界附近的跳跃可能产生大的单步偏离。

### 2.4 推荐方案

**漂移测量方法**：

```
输入：原始代码C0 → 编码为离散码D0
Step 1: 对D0施加steering δ → D1
Step 2: 解码恢复 C0' = dec(D0) 和 C1 = dec(D1)
Step 3: 测量漂移量：
  - 语义漂移 = 1 - cos_sim(emb(C0), emb(C1))
  - 语法漂移 = 编辑距离(C0, C1) / len(C0)
  - 量化域漂移 = ||round(enc(C0)) - round(enc(C1))||₀ (汉明距离)
```

**应对策略**：

| 策略 | 成本 | 效果预期 | 实现复杂度 |
|------|------|---------|-----------|
| 1. 单层steering + 限制步长 | 低 | 中等 | 低 |
| 2. 漂移边界检测 + 回退 | 低 | 高 | 中 |
| 3. 跨层一致性矫正（类似GER-steer） | 中高 | 高 | 高 |
| 4. 每次steering后做码本对齐（re-quantize校正） | 低 | 中高 | 低 |

**推荐实施优先级**：策略1+4（快速）→ 策略2（回滚安全网）→ 策略3（可选优化）

策略4的**码本对齐**具体实现：
```
alias steering_with_requantize(latent, steering_vector):
    steered = latent + steering_vector       # 施加编辑
    steered_rounded = fsq_round(steered)     # 重新量化到最近离散点
    # 如果round前后差异过大（>阈值），回退step或缩小steering幅度
    if ||steered_rounded - steered||₂ > τ:
        steered_rounded = latent  # 回退
    return steered_rounded
```

### 2.5 工时估算

| 任务 | 预估天数（日均1h） | 关键路径 |
|------|-------------------|----------|
| 漂移测量工具开发 | 2-3天 | 确认metric有效性 |
| 单步/多步steering漂移实验 | 3-4天 | 收集漂移增长曲线 |
| 码本对齐策略实现 | 1-2天 | 阈值τ调优 |
| **合计** | **5-7天** | 含实验报告 |

### 2.6 下一步实验

**实验A（漂移测量基线）**：
1. 准备10段不同长度的代码（100-500行）
2. 编码为离散latent → 施加随机方向steering（幅度范围：0.01~0.5）
3. 对每个幅度做1/2/4/8/16步累加steering
4. 绘制：漂移幅度 vs. 步数曲线 → 判断是线性/亚线性/指数

**实验B（码本对齐有效性验证）**：
1. 对比：原始steering vs. 码本对齐steering（策略4）
2. 关注两个指标：①语义保持度（与unsteered版本的差异） ②steering方向效力（是否成功实现了目标编辑）
3. 如果码本对齐策略显著减少漂移但不削弱效力，则纳入流水线

## 议题3：FSQ 梯度崩溃与码本坍缩（#5）

### 3.1 问题定义

ITA使用FSQ（Finite Scalar Quantization）将编码器输出映射到离散码本空间。问题：

- FSQ是否存在梯度崩溃/码本坍缩？机理是什么？
- 文献称FSQ"不会发生"VQ-VAE式的码本坍缩——是否完全可靠？
- ITA场景下（代码隐状态，低维量化）是否存在新的坍缩模式？

### 3.2 现有知识

**FSQ基本原理**（文献支撑，Mentzer et al. 2023, Google）：
- 将高维隐空间投影到低维（通常≤10维），每维量化到固定值集
- 隐式码本 = 各维度量化值的笛卡尔积
- 示例：5维 × 每维7个值 = 7⁵ = 16807个码字
- 量化操作为element-wise round → 梯度用 straight-through estimator（STE）传递

**FSQ vs. VQ-VAE对比**（文献支撑）：

| 特性 | VQ-VAE | FSQ |
|------|--------|-----|
| 码本 | 可学习的嵌入向量 | 隐式固定（维度乘以定值） |
| 码本坍缩 | 常见问题（50-80%码字未使用） | 官方声称不会发生 |
| 辅助损失 | 需要commitment loss + codebook loss | 不需要 |
| 编码器学习信号 | 通过argmin + 梯度复制 | 通过STE round |
| 码本利用率 | 低（需reseed/splitting） | 高（所有码字自然覆盖） |

**iFSQ 关键发现**（文献支撑，Lin et al. 2026, Tencent）：
- **FSQ存在"激活坍缩"（activation collapse）问题**：等间隔量化与神经网络激活的非均匀分布不匹配
- 表现：部分bin的利用率极低（接近0），等价于部分码字永久性未使用——这本质上是一种**码本坍缩的变体**
- 根因：激活值集中在某些区间 → 大部分FSQ bin落在激活的稀疏区域 → 这些bin即使被量化到也缺乏有效梯度信号
- iFSQ的修复（仅1行代码）：用分布匹配映射替代原始FSQ的线性缩放，强制激活呈均匀分布

**Rethinking Codebook Collapse**（文献支撑，Lu et al. 2026）：
- VQ坍缩的根因新解释：**编码器的非平稳更新（non-stationary encoder drift）**
- 无选择权重的码字因编码器漂移而永远收不到梯度
- 提出NS-VQ/TransVQ：非平稳环境中维持码本利用率

### 3.3 关键发现

| 发现 | 置信度 | 来源 |
|------|--------|------|
| FSQ在**视觉任务**上不会发生VQ式的完全码本坍缩 | 文献支撑 | Mentzer et al. 2023 |
| FSQ存在"激活坍缩"（bin利用率不均匀）问题 | 文献支撑 | iFSQ (arXiv 2601.17124) |
| ITA场景（代码latent）下激活分布可能更不均匀 | **推测** | 代码语义的隐状态有模态特异聚类倾向 |
| 低维FSQ（<4维）对激活分布更敏感，坍缩风险更高 | **推测** | iFSQ分析：4bit/维为最优平衡点 |
| FSQ梯度通过STE传递 → 当编码器输出稳定在bin边界附近 → 梯度消失 | **推测** | 从STE数学性质推导 |
| 原始FSQ论文在图像任务验证，未系统测试代码/文本场景 | 事实 | 论文场景：ImageNet, COCO |

**核心洞察**：ITA使用的FSQ不是VQ，所以不会发生"经典码本坍缩"（多数码字完全不使用）。但会发生一种**更隐蔽的次优坍缩**——少数bin占据绝大部分编码量，剩余bin仅有极低利用率 → 有效码本容量远小于理论值。

### 3.4 推荐方案

**训练稳定性检查清单**（可执行版）：

```
□ 1. 编码器输出分布检查
   方法：收集500批次的编码器输出，绘制每维激活直方图
   预期：近似均匀分布（左偏/右偏/尖峰都是风险信号）
   阈值：任一维度的bin利用率 < 10% → 需要干预

□ 2. 码本利用率测量
   指标：Perplexity(码字使用分布) / log(码本大小) → 接近1为好
   监测：每1000步记录一次，观察是否持续下降
   阈值：< 0.5 → 严重坍缩

□ 3. 重建轨迹平滑度
   检查：相邻离散码字间的嵌入向量是否语义连续
   方法：选择2个相邻码字→分别解码→比较输出相似度
   预期：相邻码字应产生相似但不完全相同的输出

□ 4. 梯度量级监控
   指标：||梯度||₂ 在每个STE传播路径上的衰落率
   现象：如果编码器输出坍缩到单一bin附近 → near-zero梯度

□ 5. 边界样本测试
   方法：构造编码器输出的极端值（±3σ）→ 看是否被量化到非边缘bin
   预期：边缘区域也应有一定bin覆盖
```

**推荐抗坍缩策略**（按优先级）：

1. **iFSQ分布匹配**（1行代码，强烈推荐）
   - 用tanh/custom映射取代原始线性缩放
   - 参考：`z_mapped = scale * tanh(z / scale)` 作为FSQ的预处理器
   - 成本几乎为0，有文献支撑且在图像任务上已验证

2. **Bin-Dropout正则化**（推测方案，需实验验证）
   - 训练时对高利用率bin施加dropout → 强制模型使用更多bin
   - 类似VQ中的codebook reseeding思想，但更温和
   - 注意：dropout概率需随码本利用率动态调整

3. **温度编码 + 退火**
   - 训练初期使用soft quantization（温度>1），逐步退火到hard round
   - 类似VQ-VAE 2.0的技巧
   - 可在前5000步使用，之后固化到hard量化

4. **维度重缩放监控**
   - 定期检查每维的实际range是否覆盖了所有量化级别
   - 如果某维range小于码本覆盖范围 → 缩小该维的缩放因子

### 3.5 工时估算

| 任务 | 预估天数（日均1h） | 关键路径 |
|------|-------------------|----------|
| 基础FSQ实现 + 训练脚本 | 3-4天 | 先让训练跑通 |
| 码本利用率监控工具 | 1-2天 | 可视化输出分布 |
| iFSQ适配（1行修改） | 0.5天 | 快速收益 |
| 训练稳定实验（3+ seed） | 4-5天 | 验证检查清单有效性 |
| **合计** | **7-9天** | 含训练实验 |

### 3.6 下一步实验

**实验A（激活分布诊断）**：
1. 用ITA编码器预处理批量代码（1000段），收集编码器输出向量（假设FSQ前是4-8维）
2. 对每维做直方图（bin = FSQ级别数）
3. 计算每维bin利用率的均匀性（KL散度 vs 均匀分布）
4. 如果任一维KL散度 > 0.5 → 确认存在激活坍缩

**实验B（iFSQ vs vanilla FSQ 对比）**：
1. 实现两套量化前处理：原始线性缩放 vs iFSQ的tanh映射
2. 在ITA编码器训练中对比：
   - 训练稳定性（loss曲线平滑度）
   - 码本利用率（perplexity）
   - 最终重建精度（BLEU/edit distance）
3. 如果iFSQ稳定提升 → 纳入默认方案
