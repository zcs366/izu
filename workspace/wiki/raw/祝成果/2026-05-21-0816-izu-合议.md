# Phase 1B — izu 5轮合议（2026-05-21 08:16）

## Round 0 / 子产：需求判断+研究方向

**问题真实性**：真实但被严重高估。记忆退化主要在"月级生命周期Agent"（如代码库维护Agent），而非"长会话"场景。90%短期交互滑动窗口+摘要已够用。

**时间窗口**：12-18个月。窗口膨胀不是万能药——信息检索成本与窗口大小非线性相关。

**值得做的**（富矿）：
- P0：记忆压缩决策系统（何时压、压什么）
- P1：跨会话记忆一致性保障（偏好冲突、过时标记、版本控制）
- P2：记忆的层次化检索架构（层间流动机制）
- P3：评估基准（怎么做评估本身就是贡献）

**死胡同**：通用记忆压缩模型、类人记忆模拟、纯向量DB方案、理论最优压缩。

## Round 1 / 韩信：技术远景

**生产环境现状**：100%依赖"配置文件+RAG+截断"三件套。Cursor（.cursorrules+索引）、Claude Code（CLAUDE.md）、Windsurf（Cascade流式+隐式建模）、Devin（状态持久化）、Copilot（无跨会话记忆）。没有任何主流编码Agent实现了主动的自动化记忆压缩。

**五路线对比**：
- A：分层记忆（MemGPT/Letta）——架构优雅，但换入/换出决策依赖LLM自身判断
- B：树状递归摘要（RAPTOR）——静态长文档效果好，对流式增量适配差
- C：知识图谱（GraphRAG）——天然支持关系推理和一致性检查，图维护成本高
- D：自适应压缩——计算开销可控，直接对应P0，压缩质量评估难
- E：流式状态机——增量处理延迟可控，对非线性任务建模困难

**综合判断**：短期自适应压缩（D）+分层记忆（A）混合；中期知识图谱（C）补P1；RAPTOR路线死胡同。

## Round 2 / 鲁班：工程可行

**四层三管道架构**（轴向约束：渐进式、可回溯、可审计）：
- HOT层（Working）：当前会话上下文，存储内存+WAL
- WARM层（Sessional）：跨会话任务状态，SQLite+向量索引，TTL 7-30天
- COLD层（Archival）：压缩决策摘要，TTL 90天+
- ARCHIVE层（Raw）：原始未压缩数据，append-only写入

**CDE（压缩决策引擎）**——系统的大脑：
- 触发器1：容量压力→按LRU+频率选候选
- 触发器2：条目老化→7天未recall的条目
- 触发器3：冗余检测→语义聚类，redundancy_score > 0.7

**关键工程决策**：混合（LLM摘要+规则校验实体完整性）；SQLite为主向量为辅；条目级压缩；ARCHIVE永久保留。

**6周路线图**：Phase 1（2周）CDE MVP → Phase 2（2周）跨会话一致性 → Phase 3（1周）分层流动优化 → Phase 4（1周）评估基准。

## Round 3 / 萧何：执行路径

**算力需求**：单Agent日均50K-250K token（压缩任务），年成本$500-$10,000（Sonnet级）。
**存储**：非瓶颈。单Agent年增长1-3MB（纯文本）。
**人力**：1-2人可推完，senior AI engineer为核心。
**时间修正**：鲁班6周→萧何评估7-9周，评估应前置至Week 0。

**三大风险**：
1. LLM压缩质量不稳定（命门——无ground truth判断完整性）
2. 上下文窗口暴涨导致压缩需求消失（倒计时）
3. 评估基准缺失（把评估放最后是倒置的——应Week 0就开始）

**三角分析**：3周可验证方向可行性但不可产出可评估结论；12-16周高质量但窗口可能关闭。

**修正路线图**：Week 0评估基准定义+技术选型 → Week 1-2基础管道 → Week 3-4 CDE引擎+评估 → Week 5跨会话精简版 → Week 6集成评估。

## Round 4 / 张仪：最强攻击

**三发重炮**：

**质疑一：伪命题**——"记忆退化"是产品控制问题（记忆不存在、记忆错误、记忆失控），不是技术架构问题。今天数亿ChatGPT/Claude用户没有因压缩不足抱怨。12-18个月窗口是厂商营销叙事（cost optimization），非需求信号。

**质疑二：LLM不可靠**——重要性判断在认识论上不可行：什么记忆"重要"取决于未来的任务，而未来任务是不可预测的。重要性是在回忆时被事后建构的，不是在存储时被事前评估的。压缩错误一旦发生就不可逆。

**质疑三：结构损失**——分层流动架构忽略记忆间关系网络的涌现价值。100条记忆压缩为10条，潜在关联从C(100,2)=4950暴跌至C(10,2)=45。这不是信息损失，是结构损失。

**替代方案**：放弃压缩→拥抱索引。从"记忆压缩"转向"记忆控制"（可解释性+可编辑性+可审计性）。从通用方案转向垂直场景。

**底线**：值得做但方向要改——做垂直场景记忆管理系统（基于规则+索引，不依赖LLM压缩）；做记忆质量评估基准（独立无争议；不做通用LLM驱动压缩方案。
