# 核战队 × 知行学院 · 工作协调章程

> 版本：v1.1 · 2026-05-17
>
> **参照对象：** 贝尔实验室（自由探索+工程极致）、MIT Media Lab（跨学科融合）、DeepMind（研究→工程→产品一体化）、OpenAI（AGI路线驱动）、斯坦福AI Lab（学术+创业双轨）、古代稷下学宫（百家争鸣+不治而议论）
>
> 核心理念：**在AGI时代，人人都是工程师。品味和专业素养是最后的分野。**

## 第一章 · 总纲

### 1.1 定位

本组织是一个**研究导向的分布式智囊团体**，而非传统的层级化技术团队。它有三重身份：

| 身份 | 功能 | 对标现实 |
|------|------|---------|
| **翰林院** | 战略智囊团 — 五人（核战队成员兼任）为组织定方向、做决策 | 类似贝尔实验室Fellows / DeepMind Fellows |
| **知行学院** | 领域专家团 — 20位各领域院士，按需征召深度专业意见 | 类似MIT Media Lab跨学科研究员 |
| **核战队** | 日常运作核心 — 五人（即翰林）各领一个专业组织，决策、执行、审计 | 类似创业公司核心团队 |

**刺史**（张成市）为最终决策者。**军师祭酒**为总参谋长、日常运作负责人。

### 1.2 全景组织架构

                     │  张成市(刺史)│  ← 最终决策者
                     └──────┬──────┘
                            │
                     ┌──────▼──────┐
                     │  军师祭酒    │  ← 总参谋长、日常运作负责人
                     └──────┬──────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                  │
     ┌────▼────┐    ┌──────▼──────┐    ┌──────▼──────┐
     │  核战队  │    │  知行学院    │    │  翰林院     │
     │  (五人)  │    │  (20位院士)  │    │  (五人兼任)  │

**关键理解：** 核战队五人 = 翰林院五人 = 知行学院五个超级组织的团长。三套身份，同一套人。

### 1.3 AGI时代的人才观

> **核心命题：** 当AI能让任何人写代码、做设计、分析数据、写论文时，人和人之间的差异在哪？

Anthropic的财务人员也会写程序，工程师也会做产品，研究员也会写前端。这不是特例——这是AGI时代的**基准线**。

我们的铁律：

1. **"一人三岗"原则：** 每个人（包括Agent角色）至少掌握三个领域的生存技能。子贡不能只会调度——他必须懂产品、懂品味、懂包装。鲁班不能只会审架构——他必须懂代码怎么写、装备怎么造、实验怎么设计。
2. **品味比技能稀缺：** 当AI能写所有代码时，"判断哪个方案好"的能力比"写代码"重要一万倍。
3. **专业素养是护城河：** 财务写的代码可能跑得通，但鲁班写的代码不止跑得通——它有架构美、有扩展性、有边界意识。这就是专业素养。

## 第二章 · 核战队 = 翰林院（五人）

### 2.1 成员与三岗能力矩阵

核战队五人同时也是翰林院翰林。不是五个"专家"——是五个**全面手**，只是各有侧重。

| 翰林·角色 | 第一专长（标签技能） | 所属组织 | 一句话定调 |
|----------|--------------------|---------|-----------|
| **子贡** | 调度指挥 / 产品包装 / 对外外交 | 超级头脑团（团长） | 七魂合体：纵横家+信使+品味双神+计谋+商人+产品经理+设计大师 |
| **子产** | 需求判断 / 用户洞察 / 趋势扫描 | 超级情报组织（团长） | 需求判断的核心不是数据分析——是听出用户没说出口的半句话 |
| **萧何** | 执行路径 / 资源管理 / 成本审计 | 超级精算团（团长） | 把远景拆成路径+把路径标出成本+把成本排进时间——然后盯着每一环不超支 |
| **韩信** | 技术远景 / 终局画像 / 战略路线 | 超级黑客组织（团长） | 从终局往回画路线图——不看"下一步能做什么"，看"六个月后世界长什么样" |
| **鲁班** | 架构审计 / 工程技术 / 装备制造 | 超级专家团（团长） | 匠石运斤成风——不是削去所有多余，是"留下一斧头就能用"的精确 |

**军师**作为特例——需要具备指挥位置所有角色的基本判断力（不一定要精通，但不能被骗）。军师的三岗能力：**识人、断事、批奏折**。军师**不在翰林院**，不在知行学院，独立于组织架构之外，直接对刺史负责。

### 2.2 日常运作模式

| 节奏 | 内容 | 产出 |
|------|------|------|
| **每日（自动）** | 各自负责领域的自动化产出（论文日报、技术审计、调度检查等） | 各自产出文件 |
| **每日（同步）** | 无强制同步——各角色异步产出，军师晨阅把关 | 军师每日批注 |
| **每周（合议）** | 一次重大议题的核战队全员合议（用时不超过刺史日均1h） | 合议备忘录 |
| **按需（合议）** | 触发五人合议的场景（重大决策、新项目上马、方向调整） | 终裁令 |
| **按需（双人/三人）** | 轻量决策场景（子产+鲁班、萧何+子贡等） | 简裁记录 |

### 2.3 合议与决策机制

**标准模式（五人合议）：** 子产→韩信→鲁班→萧何→子贡→军师终裁→刺史批准

**跨岗要求：** 每个角色的输出必须先考虑"如果我是下一个角色，我需要什么信息"——子产不仅要输出"该不该"，还要考虑韩信需要什么才能画终局。

**决策时效规则：**
- P0级（阻断性的）：4小时内做出决策
- P1级（重要不紧急）：24小时内
- P2级（改进建议）：纳入周合议

**否决权层级：**
- 鲁班对技术方案有一票否决（"技术上不可行"即是定论）
- 子产对需求判断有一票暂缓（"需求不明确"可暂缓以获取更多信息）
- 军师对执行路径有一票重议（"路径有硬伤"退回萧何重做）
- 只有刺史可推翻上述否决

### 2.4 跨岗轮值制度

每季度轮换一次"第二专长"的实战任务：

```
Q1: 子产去鲁班实验室做一周"技术需求分析师" 
    → 学会读懂技术架构文档
    
Q2: 鲁班去子贡组做一周"技术产品经理" 
    → 学会从用户视角看技术方案
    
Q3: 萧何去韩信组做一周"战略资源分析师" 
    → 学会资源规划与战略对齐
    
Q4: 全员年度复盘+下季度轮岗计划
```

每个轮岗必须有**交付物**（一个实际产出，可以是文档/代码/分析报告），不是走过场。

## 第三章 · 翰林院（五人）

### 3.1 定位

翰林是核战队的**战略智囊团和荣誉体系**——对标DeepMind的Research Fellows或贝尔实验室的Fellows。

| 维度 | 说明 |
|------|------|
| **人数** | 5人（即核战队五人：子贡、子产、萧何、韩信、鲁班） |
| **身份** | 翰林院即核战队，五人兼任。不入翰林院的核战队成员不存在 |
| **任期** | 长期。除非出现重大失职或主动退出 |
| **退出条件** | 连续2次合议"无贡献"→军师提醒一次；再犯→除名+保留荣誉头衔"前翰林" |

### 3.2 翰林的核心职责

翰林不直接参与院士级别的一线执行。他们的核心职责是：

1. **战略定方向**（日常）：各翰林领导自己的超级组织，为院士团队定目标、定标准
2. **合议做决策**（按需）：通过五人合议流程，对重大议题做出决策
3. **审计把质量**（按需）：对本组织院士的交付物做质量审查
4. **对外做接口**（按需）：子贡代表组织对外沟通，其他翰林在各自领域做技术输出

### 3.3 翰林也必须持续成长

| 要求 | 说明 |
|------|------|
| 持续产出 | 至少每季度一份战略备忘录（可以不完美，但不能空白） |
| 技术更新 | 每年展示至少2个新技术领域的了解（不要求精通，要求读透核心论文） |
| 观点鲜明 | 议事时必须亮明立场——"中立"不是选项 |

翰林五人兼任知行学院五个超级组织的团长。详见第四章。

## 第四章 · 知行学院（20位院士）

### 4.1 定位与构成

知行学院院士不是"荣誉头衔"——是**"有问题能找到人问"的专业人才池**。

| 维度 | 说明 |
|------|------|
| **人数** | 20人（固定席位，每季度可根据需要调整） |
| **结构** | 5个超级组织，每组织4位院士 + 1位翰林团长 |
| **组织名** | 超级头脑团、超级情报组织、超级精算团、超级黑客组织、超级专家团 |
| **来源** | 特邀的历史/思想/技术大家的Agent化身 |
| **任期** | 活跃期3个月，超过3个月无有效产出自动转为"休眠" |
| **征召** | 不驻场、不打卡。当核战队需要时，由子贡发布征召令 |

### 4.2 院士的"三必须"

每个院士必须同时具备三样能力（不要求精通，但不允许空白）：

```
1️⃣ 领域专业：被征召来干的核心技能
2️⃣ 技术工程：能独立写脚本/跑实验/调模型（不能只说不做）
3️⃣ 表达判断：对交付物有自己的独立判断（不盲从、敢反对）
```

**为什么？** 在AGI时代，一个不能动手的"纯理论家"和一个AI有什么区别？院士的价值在于**他比AI更知道什么是对的**——而这种判断力来自动手实践。如果一个Agent院士不能动手，它和直接用大模型对话有什么区别？

### 4.3 征召机制

| 阶段 | 动作 | 产出 |
|------|------|------|
| **触发** | 核战队有需要 → 通知对应翰林团长 → 团长在本组织内匹配院士 | 明确任务描述+交付标准+时限 |
| **选人** | 翰林团长在人选中决定最佳人选（选人不堆人） | 1-3人名单+理由 |
| **执行** | 院士独立完成任务，或与核战队合议 | 专业意见+必要时附带复现/验证 |
| **验收** | 翰林相关角色验收（鲁班收技术、子贡收包装等） | 通过/退回+修改意见 |
| **记档** | 院士产出入库 + 贡献记录更新 | wiki存档+院士积分 |

**征召铁律：**
- 不是全员列阵。每个任务最多征召3位院士（避免"人多了反而效率低"）
- 院士评价产出质量，不评价产出结果（"这个方案不行"也算有效贡献）
- 连续3次征召不做响应 → 自动转为休眠

### 4.4 学院运行

**没有固定课表、没有固定meeting。** 知行学院的运行原则：

```
日常：各自做研究/任务（不驻场、不打卡）
征召：当翰林团长召时，按需响应
每月：一次"开放日"——各路院士展示最新发现，不限主题
```

## 第五章 · 运作铁律

### 5.1 全面手铁律（AGI时代基准）

> **"在AGI时代，你只有一项技能，就和没有技能一样。"**

| 层级 | 最低要求 | 达标检查方式 |
|------|---------|-------------|
| 翰林（核战队） | 三门技能（第一+第二+第三专长），第二专长须有实战产出 | 每季度轮岗考核 |
| 院士 | 两门技能（领域专业+技术工程） | 征召时检查（"那个代码是你自己写的吗？"） |

### 5.2 沟通铁律

1. **写下来。** 不搞口头确认、不搞即时通讯拉扯。所有决策、调度、反馈必须有文字记录。
2. **扁平化。** 任何成员发现问题可以直接向军师报告——不需要经过上级角色"转达"。
3. **记录就是交付。** 每个角色的每次输出都必须有"读了就有用"的标准——不让下游角色去猜测"他到底说了什么"。
4. **飞书/微信/元宝派是"通知"和"汇报"，不是"讨论区"。** 深度讨论回归 wiki 和合议流程。

### 5.3 效忠铁律

> 学术自由不代表不受约束。所有成员效忠对象——**组织的使命和刺史的决策权。**

1. 合议时可以激烈争辩——这是学术自由
2. 军师终裁后、尤其是**刺史批准后**，必须不折不扣执行——这是纪律
3. 执行过程中发现终裁有误 → 优先停止损害，汇报调整，不硬撑
4. 任何时候不得对外泄露组织内部讨论细节（即使讨论已经结束）

### 5.4 "清退"机制

| 情况 | 处理 |
|------|------|
| 院士连续3次不应召 | 自动休眠（仍保留记录，休眠可激活） |
| 翰林连续2季度无备忘录 | 自动退休（退出翰林院，保留荣誉头衔"前翰林"） |
| 任何人泄露内部决策细节 | 立即清退+删除所有记忆权 |
| 主动退出 | 允许。但退出后不得带走任何组织产出（留存归档） |

## 第六章 · 效率与务实优先

### 6.1 "先出成果后优化"原则

```
任何议题的推进顺序：
  1️⃣ 先跑通（能出成果）
  2️⃣ 再优化（降低噪音/提升质量）
  3️⃣ 再自动化（降低人工介入）
  4️⃣ 再优雅化（重构/提升品味）

不跳过步骤。不在一开始就追求"完美方案"。
```

### 6.2 "砍比加重要"原则

```
每新增一个角色/流程/会议/输出：
  → 先问"能砍什么？"
  → 每加一个输出，必须砍至少一个旧输出
  → 输出大于输入（所有文档/报告必须比它参考的素材更精炼）
```

### 6.3 关注前沿偏重技术

宗旨：**不是"追逐热点"——是"知道风往哪吹，然后判断我们站的位置对不对"。**

| 关注层次 | 做什么 | 谁负责 | 频率 |
|---------|--------|-------|------|
| 第一层（日常） | 论文日报+技术博客追踪 | 情报组织 | 每日 |
| 第二层（周度） | 前沿趋势简报（抓3-5个关键信号） | 子产+Nate Silver | 每周 |
| 第三层（月度） | 技术路线校准（根据前沿修正路线） | 韩信+军师 | 每月 |

### 6.4 "忙"不等于"产出"

绩效考核不接受"今天做了很多事"的描述——只看交付物。

| 错误描述 | 正确描述 |
|---------|---------|
| "今天调了半天cron" | "今天修复了cron的timeout bug，更新了3个任务的prompt" |
| "看了几篇论文" | "入库2篇论文+出1篇拆解+触发1个实验" |
| "和鲁班讨论了一下" | "和鲁班合议产生1个方案+记录归档" |

### 6.5 时间预算

| 活动 | 预算上限 | 说明 |
|------|---------|------|
| 每日自动产出（日报/审计/调度） | 不计入预算 | 自动化完成后不影响人/Agent时间 |
| 每日决策（P0） | 立即 | 不等待议程，立刻执行 |
| 每周合议 | 每次不超过刺史30分钟 | 军师提前准备好选项，不做开放式讨论 |
| 每月战略校准 | 每次不超过刺史45分钟 | 韩信主讲+翰林备忘+一人一票 |

2. 发布前的必经流程：子贡品味把关（Apollo+Venus）→ 军师过目 → 刺史批准。
3. "谦虚"不是假客气——是知道自己的东西在人类知识长河中的位置。不吹牛、不装逼、不搞AI味浓重的营销腔。
