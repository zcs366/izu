# 比OpenClaw更好！Anthropic Managed Agents 架构深度拆解

> UP主：小天fotos | 时长：11:26 | B站 BV1DB546wEb8

## 术语说明

| 术语 | 说明 |
|------|------|
| **Managed Agents** | Anthropic 发布的云端多Agent管理服务 |
| **解耦（Decoupling）** | 核心设计理念——将Agent的"大脑"（规划/决策）与"双手"（执行沙盒）彻底分离 |
| **Coordinator** | 编排者/指挥官，不直接干活，只负责拆任务、派活 |

## [00:45-01:56] 背景：从"小龙虾"到 Managed Agents

春节期间我做了个五只龙虾协同开发的视频，全网爆火。但很多朋友问我如何实现多龙虾协作时，我没有分享教程——因为我知道这个架构太蹩脚了。

4月8日，Anthropic 的一篇博客悄悄地把答案贴出来了。标题的意思是：**你要扩大Agent的规模，就要解耦"脑"和"手"**。

这篇博客分享了一个非常真实的内部血泪史。Anthropic 为了弥补模型的记忆缺陷，工程师曾吭哧吭哧地写了几千行复杂的 Harness。结果新模型一发布，变聪明了——以前那些精妙的代码补丁瞬间沦为了毫无价值的垃圾。

> **核心观点**：在Agent领域，你为模型写的修补代码注定会过时的——因为模型的进化速度永远比你重构代码的速度快。

## [01:57-02:57] 解耦：大脑与双手分离

怎么破局？就两个字——**解耦**。把大模型的规划决策能力（也就是大脑）和执行代码的沙盒环境（也就是双手），彻底劈开。

这也是为什么之前很多朋友都跟我吐槽——在本地养小龙虾，养着养着就死了。因为在服务器架构里有个经典的理论叫**宠物与牛马**。

以前大家没解耦，模型、记忆和本地环境就死死地绑在一起。这等于你把Agent当**宠物**去养——它只要跑错一行配置，或者记忆越来越多，又或者环境被污染，系统就会越来越难用，甚至得重装。

但Anthropic这套解耦的架构告诉你要把Agent当**牛马**去用：大脑只管发指令，底层的双手全是无状态的独立沙盒。哪怕某个沙盒代码跑崩了、配置冲突了，没关系——直接干掉，重新拉起一个干净的沙盒接着干。

所以一个配置就能导致全盘崩溃吗？在这种架构下，**根本就不可能发生**。

## [03:00-03:36] 博客的陷阱：Managed Agents 是云服务

这篇博客让我兴致盎然，但是当我继续探索关于如何大规模管理Agent的事，内容却戛然而止。我只在结尾看到了这句话，翻译成最直白的人话就是：

> 底层的多大脑多双手的复杂并发实在太难了，但没关系，接口我们已经做好了。你们就别自己瞎折腾了——直接来买我们做好的云端Agent的服务吧。

所谓的Managed Agents，它其实是**云端的一项服务**。Anthropic 真正的阳谋其实是做一个**云端的Agent的操作系统**。

## [03:37-04:56] SDK 线索：Coordinator 与 20 Agent 规模

虽然Anthropic没有公开它是如何scale的，但也难不倒我——在它的SDK里我发现了一些线索。这个SDK的代码里有个藏着十分深的 beta 目录，里面藏着一整套 Managed Agents 的基础架构。

beta目录下有6个模块：
- **Agents**、**Environments**、**Sessions**、**Skills**、**Memory Stores**、**Vaults**

这些模块都没有具体的实现，它都是**云端API的包裹**。但是从这些参数和类里头，我就能发现他们的场景。

在Agents这个类型定义里，我发现了一个关键的字段叫 **Coordinator**——一个不干活的指挥官，它唯一的职责就是**拆任务、派活**。它的花名册里最多有 **20个Agent**，每个都有自己独立的 prompt、工具和 MCP 服务器。

> 这玩意不就是一个编排者吗？

## [04:56-06:08] Agent vs Session：解耦的核心

博客里提到的 Session 到底是怎么一回事？总结一句话：

- **Agent是静态的**——你可以定义它用什么工具、用什么模型、用什么系统提示词。它就是一个**模板**。
- **Session是动态的**——你把Agent拉起来跑，跑出来的对话、上下文、记忆、挂载的文件，全是属于Session的。

同一个Agent可以跑10个Session，各自独立。但Agent它自己的记忆也不是长在它自己身上的，而是作为 Memory Store **挂载**到Session上的。——这就叫解耦。

> Agent负责"我是谁"，Session负责"我在干什么"

这个Session解耦就不断地在我脑海里出现。我想到一个场景：如果我的Agent刚刚搜完了代码库，那它这个时候应该是一个最聪明的状态——但是再过几轮，它完成了ABCD任务之后，它就越来越不聪明了。

如果有一个特别聪明的编排者，它永远都知道Agent最聪明的状态是什么，并且时刻能**回滚或者复制**这个状态，来应对有针对性的任务——那是不是很厉害呢？

## [06:08-07:17] Session Store：云端记忆与无状态Agent

直到4月中下旬，我在 Claude Agent SDK 的Python代码库里发现了一条极为恐怖的PR时间线——有一个叫 **Session Store** 的东西在4月19日正式被合并了。

从此，**记忆从本地搬到了云端**。Claude Code现在可以从一个Redis的缓存里恢复它的上下文了。

我当时看到这个的时候，后背发凉——所有的线索都接上了。还记得宠物和牛马吗？如果把 Context（上下文）也解耦出来，Agent本身就彻底变成了**无状态的牛马**。

**Anthropic 的完整路线（四层解耦）：**

| 层 | 解耦对象 | 效果 |
|----|---------|------|
| 第1层 | Agent 与 沙盒解耦 | 大脑和双手分开，双手崩了就换一双 |
| 第2层 | Coordinator 编排 | 一个指挥官带着20个专业Agent |
| 第3层 | Session 作为记忆树 | 可以 fork、回滚、克隆——是协调者的调度工具 |
| 第4层 | Session Store | 云端记忆，Agent彻底无状态，随时销毁随时重建 |

> 这不就是一个**Agent的操作系统**吗？

## [07:17-08:58] UP主的复刻实践

4月中下旬我茅塞顿开，用了一周时间就把 Anthropic 这套四层解耦架构几乎完整复刻出来了：Agent的沙盒、Session Store、静态编排器——除了结果评估模块还没做，其他基本都跑起来了。

我的实现是：把 Agent Harness 塞进了 Walker 节点（一个Docker容器）。每个 Docker 都是可以随时销毁、随时创建的。一个 Walker 在创建时候，你可以决定：
- 它是什么模型
- 是什么 Harness
- 是什么 Scale
- 从哪个 Session 的什么位置来恢复
- 挂载好 Git SSH Key 以及工作目录

主控服务器通过**预定义的任务图**来让各个 Walker 按照预定义的规则交互。任务的定义和业务流程有关——比如编码→Review→测试的流程，可以同时并发多个编码+Review，然后汇总到一个节点。

甚至可以用这样的任务图来做 **Deep Research** 的 Agent 任务——多个节点并发搜索，再交给多个并发的写作节点去整理，最后交给一个节点去做 PPT/报告。

由于每个节点的任务都是独立的，所以它们可以从一个**全新的上下文**开始。这样每个节点就可以是**不同的模型了**——充分利用大小模型的组合，实现最佳的**Token Efficiency**。

## [08:58-09:56] 未来展望：动态 Agent 容器

这种体验让我大为震撼。我只需要一个接待员了解我的想法，它随时调度背后的几十个Agent容器一步协作。

我们使用云的场景可能也在变化了——以前我们都有一个容器、固定的服务在长期使用。但是未来可不可能变成**无数个动态的Agent容器在不断的创建和销毁**？在这样的模式下，计算资源的分配和计价是不是也会开始变革？

于是我觉得 Docker 这种容器是不是就有点瓶颈——毕竟它的启动和销毁还是有点耗时的。结果你说巧不巧，**Kube Sandbox** 就在4月20几号的时候就发布了（开源沙盒），据称可以**毫秒级**启动一个沙盒。我又有种后背发凉的感觉——好像踩中方向了。

## [09:57-10:55] 结语：Agent 从个人工具变成企业基础设施

虽然关于如何编排才是最优的探索还有很长的路要走，但我可以预见：未来无论在哪里，我只需要一部手机或者是一个眼镜，只要一句话，云端的集群就会在数十个沙盒里协作，帮我们来完成任务。

有些事情其实早就已经在海外发生了：
- **Palantir** 的 AIP 系统
- **Anthropic** 的 Managed Agents
- **OpenAI** 的 Frontier
- 还有一个不断兴起的新职业 **FDE**（待下次说）

他们都在做同一件事：**把Agent从个人工具变成企业基础设施**。

而**我们**呢？我们还在研究怎么样在本地养多只小龙虾，还在为用 OpenClaw 还是用 **Hermes** 在争论不休。这就是为什么我要花一整期的视频来拆解这套架构。

我们国产模型这几年确实进步得很快，似乎是和海外在不断地拉近距离。但是当很多厂商现在还在不断优化如何把卖Token这个生意做得更好的时候，海外的厂商们已经把对AGI的理解以及如何落地上升到了另一个维度了。

所以——**我们是不是落后的更多了？**
