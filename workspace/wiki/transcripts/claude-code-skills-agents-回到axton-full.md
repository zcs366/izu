# Claude Code: 从零搭建你的 AI 工作团队（Skills + Agents）

> UP主：回到Axton | 时长：20:28 | 原视频：B站 BV1eADaBME5z

## 术语说明

| 术语 | 说明 |
|------|------|
| **Claude Code** | Anthropic 推出的 AI 编程助手，可在终端、Cursor 编辑器等环境中使用 |

## [00:00-01:13] 开场：搭一个 AI 工作团队

如果你能搭一个 AI 团队，帮你完成从信息筛选、内容审查，到多平台发布的全流程，你会怎么用它呢？今天我就带你从零搭建一个。

嗨，你好，欢迎回到 **Axton**。我们先让你来看一下这个系统搭建完成之后长什么样——这是我现在每周都在跑的一个真实的工作流。

今天的视频，我会带你从零搭建这一整套系统的起点。今天我会带你搭两样东西：

1. **Skills** — 你可以把它理解成我们写给 AI 的标准操作手册
2. **Agent** — 有明确职责的 AI 团队成员，他知道什么时候该用什么 Skill

搭完之后，我会展示用同样的方法搭出来的完整系统跑起来到底是什么样的效果。

如果你不懂编程，不用担心，没关系。我们全程是用 **Cursor** 里边的 **Claude Code** 来进行操作，不需要写代码，也不需要用终端的命令行。

## [01:26-02:03] Claude Code 的使用方式

我们先来快速说一下 Claude Code 的使用方式。目前有三种：

1. 桌面端 app 直接使用
2. 在终端窗口当中使用
3. 在 **Cursor** 这样的编辑器里面使用

今天我用 Cursor 的目的，就是你可以同时看到我们的项目的文件结构，以及 Claude Code 的对话界面，看起来会非常地方便。

如果你还没有装过 Claude Code，我们可以在 Cursor 的扩展商店里面去搜索 Claude Code，搜索之后点击安装，安装 Anthropic 官方的这个就可以了。然后用你的 Claude 账号登录就可以。

## [02:04-03:06] 项目初始化：创建 CLAUDE.md

目前我已经准备了一个项目文件夹，就是「我的 AI 团队」（MyAI Team）。你看这个结构：

- `context/` — 放基础资料（写作风格、审查标准、发布规范）
- `template/` — 放模板
- `article/` — 放等待处理的文章
- `skills/` 和 `agents/` — 待会搭建时自动生成

这些资料非常重要，它是你的 AI 团队了解你是谁的基础。

我们打开了这个项目文件夹之后，第一步就是来做初始化的工作——也就是创建 **CLAUDE.md** 这个文件。这个文件是你给 AI 团队的一个入职手册。Claude 每次要打开一个新的会话的时候，它都会读取 CLAUDE.md 这个文件，知道项目的背景、规则以及你的偏好。

初始化的方式，就是在 Claude Code 的对话框里边直接输入 `-init`，然后等待生成。它会读取我们已经提供好的这些文档，然后创建 CLAUDE.md 文件。

## [03:07-04:02] 安装官方的 Skill

还有一步准备工作——我们可以安装一些 Claude 官方的 Skills。我们可以输入 `/plugin`，然后添加 Anthropic 的官方 Skill 仓库。之后我们就可以搜索和安装我们所需要的基础 Skills 了。

这里面最需要大家安装的就是 **Skill Creator**，这是 Anthropic 官方用来帮你创建 Skills 和优化你现有 Skills 的最重要的一个 Skill。这个建议大家一定要把它安装上。你可以只为这个 Project 安装，当然要方便的话你可以 Install for you，这样你所有的 Project 都可以用了。

**注意**：这边说的 Plugins 其实也就是 Skills，目前基本上都是同一回事。安装之后需要 Restart 让 Skills Plugin 生效。

## [04:03-07:46] 搭建第一个 Skill：内容审查

接下来我为我们的项目搭建第一个 Skill——**内容审查 Skill**。

这个 Skill 的作用：你把一篇文章丢给它，它会用两个不同的 AI 模型去分别审查，然后把两边的意见汇总给你。

**为什么要用两个模型？** 同一个模型审查自己的输出会存在系统性的盲区。用两个不同的模型来进行交叉检查，就能发现更多的问题。

（UP主也开源了一个全功能的多模型讨论和辩论的 Skill，在 GitHub 上的 `ai_pair`。）

我们要搭一个好的 Skill，需要告诉 Claude 希望它怎么去审查。我在 context 文件夹里面准备了一个审查标准文档，里面写了一些审查维度，比如：
- 逻辑是否自洽
- 事实是否可验证
- 语气是否一致
- 有没有 AI 味道太浓的表达

这就是你的操作手册。当然你的标准跟我肯定不一样，关键是把**你脑子里的审查标准都写下来**，让 AI 有章可循。

接下来我们就让 Claude 创建 Skill——根据 `context/review_standard.md` 这个审查标准，来帮我们创建一个叫 **content_review** 的 Skill：

1. 先用 Claude 从逻辑和结构的维度审查
2. 再用 **Gemini**（通过 Gemini CLI）从事实准确性和风格一致性的维度进行审查
3. 汇总两边的发现，输出一份审查报告
4. 把 Skill 创建在 `skills/content_review/` 目录下

它会调用 Skill Creator 这个 Skill 来帮我们创建。

**测试结果**：用项目里的 newsletter 草稿做了测试。Claude 指出的主要问题是结构问题——比喻矛盾、结尾缺乏可执行的 take away 等。Gemini 指出的内容完全不一样——大部分人的断言没有来源、"不需要学新工具"表述过于绝对、"提示词"应该改为"prompt"等。

这就是 Skill 的价值体现：你提前想好分工，然后 AI 就会按照你的设计来执行。

## [08:04-09:36] 搭建第二个 Skill：微信发布

接下来再搭建一个用来发布微信公众号的 Skill。这个 Skill 的特殊之处在于，它不是只让 AI 处理文本了——它要让 AI 直接操控一个外部的平台，要用工具来做事情。

这就需要用到一个叫做 **MCP** 的协议（Model Context Protocol），你可以把它理解成 **AI 和外部工具之间的桥梁**。要让 Claude Code 跟外部工具通信，需要配置 MCP 的连接。

通过 MCP，我们就可以让 AI 直接调用我们在 **Make**（make.com）上搭好的工作流，不需要我们手动去 Make 里面去点运行了。

接下来创建 **wechat_publish** 这个 Skill：
- 功能：接收一篇 Markdown 格式的定稿文章，通过 MCP 调用 Make 的微信公众号发布场景，自动完成发布
- 流程：读取校验 → 组装文章元数据 → 用户确认 → 调用 MCP → 报告结果

## [09:37-10:53] 为什么要先搭 Skills 再搭 Agents？

在搭 Agent 之前，我想说一下为什么我们先要把 Skills 搭好，而不是直接上来就搭建 Agent。

你可以把这件事想象成**开公司**。假设你有一笔钱要创业，你不会拿到钱直接招一个 CEO，然后跟他说"目标是一年赚一百万，你就看着办吧"——然后放手。现实里不会有人这么干，但很多人用 Agent 的方式就是这样。

现在有很多开源 Agent 编排框架，上来就让你建一个 Agent，告诉它目标让它自己去搞，自己去建团队——结果就是混乱不可控，产出的质量也看不下去了。

**正常的创业你会怎么做？** 你作为创始人，先自己把业务流程跑通——哪些环节需要你判断、哪些是纯执行的、标准是什么。这些搞清楚了，写下来——这就是 **Skills**。Skill 就是你脑子里的流程变成了 AI 可以执行的标准操作手册。然后你才去招人——这就是 **Agent**。Agent 会按照 Skill 来工作，它有标准可循，干完之后还能根据反馈来更新 Skill，让流程越跑越好。

所以：**先定流程，再配人**——这个顺序不能搞反了。

## [10:54-14:20] 搭建 Agent：Publisher

好了两个 Skill 搭好了，我们现在来搭 Agent。

Skill 是操作手册，Agent 是拿着手册干活的人。一个 Agent 可以装备多个 Skill，就像一个员工可以负责多项工作一样。

用 Claude Code 创建 Agent 的方式很简单，只不过不能在 Cursor 的 Claude Code 插件里面创建，需要在**终端窗口**进行创建：

1. 打开终端，进入 Claude Code
2. 输入 `/agents` 命令
3. 选择「创建一个新的 Agent」
4. 选择「只为当前 Project 创建」
5. 选择**手动配置**（为了充分演示）

**配置过程**：
- **名称**：`publisher`（发布用 Agent）
- **System Prompt**：发布运营 Agent，负责内容从定稿到发布的完整流程——质量审查 + 发布到微信公众号
- **触发条件**：描述 Agent 的主要功能和关键词
- **工具**：默认选择所有工具（实际使用建议只选需要的）
- **模型**：默认 Sonnet
- **颜色**：绿色
- **记忆范围**：当前项目范围

**重要步骤**：创建完成后，需要在 `agent.md` 文件的 `runtimetool`（运行时工具）部分手工加上两行——引用我们之前创建好的两个 Skills：`content_review` 和 `wechat_publish`。这样 Agent 启动时就会自动加载它们。同时注意把文件名和 `name` 字段改成一致，避免混淆。

## [14:22-15:37] 测试 Publisher Agent

让 Publisher Agent 把 newsletter 草稿发布到微信公众号。可以看到它：
1. 调用了 `content_review` Skill 进行审查
2. 审查完成后调用 `wechat_publish` Skill
3. 通过 Make 的 MCP 往微信公众号上进行发布

结果：文章已经推送到微信公众号草稿箱。审查结果思维全部通过，标题 22 字符合限制。下一步登陆公众号后台确认草稿并且发布。

到公众号后台刷新，可以看到最新发过来的文章——「从消费智能到编排智能：AI 时代的工作方式」。

这说明整个发布 Agent 的功能是正常的：它根据我们的要求，对一篇文章先进行审查，审查通过之后再进行发布。

## [15:38-17:36] 搭建第二个 Agent：社交互动

接下来再创建一个用于**社交互动的 Agent**。它不装备任何 Skill，就是用 Claude 的基础能力，把长内容转换成社交媒体上适合传播的短内容。

不是所有的 Agent 都需要 Skill，简单的任务用 Claude 的基础能力就够了。所以给大家演示两种 Agent：一种复杂的（装备多个 Skill），一种最简单的。

**配置过程**（同前）：
- 名称：`social_voice`
- System Prompt：社交互动 Agent，负责把长内容转换成适合传播的短内容，主要输出推文
- 触发条件：当用户说"写条推文"、"帮我发个推"、"把这篇转成推文"时触发
- 工具：默认全部
- 模型：Sonnet
- 颜色：黄色
- 记忆范围：项目范围

测试：把 newsletter 草稿生成一条推文，成功输出。

## [17:37-19:13] 总结：两个 Agent 的对比

以上就是两个 Agent 完整的配置和演示过程——两个 Agent 完全不同的配置：

- **Publisher**：装备了两个 Skill，走的是审查发布的完整流水线
- **Social Voice**：什么 Skill 都没有，靠 System Prompt 和 Claude 的基础能力就能干活

根据任务的复杂度来决定怎么配置你的 Agent。

用同样的方法，可以继续搭更多的 Skill 和 Agent——比如：
- **内容策划 Agent**：装备选题分析和脚本创作的 Skill
- **视觉设计 Agent**：装备配图和封面图的 Skill

UP主自己用这个方法搭了 **12 个 Agent**，起名叫做「柯家族」，包括信息筛选、内容策划、视频制作、视觉设计、多平台发布等。每个 Agent 有自己的职责、自己的 Skill、明确的协作规则。

最终效果：一条命令启动 Agent，自动筛选本周 AI 重点新闻，到知识库查之前的观点，按照格式写一篇完整的 newsletter，之后自动配图，通过 MCP 一键发布到微信公众号。整个过程只介入了一次。

## [19:13-20:28] 结语：从操作到系统

这是 UP主新出的一本书《**重构个体：AI时代如何打造个人竞争力**》，由电子工业出版社出版。

今天学会了搭 Skill 和 Agent，这是操作层面。但是搭一个真正有效的系统，光会操作是不够的：

1. **心智** — 知道怎么判断工作流，哪里该用 AI，哪里不该用
2. **架构** — 设计一个架构蓝图，让系统随工具变化灵活替换
3. **提示词** — 跟 AI 精准沟通，让输出稳定可靠
4. **系统** — 把能力组装成一个真正能跑起来的系统

这四件事，就是书里写的完整路径。今天视频里面用的是 Claude Code，书里面用的是 Make，工具不一样，但思维方式是通用的。
