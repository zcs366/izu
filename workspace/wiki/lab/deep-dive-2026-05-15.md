## 🥇 第一篇：ActGuide-RL — 用人类交互数据替代昂贵SFT的Agent训练新范式

- **论文**：[Learning Agentic Policy from Action Guidance](https://arxiv.org/abs/2605.12004)
- **作者**：Yuxiang Ji, Xiangxiang Chu 等（9人）
- **提交**：2026-05-12 · **代码**：[AMAP-ML/ActGuide-RL](https://github.com/AMAP-ML/ActGuide-RL) ⭐5
- **方向标签**：🔴 Agent自我迭代

### 一、问题定义

Agent强化学习（RL）有一个"冷启动死结"：基础策略探索能力不足 → 无法到达奖励状态 → 没有训练信号 → 无法改进。现有方案是用监督微调（SFT）做冷启动，但SFT数据昂贵且容易过拟合。本论文问了一个好问题：**人类每天与Agent交互产生的海量Action Data，能否替代昂贵的SFT？**

### 二、核心方法拆解

**ActGuide-RL 三件套**：

1. **Action Data注入**：将人类交互中产生的Action Data转化为"plan-style reference guidance"（计划式参考引导）。不是完全替代Agent的决策，而是作为"路标"指引Agent跨越可达性障碍。

2. **混合策略训练（Mixed-Policy Training）**：Guided rollouts（有引导的探索轨迹）和Unguided rollouts（无引导的自主探索轨迹）联合优化。关键设计：引导只在Agent卡住时触发——**最小干预原则**。

3. **自适应Fallback机制**：根据任务难度动态决定是否注入引导。难度匹配 → 最小化off-policy risk。这避免了"保姆式引导"导致的策略退化。

### 三、关键数据

| 基准 | 提升幅度 | 模型 |
|------|---------|------|
| GAIA | **+10.7 pp** (vs zero RL) | Qwen3-4B |
| XBench | **+19 pp** (vs zero RL) | Qwen3-4B |
| vs SFT+RL | **持平**，但无需任何冷启动数据 | Qwen3-4B |

> 这意味着：**ActGuide-RL = SFT+RL的性能，但成本只有后者的RL部分。**

### 四、对Hermes Agent的实战启示

1. **工具调用轨迹就是Action Data**：Hermes Agent的每一次工具调用（terminal、search、patch等）都产生Action Data。这些数据天然包含"在什么状态下用了什么工具、参数怎么填、结果如何"——正是ActGuide-RL需要的plan-style guidance。

2. **训练管线可以直接套用**：
   - 收集Hermes Agent的真实交互轨迹（尤其是成功的多步工具调用链）
   - 用ActGuide-RL的混合策略框架做RL训练
   - 引导只在Agent陷入循环/错误工具选择时触发
   - 训练后引导策略的能力内化到无引导策略中

3. **最小干预原则特别适合工具调用场景**：Agent调用工具时，大多数情况不需要干预。只在工具选择错误、参数错误、或陷入死循环时才注入Action Data引导。

### 五、局限与风险（⚠️ 推断）

- Action Data质量决定训练上限——低质量的交互数据可能引入噪声
- 论文仅验证了搜索Agent场景（GAIA/XBench），是否适用于更复杂的编码/多工具编排场景待验证
- "最小干预"的触发条件设计是关键工程挑战

## 🥈 第二篇：DAgger回归 — 4B Agent击败8B系统的训练秘籍

- **论文**：[Revisiting DAgger in the Era of LLM-Agents](https://arxiv.org/abs/2605.12913)
- **作者**：Changhao Li, Rushi Qiang, Niao He, Bo Dai 等（Georgia Tech）
- **提交**：2026-05-13
- **方向标签**：🔴 Agent自我迭代 · 🔵 多Agent协作架构（训练方法论）

### 一、问题定义

多轮Agent训练面临经典的SFT-vs-RL两难：
- **SFT**：教师轨迹密集监督，但在off-policy数据上训练，部署时遇到covariate shift（状态分布偏移）
- **RL**：on-policy探索避免分布偏移，但奖励信号稀疏（只有最终pass/fail）
- **DAgger**：2011年的模仿学习算法，恰好架起两者的桥梁——但从未在LLM Agent场景验证过

### 二、核心方法拆解

**DAgger三步曲（适配LLM Agent版）**：

```
回合1：教师策略 π_teacher 执行 → 收集 (状态, 教师动作) → 训练学生 π_student_1
回合2：β·π_student_1 + (1-β)·π_teacher 混合执行 → 收集数据 → 训练 π_student_2
回合3：β·π_student_2 + (1-β)·π_teacher 混合执行 → ...
...
回合N：π_student_N 逼近 π_teacher，且经历了真实环境的状态分布
```

关键设计：
- **Turn-level插值**：不是轨迹级混合，而是每一步都按β概率使用学生策略
- β从0→1逐步退火，让学生从"看老师做"过渡到"自己探索"
- 训练目标始终是模仿教师（SFT loss），但数据来自on-policy的混合轨迹

### 三、关键数据

| 模型 | SWE-bench Verified | 对比 |
|------|-------------------|------|
| DAgger-4B | **27.3%** | 超过已发表的8B SWE-Agent系统 |
| DAgger-8B | **29.8%** | 超过SWE-Gym-32B，逼近更强的32B Agent |
| 最强Post-Training Baseline (4B) | 23.4% | DAgger +3.9pp |
| 最强Post-Training Baseline (8B) | 26.2% | DAgger +3.6pp |

> **核心信号**：DAgger让小模型获得了跨量级的竞争力。4B Agent达到27.3%，这不仅超过了训练它的8B教师，还超过了所有已发布的8B SWE-Agent系统。

### 四、对Hermes Agent的实战启示

1. **DAgger天然适合多工具调用Agent训练**：Hermes Agent的每次工具调用都是一个turn，DAgger的turn-level插值直接适用。

2. **教师策略可以是Claude/GPT-4等强模型**：用强模型作为π_teacher生成工具调用轨迹，训练本地的小模型（如Qwen-4B），实现"大模型教小模型"。

3. **统一了SFT和RL的视角**：DAgger框架下，SFT、RL、Off-Policy Distillation都是特例。这为Hermes Agent的训练管线提供了统一的理论框架。

4. **混合策略执行天然产生多样化数据**：β概率的学生探索+教师纠偏，产生的轨迹既有正确路径也有从错误中恢复的路径——比纯SFT数据更有训练价值。

### 五、局限与风险（⚠️ 推断）

- 需要教师策略在推理时可用（多轮混合执行），增加了训练时的推理成本
- 教师策略的质量是上限——如果教师本身就有缺陷，学生学到的是"有上限的能力"
- SWE-bench是代码修复任务，是否适用于更开放的Agent任务（如研究、写作）待验证

## 🥉 第三篇：HAGE — Agent记忆从静态向量检索到动态图演化的跃迁

- **论文**：[HAGE: Harnessing Agentic Memory via RL-Driven Weighted Graph Evolution](https://arxiv.org/abs/2605.09942)
- **作者**：Dongming Jiang, Yi Li 等（5人）
- **提交**：2026-05-11 · **代码**：[FredJiang0324/HAGE_MVPReview](https://github.com/FredJiang0324/HAGE_MVPReview) ⭐10
- **方向标签**：🔴 Agent自我迭代 · 🔵 多Agent协作架构（共享记忆基础设施）

### 一、问题定义

现有Agent记忆系统有两种范式，各有关键缺陷：
- **扁平向量检索**（如RAG）：无法捕捉事件间的关系结构
- **固定二值关系图**：边权重固定，无法反映不同查询下的关系强度变化

**核心洞察**：同一对事件之间的关系，在不同查询意图下应该有不同的权重。例如"我昨天改了Hermes的配置文件"和"今天Agent启动失败"——在做"故障排查"查询时是强因果，在做"代码变更日志"查询时只是弱时序。

### 二、核心方法拆解

**HAGE的四层关系图 + 自适应路由**：

```
记忆图谱架构：

共享记忆节点（Memory Nodes）
    │
    ├── 语义关系视图（Semantic Graph View）
    ├── 时序关系视图（Temporal Graph View）
    ├── 因果关系视图（Causal Graph View）
    └── 实体关系视图（Entity Graph View）

每条边的特征向量：可训练的，编码多种关系信号

查询流程：
Query → LLM意图分类器 → 路由网络（QueryRouter MLP）→ 动态调制边嵌入维度 → 遍历打分 → 检索结果
```

**训练框架**：
- 策略梯度RL联合优化路由网络 + 边特征
- 下游任务作为奖励信号
- 查询条件化的边权重：同一对节点，在不同查询下激活不同的关系维度

### 三、关键贡献

1. **从静态图到自适应图**：边权重不再固定，而是随查询动态变化
2. **RL驱动演化**：记忆图随着Agent使用自动优化，不需要人工标注
3. **多关系统一视图**：四种关系（语义/时序/因果/实体）在同一个图中表示，通过路由网络动态组合

### 四、对izu/Hermes的实际价值

1. **izu知识管理系统的记忆层**：HAGE的四关系图可以直接映射到izu的知识结构——论文之间的引用关系（因果）、同一主题的研究时间线（时序）、概念之间的语义关联（语义）、作者/机构的归属关系（实体）。

2. **Hermes Agent的长期记忆基建**：Hermes需要在多次对话、多个任务中积累经验。HAGE的查询条件化检索天然适合"不同任务需要不同记忆视角"的需求。

3. **可训练的路由网络**：Edge特征和Router通过RL自动优化——这意味着记忆系统可以随着使用"越用越好"，不需要人工维护知识图谱。

### 五、局限与风险（⚠️ 推断）

- 论文未报告在超长horizon（100+ turns）上的性能，实际Agent对话可能远长于实验设置
- 四关系图的计算开销随节点数增长，需要工程优化（分片/近似检索）
- GitHub ⭐仅10，代码成熟度待验证
