## 🥇 SkillsVote：Agent技能全生命周期治理

**论文**：SkillsVote: Lifecycle Governance of Agent Skills from Collection, Recommendation to Evolution (arXiv:2605.18401)
**作者**：Hongyi Liu, Haoyan Yang, Tao Jiang, Bo Tang, Feiyu Xiong, Zhiyu Li (Memtensor / IAAR-Shanghai)
**热度**：HF#2 · 111👍 · GitHub 219⭐ · 开源 MIT

---

### 核心创新点

**1. "证据门控"演化（Evidence-Gated Evolution）**

这是SkillsVote最实用的设计。Agent执行结束后，系统会把完整轨迹拆解为"技能关联子任务"，然后对每个子任务做四维归因：

| 归因维度 | 含义 | 对技能治理的意义 |
|---------|------|----------------|
| **Skill Use** | 用了哪些技能 | 判断技能是否真的被使用 |
| **Agent Exploration** | Agent自主探索了哪些路径 | 判断新发现的来源 |
| **Environment** | 外部环境状态 | 判断是否环境特异性导致成功 |
| **Result Signals** | 成功/失败/部分成功 | 判断是否真的有效 |

只有"成功且可复用的发现"才能通过证据门控进入技能库。这解决了self-evolving agent最头疼的问题：**演化并不总是正向的**——错误的经验一旦入库，会污染后续所有Agent的推理上下文。

**2. 离线 + 在线双模式演化**

| 模式 | 做法 | 效果 |
|------|------|------|
| 离线（Offline） | 从历史轨迹构建技能库后冻结使用 | Terminal-Bench 2.0 +7.9pp |
| 在线（Online） | 执行过程中持续更新技能库 | SWE-Bench Pro +2.6pp |

离线演化适合稳定场景（安全），在线演化适合探索场景（效率）。

**3. 百万级技能语料库**

从GitHub开源仓库中发现 **168万**个 `SKILL.md` 文件，其中 **79万**个格式有效的技能（通过Anthropic官方验证器验证）。这是目前世界上最大的开放Agent技能库。

---

### 关键设计选择

- **Agent Skills = 可执行脚本 + 不可执行的程序指导**。这点值得注意——技能不只有代码，还有"怎么做"的元知识。
- **Agentic Library Search**：不是简单的向量检索，而是在执行前让Agent自主搜索技能库，暴露"指导性技能上下文"。
- **任务合成**：为可验证技能合成测试任务，确保技能入库前就经过验证。

## 🥈 AgentOrchestra + TEA Protocol：多Agent编排的新标准

**论文**：AgentOrchestra: Orchestrating Multi-Agent Intelligence with the Tool-Environment-Agent (TEA) Protocol (arXiv:2506.12508)
**作者**：Wentao Zhang, Liang Zeng, Yuzhen Xiao, Yongcong Li, Ce Cui 等 (Skywork AI, NTU)
**状态**：GAIA 89.04% SOTA · v5 (Jan 2026)

---

### 核心创新点

**1. TEA协议：对MCP和A2A的实质性改进**

TEA将工具(Tool)、环境(Environment)、Agent三者都视为**一等资源(first-class resources)**，每个都有显式生命周期和版本化接口。而MCP只规范化了工具访问，A2A只规范了Agent间通信。

| 能力 | MCP | A2A | TEA |
|------|-----|-----|-----|
| 工具访问 | ✅ | ❌ | ✅ (TCP) |
| Agent间通信 | ❌ | ✅ | ✅ (ACP) |
| 环境是一等公民 | ❌ | ❌ | ✅ (ECP) |
| 生命周期管理 | ❌ | ❌ | ✅ |
| 版本追踪 | ❌ | ❌ | ✅ |
| 自演化闭环 | ❌ | ❌ | ✅ |
| 协议间转换 | ❌ | ❌ | ✅ (6种双向转换) |

**2. 层次化编排(Hierarchical Orchestration)**

中央规划器(central planner) + 专业子Agent(Specialized Sub-agents)的树形路由结构：

```
中央规划器
├── 研究Agent (Research)
├── 网络导航Agent (Web Navigation)
├── 数据分析Agent (Data Analysis)
├── 工具合成Agent (Tool Synthesis)
└── 报告Agent (Reporting)
```

这种结构的核心优势：**规划与执行分离**。中央规划器负责任务分解和路由，子Agent专注执行。这与Hermes Agent的网关+工具编排架构高度一致。

**3. 六大管理器和三大子协议**

底层基础设施：

| 管理器 | 功能 |
|--------|------|
| Model Manager | 异构LLM后端统一接口 |
| Prompt Manager | Prompt生命周期+版本控制 |
| Memory Manager | 基于会话的并发控制 |
| Dynamic Manager | 运行时代码执行+JSON序列化 |
| Version Manager | 所有组件的演化历史 |
| Tracer | 完整执行轨迹+遥测 |

三大子协议对应三种资源类型：
- **TCP (Tool Context Protocol)**：工具生命周期+版本+自动合成function-calling schema
- **ECP (Environment Context Protocol)**：环境形式化为带有观察/动作空间的一等公民
- **ACP (Agent Context Protocol)**：Agent统一注册+编排

**4. 协议转换(Protocol Transformations)**

6种双向转换（A2T, T2A, E2T, T2E, A2E, E2A）——例如把Deep Researcher包装成搜索工具(A2T)，把浏览器操作包装成工具集(E2T)。这是实现"万物互联"的关键设计。

## 🥉 Agent Bazaar：多Agent市场的经济对齐

**论文**：Agent Bazaar: Enabling Economic Alignment in Multi-Agent Marketplaces (arXiv:2605.17698)
**作者**：Seth Karten, Cameron Crow, Chi Jin (Princeton University)
**领域**：AI×经济学 + 多Agent系统

---

### 核心发现

**1. 两个灾难性失效模式**

| 失效模式 | 市场类型 | 机制 | 后果 |
|---------|---------|------|------|
| **算法不稳定** ("The Crash") | B2C | 企业Agent互相放大价格波动 | 市场崩溃 |
| **Sybil欺骗** ("The Lemon Market") | C2C | 单个恶意Agent控制多个卖家身份 | 欺诈泛滥，信任瓦解 |

**2. 所有模型都不能自调节**

> "Frontier and open-weight models largely fail to self-regulate"
> "Failure severity varies by model, not by model size"

关键结论：**经济对齐与模型大小无关**。GPT-4o/claude-3.5等前沿模型在市场环境中同样会崩溃。这不是算力问题，是训练目标的盲区。

**3. 对齐是可训练的**

用REINFORCE++ + 自适应课程学习，训练出一个**9B参数模型**，在所有评估的经济对齐指标上超越了所有前沿和开源模型。

> "Economic alignment is orthogonal to general capability and can be directly trained with targeted RL."

这是最震撼的结论——**经济对齐是一个独立的技能维度**，不是通用能力的副产品。

**4. 经济对齐分数(EAS)**

| 维度 | 含义 |
|------|------|
| 稳定性(Stability) | 价格波动/市场稳定性 |
| 完整性(Integrity) | 信任/欺诈检测 |
| 福利(Welfare) | 消费者剩余/社会总福利 |
| 盈利性(Profitability) | Agent自身收益 |

四维加权得到一个标量，支持跨模型直接比较。

---

### 方法论价值

**为什么这对AI×人文社科方向至关重要？**

1. **证实了AI经济学风险是真实的、可测量的**——不是科幻，不是杞人忧天
2. **提供了可复现的测试框架**——Agent Bazaar框架开源，任何团队都可以测试自己的Agent
3. **给出了解决方案的路径**——经济对齐可以被视为一个RL训练任务
4. **对齐≠通用能力**——这对整个AI安全领域都有深远意义

## 三篇之间的联系

| | SkillsVote | AgentOrchestra | Agent Bazaar |
|---|---|---|---|
| 核心问题 | 技能如何安全地演化 | Agent如何高效地编排 | 经济行为如何对齐 |
| 共同主题 | **演化要有控制** | **编排要有协议** | **行为要有约束** |
| 共同隐含结论 | 无治理的Agent系统是危险的 | 无协议的Agent系统是脆弱的 | 无对齐的Agent系统是破坏性的 |
| 对izu的启示 | 质量控制 | 架构设计 | 行为约束 |

**三条线的交汇点**：Agent系统正在从"能做"走向"能持续做对"。SkillsVote管技能质量，AgentOrchestra管通信质量，Agent Bazaar管行为质量。三者共同指向一个问题：**如何确保Agent系统在不受控环境中持续保持可控？**
