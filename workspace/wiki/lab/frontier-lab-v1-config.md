## 一、使命

探索和实现人工智能的自我迭代——以多Agent协作系统为研究载体，以人文社科为应用领域，以学术发表为知识沉淀方式。

## 二、研究议程（三大方向）

| 方向 | 核心问题 | 关键子题 |
|------|---------|---------|
| **Agent自我迭代** | Agent怎么让自己变强？ | 元认知、反思机制、自主进化、能力边界自检、失败学习 |
| **多Agent协作架构** | 一群Agent怎么分工？ | 角色定义、通信协议、质量控制、任务拆分、冲突解决 |
| **AI×人文社科** | AI怎么理解人类文明？ | 政治分析、军事推演、文学批评、艺术生成、历史解读 |

## 三、团队角色

### 3.1 猎手（Scout）
- **职责**：每日扫论文/动态，发现"什么在动"
- **信源**：arXiv (cs.AI/cs.CL/cs.MA)、Twitter/X、GitHub trending、HackerNews、知乎、Reddit r/MachineLearning
- **输出**：每日论文列表（标题+摘要+初筛标签）+ 热点信号
- **频率**：每日自动运行（cron: 每天上午各扫一轮）
- **工具集**：web_search, bing_search, web_extract, arxiv

### 3.2 矿工（Miner）
- **职责**：深挖论文——读懂、翻译、拆解技术路线
- **输入**：猎手筛选的TOP论文
- **输出**：论文深度拆解（核心方法+技术路线图+关键公式解读+中文摘要）
- **频率**：按需（猎手标记"深挖"后触发）
- **工具集**：web_extract, paper-translate-research skill, terminal

### 3.3 铁匠（Smith）
- **职责**：复现关键实验，验证论文真伪
- **输入**：矿工拆解后的论文（含可复现的实验方案）
- **输出**：复现报告（成功了？失败了？差距在哪？）+ benchmark数据
- **频率**：按需（判官标记"需要验证"后触发）
- **工具集**：terminal, python, execute_code

### 3.4 织网者（Weaver）
- **职责**：把孤立知识点串成知识图谱
- **输入**：矿工+铁匠+判官的全部输出
- **输出**：技术演进图、概念关系图、研究方向脉络
- **频率**：每周一次（cron: 每周日汇总）
- **工具集**：wiki, fact_store, zh-dep-parse-graphrag skill

### 3.5 判官（Judge）
- **职责**：批判性审视——真靠谱还是灌水？
- **输入**：矿工拆解后的论文
- **输出**：批判报告（方法缺陷、实验漏洞、过度声称、与其他论文矛盾处）
- **频率**：每篇"深挖"论文必审
- **工具集**：web_search（查引用/反驳证据）, fact_store

### 3.6 主笔（Scribe）
- **职责**：整合输出——日报/周报/论文草稿
- **输入**：以上所有角色的输出
- **输出**：
  - 日报（每日，10篇论文+分类+批判摘要）
  - 周报（每周，领域趋势+关键进展+izu实验室动态）
  - 论文草稿（按需，学术格式，可投稿）
- **频率**：日报每日，周报每周日
- **工具集**：write_file, wiki, humanizer skill

## 四、工作流

### 4.1 日常运转（自治）

```
每天上午:
  猎手扫描 → 产出论文列表+初筛标签
    ↓
  （子贡路由：标记"深挖"的 → 派给矿工）
    ↓
  矿工深挖TOP3 → 产出拆解报告
    ↓
  判官审读 → 产出批判报告
    ↓
  主笔整合 → 产出日报 → 推送微信/存入wiki
```

### 4.2 周度汇总（自治）

```
每周日晚:
  织网者拉取本周全部产出 → 生成知识图谱+趋势报告
    ↓
  主笔整合日报+织网报告 → 产出周报 → 推送+存档
```

### 4.3 按需深度研究（触发式）

```
成市/军师触发"研究XXX" →
  五人合议审议方向 →
    子贡调度：
      猎手扩展搜索 → 矿工深度挖掘 → 铁匠验证 →
      判官评审 → 织网者关联 → 主笔出论文草稿
```

## 五、调度规则（子贡掌管）

### 5.1 日常调度
- 猎手：cronjob，每日上午自动运行
- 矿工：猎手标记≥3篇"深挖"后自动触发
- 判官：矿工每完成一篇即触发
- 主笔：每日晚汇总当天所有产出
- 织网者：每周日晚运行

### 5.2 资源分配
- 猎手/矿工/判官：使用低成本模型（DeepSeek等）
- 铁匠：使用本地终端+Python环境
- 主笔/织网者：核心任务使用高质量模型

### 5.3 质量门槛
- 判官批判用"匠石铁律"：能用代码验证的不用模型判断
- 主笔产出前过子贡品味审查
- 连续3次质量不达标 → 上报军师

- 关键技术进展
- izu实验室动态

### 论文草稿格式
- 标准学术论文格式（标题/摘要/引言/方法/实验/讨论/结论/参考文献）
- 中文为主，英文摘要
- 目标投稿：arXiv 或中文核心期刊

## 七、与五人合议的关系

- 五人合议是最高层审议机构
- 实验室日常运转不需五人合议
- 当实验室需要调整方向、新增研究方向、评估重大产出时 → 启动五人合议
- 子贡是实验室与五人合议之间的接口

## 八、进化机制（Agent自我迭代的实验场）

本实验室本身就是Agent自我迭代的研究对象：
- 实验室的每个Agent角色都有自己的"元认知日志"——记录成功/失败/改进
- 每月复盘：哪些角色配置需要调整？工作流哪里冗余？质量哪里下降？
- 发现的改进 → 写入方法论 → 可能成为论文素材
