# Info Source Cultivation — 个人信息源生态系统

> 核心理念：当用户分享可复用输入（信息源、工具、工作流）时，立即建立结构化耐久设施，而非留在聊天记录里腐烂。

## When to Use

触发条件：用户分享一个他们会反复使用/持续跟踪的信息源，满足以下任一条：

| 场景 | 示例 | 是否触发 |
|------|------|----------|
| 用户说"这两个频道是我的科技信息源" | 老范讲故事、人民公园说AI | 是 |
| 用户分享一个一次性文章 | "看看这篇报道" | 否（走 wiki-drop） |
| 用户说"关注这个作者" | "这个人的分析靠谱" | 是 |
| 用户推荐一个工具链 | "我现在主力用这个" | 是 |
| 用户分享一个一次性视频 | "这个视频有意思" | 否（普通对话） |
| 用户说"以后这种源多找给我" | "这个方向的博主都推给我" | 是 |

判断标准：源能命名、有持续输出、用户主动表明"这是我的源"或期待你记住它。

## Workflow

### 第一步：分析源特征

对每个源，回答四个维度（与用户确认后再写入）：

- **风格**：叙事驱动/情绪驱动/信息密度型/深度分析型？
- **场景**：适合什么话题？不适合什么话题？
- **可信度**：数据扎实吗？观点有偏吗？
- **盲区**：他/它不擅长什么？

### 第二步：建立wiki条目

写入 `wiki/concepts/my-info-sources.md`（全局源地图文件）。每条源一个表格：

```
| 属性 | 值 |
| 链接 | [频道名](URL) |
| 风格 | XXX驱动型 |
| 特点 | 2-3句话总结 |
| 适合场景 | 场景1、场景2 |
| 可信度参考 | 评价+依据 |
| 盲区 | 注意什么 |
| 最近细读 | [文章标题](URL) |
```

文件底部需附使用规则：

1. 吃来源，不盲从来源——叙事框架好用，但事实要溯源
2. 交叉验证——情绪型来源的观点，用叙事型来源对照
3. 叙事优先——给复杂判断时，可以先用源的叙事方式入场，再展开深度
4. 新源加入流程：用户丢链接 → 军师初判 → 记入此表 → 标注场景/盲区/最近细读

### 第三步：记忆落定

将源的风格偏好和用途写入用户记忆，格式：`{日期} 信息源：{名称}（{风格}）& {名称}（{风格}）。已建源地图 wiki/concepts/my-info-sources.md。`

### 第四步：Holographic Memory 留存

将每条源的关键特征存入 fact_store，tag 含 `info-source`。

### 第五步：交付摘要

完成后给用户干净摘要：已接入哪些源、各自适合什么场景、盲区提示、一个观察建议。

## User Preferences

1. **不要只聊天——建立结构**。用户分享可复用输入时，第一时间建wiki条目，不留在聊天里。
2. **每条源附盲区**。用户需要知道什么判断适合什么源，什么判断不适合。
3. **叙事框架优先**。用户偏好从故事入手的输出风格。复杂判断应找叙事入口。
4. **风格分类要准**。分叙事驱动/情绪驱动/信息密度型/深度分析型，不要笼统说"科技频道"。
5. **源地图是活的**。初次录入只做初始判断，后续持续更新。

## Pitfalls

1. **不要把单篇URL摄入当源收录**。用户分享一篇文章不等于他说"这是我的源"。触发条件是明确表明持续使用。
2. **不要跳过分析直接填表**。与用户确认风格判断再写入。
3. **不要一个源写太长**。每条源2-4个维度足够。
4. **不和wiki-drop冲突**。wiki-drop做单篇摄入，这个技能做源地图，文件路径不同。
5. **不给源打"好/坏"标签**。风格无好坏，只有适不适合。
