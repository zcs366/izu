# 军师每日功课 · 闭环系统

> **核心问题**：精力太散，一直在开始很少完成。
> **核心路线**：先做好父亲，再做好写作者。
> **关键机制**：一条指令闭环执行——不说"记得就做、忘了就算"。

## 一、六项功课总览

| # | 频率 | 功课 | 最低完成线 | 耗时 |
|---|------|------|-----------|------|
| ① | 每日 | 读诗20行 + 手抄 + 50字分析 | 至少10行+手抄 | 15-20min |
| ② | 每周 | 写一首短诗 | 8行以上，新旧不限 | 30min |
| ③ | 每月 | 重写一件老作品 | 改一篇旧文或改旧诗 | 1-2h |
| ④ | 每日 | 给女儿讲15分钟知识 | 至少讲一个知识点 | 15min |
| ⑤ | 日常 | 以用带学计算机 | 每天至少一个实操动作 | 20min+ |
| ⑥ | 年度 | 完成一件具体的事 | 每天推进至少一步 | 视项目定 |

## 二、触发与执行机制

### 触发指令

```
用 daily-rituals 执行今日功课
```

### 执行流程（每次触发自动执行）

```
Step 1: 检查今天星期几 → 确定周/月任务是否该做
Step 2: 生成当日读诗内容（20行诗+抄写模板+分析引导）

Step 5: 检查年度大事进度，给出今日推进建议

```

## 三、每日读诗模块

### 选诗原则

- 优先选**完整的诗**，而不是节选。20行大约相当于：
  - 5首五言绝句（每首4行×5=20行）
  - 3-4首七言绝句（每首4行×4=16行，再加一首5-8行的短诗）
  - 1首中长诗（如《登高》8行、《将进酒》40行可拆两天）
  - 或1首词（小令30-58字）+ 1-2首小诗补齐
- 保证**题材多样**：咏物、怀古、边塞、山水、田园、送别、思乡循环
- 优先作者：李白、杜甫、王维、白居易、苏轼、辛弃疾、杜牧、李商隐、陶渊明、屈原（楚辞节选）
- 按朝代/风格循环，不长期偏食

### 推荐循环序列（28天一轮）

| 日 | 题材 | 推荐诗人 |
|----|------|----------|
| 1-3 | 盛唐气象 | 李白 |
| 4-6 | 诗史沉郁 | 杜甫 |
| 7-9 | 山水田园 | 王维/孟浩然 |
| 10-12 | 边塞豪情 | 王昌龄/岑参/高适 |
| 13-14 | 中唐新变 | 白居易/刘禹锡 |
| 15-16 | 晚唐余韵 | 杜牧/李商隐 |
| 17-18 | 宋词豪放 | 苏轼/辛弃疾 |
| 19-20 | 宋词婉约 | 李清照/柳永 |
| 21-22 | 魏晋风度 | 陶渊明/曹操 |
| 23-24 | 楚辞/诗经 | 屈原（节选） |
| 25-26 | 明清诗词 | 纳兰性德/龚自珍 |
| 27-28 | 自由/回顾 | 自选或重读近期最爱 |

### 分析引导池（每次随机选1-2个方向）

- 这首诗里哪个字用得最好？为什么？
- 如果给这首诗配一幅画，你会画什么？
- 这首诗的节奏（平仄/韵脚）给你什么感觉？
- 诗人在写这首诗时是什么心情？你怎么知道的？
- 这首诗跟你今天的生活有什么关联？
- 如果改诗中的两个字，你会改什么？怎么改？
- 这首诗的结构是怎样的？（起承转合？先景后情？）
- 这首诗让你想起哪首别的诗？对比一下。
- 用一句话把这首诗的核心感受告诉一个没读过的人。
- 诗里有没有你以前不认识的字/词？记下来。

## 四、每周短诗模块

### 触发条件

每逢**周一**生成本周诗作提示（如果是其他日子触发功课，提示"本周诗作待完成"）。

### 写诗引导（每次选一个方向）

**方向一：命题式**
给出一个具体题目，如《夜读》、《雨后菜园》、《接娃路上》、《女儿睡着了》——跟生活紧密相关的题目。

**方向二：仿写式**
取一首本周读过的诗，用同样的结构/韵脚/意象写一首自己的。

**方向三：自由式**
"随便写，不设限。写完回来告诉我。"

**方向四：改旧式**
找一首上周写的不满意的，改到满意为止。

### 提交检查

- 最少8行
- 古体/近体/现代诗不限
- 写完后自我评价一句："这首诗好在哪？"
- 如写不出来："写不出来也没关系，把为什么写不出来的感受写下来，也是一段文字。"

## 五、每月重写模块

### 触发条件

每逢**每月1日**（或本月第一次触发时检查），生成本月重写提示。

### 重写池候选

从以下列表中选一件：
- 过去写的一首不满意的长诗（如《佉馘》某一段）
- 一篇半成品文章/编辑手记（如《假如经理们读了德鲁克》某章）
- 一封没发出去的信
- 随手写的碎笔/日记

### 重写三段式

```
Step 1 - 初读：把旧作通读一遍，不改，只标记"保留""删掉""重写"
Step 2 - 重写：按标记改一遍。改完通读，不求完美，但求比上版好
Step 3 - 对比：新旧比一比，写一句"这版比上版好在哪"
```

## 六、女儿15分钟知识模块

### 内容类型轮换（每天一类）

| 星期 | 类型 | 说明 |
|------|------|------|
| 周一 | 万物由来 | 一个日常事物的起源（纸、镜子、筷子、雨伞……） |
| 周二 | 人物故事 | 一个历史/科学人物的小故事（不超过5句话讲清） |
| 周三 | 自然奥秘 | 一个自然现象的原因（为什么天蓝？为什么叶子变黄？） |
| 周四 | 身体秘密 | 身体的一个功能（为什么我们会打哈欠？为什么指甲会长？） |
| 周五 | 神奇动物 | 一种动物的奇特能力 |
| 周六 | 动手实验 | 一个在家能做的简单实验（水杯望远镜、纸桥承重……） |
| 周日 | 自由话题 | 女儿想知道什么，或者你当天想到的有趣话题 |

### 输出格式

```
【今日主题】XXX
【一句话解释】（二年级能听懂）
【口述版】（供你直接讲给她听，100-150字）
【互动问题】（讲完后问她一个问题）
【如果想多讲一点】（给她留一个钩子，她有兴趣再展开）
```

### 执行要诀

- **不超过15分钟**。时间到了收住，哪怕没讲完。留个悬念明天继续。
- **孩子不想听就停**。不追问、不失望。明天换一个话题再试。
- **用实物/动作辅助**。讲纸的历史就拿张纸，讲种子就拿颗豆子。二年级听觉通道堵塞型学习者需要多感官辅助。
- **你不知道没关系**。"这个问题爸爸也不知道，我们一起来查。"——这本身就是最好的知识示范。
- **讲完如果不互动**，不强求。她听进去了就行，不是每一场都需要反馈。

## 七、以用带学计算机模块

### 原则

不学"为了学"，只学"为了做"。用真实项目驱动技术学习。

### 核心方法

```
你有一个真实需求 → 你动手做 → 遇到问题 → 学技术解决问题 → 做出来 → 下一个需求
```

### 每日最小操作（任选一个）

- 写/改一段Python脚本（哪怕3行）
- 查一个技术概念（15分钟搞懂，写一段笔记）
- 调试一个bug（从报错到解决，记下解决过程）
- 优化一个自己的工作流（自动化or简化）
- 读一段技术文档/代码（不限语言，不限长短）
- 跟Hermes Agent学一个新操作（工具用法、配置项）
- 整理wiki里的一条知识

### 输出格式

```
【今日操作】做了什么
【学了什么】一个具体的知识点
【明日方向】下一步可以做什么
```

## 八、年度大事推进模块

### 核心问题

> 今年内必须完成一件具体的事。

### 日常推进模式

每次触发功课，检查一次年度大事的状态：

```
【年度大事名称】_______
【当前进度】完成了____%
【上次推进】做了什么
【今日一步】今天可以推进的一小步
```

### 如果卡住了

```
卡住原因：_________
建议方案（任选）：
□ 拆小：把这步拆成更小的三步，走一步算一步
□ 换方法：这条路走不通，换一条路
□ 先放：先做别的功课，改天再回来
□ 求教：问我（军师），我帮你分析
```

### 如果还没有年度大事

> 先停下来想：今年你最想完成的一件**具体的事**是什么？
> 不是"写好诗"这种模糊目标，而是"出版一本诗集"或"完成十万字笔记"这种可交付、可计量的目标。
> 想好了告诉我，我帮你拆成每天15分钟能推进的量。

## 十一、军师的话

> 这六项功课，每天全部做到当然最好。
> 做不到 —— **至少做一项**。做一项比一项不做强一百倍。
> 重要的是**每天**，不是**全部**。
> 闭环的核心不是完美，是**持续**。

## 十二、系统维护模块

> 军师自身系统的日常健康检查。不是给用户做的功课，是给Agent自身做的保养。

### 触发指令

`daily-rituals 系统维护`

或作为每日功课闭环的自动附加工序（在执行完全部功课后自动执行）。

### 维护项目

| # | 频率 | 项目 | 操作 | 工具 |
|---|------|------|------|------|
| ① | 每6h | 记忆系统维护 | 自动compact+purge+report+self model | cron: izu-memory-maintenance-每6h |
| ② | 每日 | 成本追踪 | 扫描新session→追加成本日志→出报告 | `python3 izu_cost_tracker.py scan` |

### 执行要诀

- 成本追踪器用字符数估算token，不依赖API返回的usage字段

- 进化管道解析Hermes session格式（单JSON对象含messages数组，非JSONL）
- 所有报告自动写入 `output/doc/` 对应子目录
- 规则提取优先于LLM调用——90%的评分/压缩/分析工作可以用代码完成
