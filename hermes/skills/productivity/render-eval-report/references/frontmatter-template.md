# 评估报告 Frontmatter 模板

wiki/research/ 下的评估文件必须包含以下 YAML frontmatter：

```yaml
---
title: 评估报告标题
source: 原始URL
date: YYYY-MM-DD
eval_level: 大 | 极大
contributors: 军师
tags: [标签1, 标签2]
references:
  - 关键参考名: URL
  - ...
status: 已评估
trigger_consultation: true  # 仅极大级需要
---
```

## 等级判定标准

### 大
- 趋势分析、方法论介绍、工具评测
- 有参考价值但非原创深度
- 流程：评估→wiki入库→output输出→HTML→log

### 极大
- 架构级见解、直接关联核战队/ITA方向
- 需要核战队审议的深度技术内容
- 流程：评估→wiki入库→output输出→HTML→log → 触发五人合议

## 评估报告结构

1. **事件概述**：一句话说清是什么
2. **核心论点**：逐条拆解（大条目下如果需要可嵌套子条目）
3. **对我们的启示**：★★★★★ 评分制，必须有具体可执行建议
4. **可执行检查清单**：表格形式，每项标当前状态和建议变更
5. **军师判断**：明确的行动建议 + 级别评定理由

## 输出交付（output版）格式

output/大/ 或 output/极大/ 下的文件：
- 最上方用 `# 标题`（普通Markdown，不要YAML）
- `**来源**：` `**日期**：` `**评估级别**：`
- 正文同wiki版，但更精简
- 适合直接阅读

## 知识框架合成（batch处理后的必需步骤）

当一篇文章是同一批相关内容的收尾（如年度综述），最后一篇评估必须做框架合成：

```yaml
# 在评估结论中加入以下结构
## 最大收获——一张地图

| 文章 | 在这个体系里的位置 |
|---|---|
| 文章A | 理论框架层 |
| 文章B | 系统架构层 |
| 文章C | 子系统X |
...所有相关文章映射到同一个框架...

## 军师判断

今天这批文章可以画成一条完整的逻辑链：
> 理论 → 架构 → 子系统 → 验证方法 → 成本约束 → 全景图
```
