# B站视频评估案例：Claude Code Dreaming 三角验证教训

> 2026-05-20 | 关联render-eval-report 路径B+

## 背景

评估「硅谷温差 Ep2: Agent记忆系统=AGI ?」(BV13WRGBoEU3)时，我写下了评估结论：
> "Dreaming机制仅停留在概念阶段，没有讨论工程实现"

**用户纠正**：Dreaming已在Claude Code泄露源码中工程化实现。

## 纠正后的发现

调取 Claude Code v2.1.88 泄露源码分析后：

| 维度 | 视频说的 | 源码真相 |
|------|---------|---------|
| Dreaming状态 | "概念，没讨论工程" | ✅ 完整实现，`src/services/autoDream/autoDream.ts` 200+行 |
| 触发条件 | 未提及 | ✅ 三重门：24h + 5 sessions + 文件锁 |
| 执行体 | 未提及 | ✅ fork独立subagent，不中断主会话 |
| 锁保护 | 未提及 | ✅ 锁文件 mtime=时间戳，body=PID，PID重用防护 |
| 手动触发 | 未提及 | ✅ `/dream` 命令 |

## 教训

1. **不要假设播客追不上工程进展** — 硅谷播客有内部信源，常常比公开文档提前
2. **涉及热门产品时先搜源码分析** — 搜索信号词："产品名 + leaked source / source code / 源码"
3. **用户的指正是最强的纠偏信号** — 用户知道你不知道的工程细节，三角验证是对评估者最好的纠偏机制
4. **宁可多做一步搜索，不要默认视频观点为真**

## 改进后的流程

评估涉及具体产品/工具的论点时：
1. 搜索：产品名 + "源码" / "leaked source" / "architecture"
2. 如果有泄露源码或开源库，优先以其为准
3. 产出对比表：视频观点 ↔ 工程实现 ↔ 自身能力
4. 标记任何未经验证的观点为 "待核实"
