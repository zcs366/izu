## 一、四团联席战报（每周一10:00）

### 议程模板（60min）

```
0-5min   萧何：上周资源消耗 + 本周预算释放
5-15min  鲁班：上周理论发现 + 本周盲区推进计划
15-25min 韩信：上周技术交付物 + 阻塞问题
25-35min 子产：上周情报产出 + 本周监控重点
35-45min ITA实验室：上周装备交付 + 本周装备计划
45-55min 跨团协调：接口问题 + 资源冲突
55-60min 军师：裁决 + 本周优先级定调
```

### 质量门

| 门 | 标准 | 不合格处理 |
|----|------|-----------|
| 产出汇报 | 每个交付物必须有可检查的证据（文件路径/运行日志/测试结果） | 退回补证据，下次重报 |
| 阻塞上报 | 每个阻塞必须有：问题描述+影响范围+尝试过的解决方案+需要谁协助 | 退回补全信息 |
| 数据真实 | 所有数字必须可追溯来源 | 虚假数据=包拯标记🔴 |

### 产出标准

- 战报纪要 → `ita/docs/meetings/war-report-YYYY-MM-DD.md`
- 包含：决策记录/行动项（带负责人+截止日）/资源调整

## 二、理论框架会议（周五16:00）

### 议程模板（90min）

```
0-20min   盲区扫描：对照8个新问题检查表
20-50min  可证伪假说审查：王莽提交→全体形式化→张衡评估可测量性
50-70min  跨学科连接：沈括汇报本周新发现的跨学科连接
70-90min  议题联动：当前进行中的议题理论新发现注入
```

### 可证伪假说审查模板

```
假说编号：ITH-YYYY-### 
假说陈述：（精确的一句话）
可证伪条件：（在什么条件下假说被推翻）
测量方法：（用什么仪器/实验/数据验证）
预计工时：
负责人：
截止日期：
```

### 产出标准

- 理论会议纪要 → `ita/docs/meetings/theory-YYYY-MM-DD.md`
- 新假说登记 → `ita/docs/hypotheses/ITH-YYYY-###.md`
- 假说状态追踪表更新

## 三、技术协调会（周三14:00）

### 议程模板（45min）

```
0-15min   代码评审：上周各组核心PR（每组1个）
15-30min  集成测试：跨组接口联调结果
30-45min  技术债务：累积的技术债务+本周清理计划
```

### 代码评审标准

| 维度 | 要求 |
|------|------|
| 测试覆盖 | 新代码必须有测试，回归测试100%通过 |
| 文档 | 每个公开API有docstring + 使用示例 |
| 军规 | 遵循junshi-code-standards全部10条 |
| 复现性 | 训练脚本可单命令复现 |

## 五、里程碑验收会

### M1终审（W10）/ M2终审（W22）/ M3终审（W36）

每个里程碑必审项（缺一项不通过）→ 见 `ita-xiaohe-path-v1.0.md` 第七章。

### 验收流程

```
1. 各团提交自评报告（按验收标准逐项对照）
2. 包拯独立审计（交付物存在性+真实性）
3. 军师终裁：通过/有条件通过（列整改项）/不通过
4. 不通过→2周整改→复验
```

## 六、方向评审会（每2周，与理论框架会合并或单独召开）

### 触发条件

- 连续4周某方向无进展
- 重大实验结果（正面或负面）
- 外部新论文/工具可能改变技术路线
- 任何团队负责人提出方向异议

### 决策框架

```
选项A：继续当前方向，调整方法
选项B：缩小范围，砍子方向
选项C：暂停，切换备用方案
选项D：终止，资源重新分配

每个选项评估：理论支撑 + 实验证据 + 资源需求 + 机会成本
```

## 八、包拯审计清单

> 包拯在每次会议后、每个里程碑自动运行
> 
> **执行模式参考**：`references/baozheng-audit-pattern.md`（含grep命令模板、标记体系、审计报告模板）
> **ITA止损检查点#1**：`references/zhangyi-bridge-experiment.md`（张仪端到端验证——cos_sim→任务性能桥接测试）

### 交付物存在性检查

```
□ 文件路径是否存在？
□ 文件大小是否>0？
□ 文件内容是否与声称的功能一致？（随机抽查代码10行+输出3个数据点）
□ 测试是否真实运行过？（检查测试输出的timestamp）
```

### 真实性深度检查

```
□ 声称的"500函数恢复精度≥95%" → 抽查20个函数，手工跑测试
□ 声称的"Fisher曲率基线值" → 检查代码是否可复现
□ 声称的"码本利用率幂律指数α" → 检查原始数据文件+拟合代码
□ 声称的"层热力图产出" → 检查图片/数据文件存在且可读
□ 声称的"情报周报归档" → 检查wiki中确实有10期周报
```

### 包拯标记体系

| 标记 | 含义 | 处理 |
|------|------|------|
| 🟢 | 通过 | — |
| 🟡 | 证据不足 | 24h内补证据 |
| 🔴 | 虚假汇报 | 立即上报军师，关联责任团回溯问责 |
| ⚪ | 不适用 | 跳过 |

## 十、会话收尾流程（每次会话结束前执行）

> 强制：CHANGELOG更新 + WORKING.md更新 + 包拯终审

### 10.1 CHANGELOG更新

```bash
# 模板：在 ita/docs/CHANGELOG.md 顶部插入新版本条目
## vX.X — YYYY-MM-DD · 简述

### 本轮战果
| 类别 | 交付 | 规模 |

### 代码变更
### 测试状态
### 军规验收（10条逐项）
```

### 10.2 WORKING.md更新

```bash
# 更新 ~/.hermes/memories/WORKING.md
# 格式：当前活跃任务 + P0待续项
# 每次会话结束前执行
```

### 10.3 包拯终审

每次会话结束前运行：
1. `ls -la` 确认所有声称的交付物文件存在+非空
2. `grep -c` 抽验关键声称在文件中真实出现
3. 输出：🟢通过/🟡证据不足/🔴虚假 判定

### 10.4 端到端摘要

```
格式：
🏮 Day N 战报
| # | 交付 | 验证 |
核心发现（≤3条）
版本记录确认
下一步预告
```
