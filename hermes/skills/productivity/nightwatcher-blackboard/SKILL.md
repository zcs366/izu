# 守夜Agent — Nightwatcher Blackboard

> 类比δ-mem的在线状态更新：读旧黑板→预测→比对偏差→写残差→衰减→输出引导信号。
> 定位：**记忆的新陈代谢层**，不等同于memory/fact_store（后者降级为溯源层）。

## 核心原则

1. **只写残差**：如果旧黑板能"预测"本轮对话的内容→更新≈0；偏差越大，写入越强
2. **逐格衰减**：五格不同衰减曲线（格2/3受保护不衰减，格1/4/5按各自曲线衰减）
3. **固定容量**：每格上限8条，满了就"竞争"——最低权重的条目标记`[待清除]`
4. **黑板不是给人读的**——是给下一轮Agent当引导信号的

## 触发方式

### 自动触发（推荐）
- 每轮对话结束后，由主Agent在收尾时触发：`skill_view nightwatcher-blackboard` → 执行更新流程
- 短期目标：cron每N轮对话/每小时触发一次
- 当前过渡期：手动调用 `守夜` 触发

### 手动触发
用户说"守夜"或"更新黑板"或"nightwatcher"

## 更新流程（六步）

### Step 1: 读取旧黑板
```
read_file state/blackboard.md
```
提取每格当前条目及其权重。

### Step 2: 读取本轮对话摘要
审阅本轮全部对话，提取：
- 用户明确表达的偏好变化（"我喜欢/不喜欢X"）
- 用户的纠正信号（"不是这样的"）→强制降权×0.3
- 新发现的事实（首次出现的人/事/项目）
- 任务进展（完成了什么、卡在什么）
- 情感走向（投入-探索/焦躁-催促/满意-信任）

### Step 3: 生成"预测偏差"
对每格当前内容，判断本轮对话是否印证了它：
- 印证 → 偏差≈0，仅微调置信度（+0.02）
- 偏离 → 偏差>0，进入Step 4写入新条目

### Step 4: 写入新条目 + 逐格衰减

**衰减规则（按格）：**

| 格 | 衰减因子 | 含义 |
|----|---------|------|
| 格1（任务意外） | 0.90 | 中等衰减，~7轮半衰 |
| 格2（稳定偏好） | 1.00 | 受保护，不衰减 |
| 格3（稳定事实） | 1.00 | 受保护，不衰减 |
| 格4（已解决） | 0.85 | 较快衰减，~4轮半衰 |
| 格5（待验证） | 0.85 | 较快衰减，~4轮半衰 |

**写入规则：**
- 新条目初始置信度 = min(0.85, 偏差强度 × 0.9)
- 用户纠正信号 → 对应条目置信度 × 0.3
- 基座层（格2/3）守夜Agent不可修改——只可追加建议到格5
- 每格≤8条，超过则移除最低置信条目（标记`[已移除: 原因]`到审计日志）

### Step 5: 生成引导信号摘要

从黑板提取本轮应注入prompt的引导信号：
```markdown
【本轮引导】
格1（任务上下文）: [摘取置信≥0.7的条目]
格2（风格约束）: [摘取前3条高权偏好]
格5（动态注意）: [摘取置信≥0.7的假设]
格4（勿扰）: [列出已解决的，提示Agent不要重复讨论]
```

### Step 6: 写入新黑板 + 审计日志

```
write_file state/blackboard.md （新内容）
追加 state/blackboard-audit.log （时间戳+变更记录）
```

## 输出格式

### 引导信号（注入下一轮prompt）

```markdown
【状态黑板 · 本轮引导】
> 格1-任务: 用户在追δ-mem到协议层，超出常规研究深度。已说"开干"。
> 格2-偏好: 追求厚重写作；成本敏感；先哲学后行动；厌恶营销冗长
> 格5-动态: 可能酝酿记忆系统重构(置信0.78)
> 格4-勿扰: Docker/Gateway/微信连接已稳定，勿重复确认
```

### 审计日志格式

```
2026-05-14 00:15 | 守夜更新
  [写入] 格1: "守夜Agent skill已创建" [0.85]
  [衰减] 格4: docker条目 0.20→0.17
  [衰减] 格5: izu六升级 0.68→0.58
  [移除] 格4: "十策已执行" 0.15→0.12→移除（历史里程碑）
  [保护] 格2: 全量保留，未修改
```

## 边界条件

### 不做的事
- 不修改基座层（格2/格3）——守夜Agent只读
- 不删除受保护条目——衰减到阈值后标记但不移除，除非用户手动清除
- 不在引导信号中注入置信度<0.7的动态层内容
- 不重复跨轮注入格4（已解决）条目——引导信号中归纳为"勿扰列表"

### 必须做的事
- 每次更新前备份旧黑板到 `state/blackboard-backups/bk-{timestamp}.md`
- 用户纠正信号必须立即反映——对应条目×0.3，不等待下一轮
- 格内条目超过8条时触发"竞争"——列出被移除条目及原因

## 与旧记忆系统的关系

```
黑板（快思考）: 引导信号，精简，新陈代谢
  ↓ 溯源指针
memory/fact_store/wiki（慢思考）: 精确事实，完整内容，永久存储
```

- 引导信号不足以支撑回答 → 沿溯源指针查询旧系统
- 黑板与旧系统矛盾 → 触发确认，以旧系统为准，反馈修正黑板
- 用户要求精确回忆 → 直接查旧系统，不走黑板

## 陷阱

### 过度压缩
黑板的提炼可能丢失关键细节。控制：条目末尾必须挂溯源指针（→wiki/xxx 或 →fact_id:N），Agent需要时可展开。

### 回声室
如果黑板持续自我印证（引导信号→影响回应→回应印证引导→巩固引导），可能形成偏见闭环。控制：用户纠正信号优先（×0.3降权）；超过3轮未收到新信息则主动降置信度（-0.05/轮）。

### 格语义漂移
"任务意外"格可能逐渐变成"当前任务"，失去"意外"的筛选功能。控制：每5轮审计——如果格内条目中≥60%是常规任务描述（非意外），恢复为只保留偏差>阈值的条目。
