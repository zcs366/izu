# 子贡 · 前沿实验室调度模式

> 2026-05-15 实战提炼。爱祝前沿实验室首次启动的调度经验。

## 一、启动模式：三线并行

当军师/成市决定启动新一轮研究时，子贡的标准调度模式：

```
并行启动三线：
  ├─ 猎手×2（delegate_task，不同方向同时扫论文）
  └─ 韩信（delegate_task，画3-6月终局）

等待全部返回 → 军师审核 → 子贡路由分发
```

**实证**：2026-05-15 启动，3个 delegate_task 并行，全部在 ~70 秒内完成：
- 猎手-A：Agent自我迭代方向，9篇核心论文
- 猎手-B：多Agent协作方向，10篇核心论文
- 韩信：6步/24周终局路线图

**效率**：串行需 ~210 秒，并行仅 70 秒，节省 67% 等待时间。

## 二、实验室六角色调度矩阵

| 角色 | 触发方式 | 频率 | 前置依赖 | 后置动作 |
|------|---------|------|---------|---------|
| 猎手 | cronjob 自动 | 每日上午 | 无 | 标记"深挖"→触发矿工 |
| 矿工 | 猎手标记触发 | 按需 | 猎手输出 | 完成→触发判官 |
| 铁匠 | 判官标记触发 | 按需 | 矿工+判官输出 | 完成→触发织网者 |
| 织网者 | cronjob 自动 | 每周日晚 | 本周全部产出 | 完成→触发主笔 |
| 判官 | 矿工完成触发 | 每篇深挖论文 | 矿工拆解报告 | 完成→回传矿工/触发铁匠 |
| 主笔 | cronjob 自动 | 每日晚+每周日晚 | 当日/当周产出 | 推送微信+存wiki |

## 三、资源分配策略

- **猎手/矿工/判官**：低成本模型（DeepSeek 等），高频低消耗
- **铁匠**：本地终端+Python，零API成本
- **主笔/织网者**：高质量模型，低频但要求高
- **韩信（终局规划）**：按需启动，高质量模型

## 四、质量阈值

- 判官批判用"匠石铁律"：能用代码验证的不用模型判断
- 主笔产出前过子贡品味审查（5条审美铁律）
- 连续3次质量不达标 → 上报军师
- 月度复盘：角色配置是否需要调整？工作流是否冗余？

## 五、实验室与五人合议的关系

- 实验室日常运转：子贡自主调度，不需五人合议
- 研究方向调整 / 新增方向 / 重大产出评估 → 启动五人合议
- 子贡是实验室与五人合议之间的接口
- 韩信终局是实验室的战略旗帜
