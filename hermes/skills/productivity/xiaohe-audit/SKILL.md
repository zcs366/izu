# 萧何审计·izu研究质量保障闭环

> 审计不是找茬。审计是让每一次研究都成为下一次研究的基线。

## 触发条件

- **自动**：军师在对话流中收到 `流水线完成` 通知后，立即对产出定本执行审计
- **手动**：用户说"萧何审计""萧何来看""评估一下"

## 审计维度（17项）

### 逻辑（权重30%）
| 子项 | 检查标准 |
|------|---------|
| 问题定义完整 | 研究问题是否被清晰界定？是否有未言明的预设？ |
| 假设显式化 | 哪些是已知事实，哪些是作者推断，哪些是待验证假设？ |
| 结论不超数据 | 结论是否严格基于数据/引用，不存在跳跃？ |
| 替代解释已处理 | 主要竞争性解释是否被讨论？ |
| 因果vs相关区分 | 相关性推断是否被误标为因果？ |
| 基线合理 | 对比基准是否合理？ |

### 论证（权重30%）
| 子项 | 检查标准 |
|------|---------|
| 论证链完整 | 从前提→推理→结论的每一步是否可追溯？ |
| 反方论点已处理 | 最强的反对意见是否被正视？ |
| 数值精度诚实 | 数据来源是否标注？局限性是否说明？ |
| 统计检验正确 | 定量断言是否有统计支撑？ |
| 不cherry-pick | 是否只选择了支持自己的证据？ |

### 方家不笑（权重25%）
| 子项 | 检查标准 |
|------|---------|
| 术语准确 | 专业术语使用是否规范？自创术语是否标注？ |
| 相关工作引全 | 主要文献是否覆盖？ |
| 方法命名不自嗨 | 自创方法名是否合理？ |
| 图表不自欺 | 视觉呈现是否如实反映数据？ |
| 限界诚实 | 研究局限性是否被坦诚讨论？ |
| PhD点头 | 一个未参与研究的同行读后会点头吗？ |

### 实用价值（权重15%）
| 子项 | 检查标准 |
|------|---------|
| 落地性 | 结论是否可转化为行动？ |
| 可操作性 | 步骤是否具体可执行？ |
| 体系衔接 | 是否与现有知识库/工作流衔接？ |

## 评分标准

- ≥8.5：优秀——可直接发布
- ≥7.0：通过——可入库，附改进建议
- <7.0：退回——需修改后重新提交
- **铁律**：任一维度<5.0 → ❌ 直接退回

## 执行流程

1. 收到流水线完成通知 → 定位定本文件（修稿 `_修_` 文件）
2. 快速通读定本（读首尾+各段首句）
3. 逐维度打分（17项，0-10分）
4. 加权计算总分
5. 产出审计报告 → 保存至 `output/doc/xiaohe-audit-{topic}-{version}-{date}.md`
6. 版本自动递增（首次v1.0，同主题重新审计v1.1...）
7. 入库wiki（concepts更新、log记录）

## 系统进化闭环

每次审计产出的P0/P1建议 → 韩信路线图 → 匠石落地 → 下次审计验证效果。

```mermaid
研究 → 评估 → 发现问题 → 改进设计 → 再次研究 → 再次评估
```
