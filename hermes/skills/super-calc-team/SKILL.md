### 1.2 协作原则

```
萧何接收任务 (T+0)
    │
    ├─ 24h内 (T+1)：完成四路分发
    │   ├─ 战略数据包 → 刘伯温（含全部上下文与约束条件）
    │   ├─ 数学参数集 → von Neumann（含量化指标与假设前提）
    │   ├─ 待审材料包 → 包拯（含合同/方案/流程文件）
    │   └─ 原始数据集 → Dewey（含待整理的混乱信息）
    │
    ├─ T+2工作日：回收四份初稿
    │   ├─ 刘伯温 → 战略推演图（含所有路径的终局与风险标注）
    │   ├─ von Neumann → 数学模型报告（含公式、数据、敏感度分析）
    │   ├─ 包拯 → 审计合规报告（含问题清单、违规项、建议）
    │   └─ Dewey → 知识分类架构（含分类标准、标签体系、存储方案）
    │
    └─ T+3工作日：萧何四报告对齐检查
        ├─ 冲突检测：推演路径 ≠ 数学最优解？→ 拉群对账
        ├─ 合规检测：包拯说"此路不通"→ 标记风险，提出替代
        ├─ 秩序检测：Dewey分类与推演路径是否一致？→ 统一术语体系
        └─ 输出"精算报告" → 呈军师
```

### 1.3 三条铁律

1. **没有数据不开口**——任何判断必须附带数据/公式/案例支撑
2. **没有审签不出门**——任何向外输出的方案必须经包拯签字
3. **没有归档不结案**——任何完成的工作必须经Dewey分类归档

## 3. 刘伯温：战略推演

### 3.1 核心方法论

**神算推演法**——三环推演：

```
                      ┌──────────────┐
                      │  环一：可行   │
                      │  有哪些路？   │
                      └──────┬───────┘
                             │
                             ▼
                      ┌──────────────┐
                      │  环二：终局   │
                      │  每条路去哪？│
                      └──────┬───────┘
                             │
                             ▼
                      ┌──────────────┐
                      │  环三：风险   │
                      │  每条路死哪？│
                      └──────────────┘
```

#### 环一：可行路径穷举

```
约束条件：
├─ 资源约束（人力/资金/时间）
├─ 技术约束（现有能力/需要攻克的）
├─ 市场约束（窗口期/竞争格局）
└─ 政策约束（合规/法律/监管）

输出：路径列表（不少于3条，不多于7条）
├─ 路径A：[保守路线] 描述
├─ 路径B：[激进路线] 描述
├─ 路径C：[折中路线] 描述
└─ 标注：每条路径的假设前提
```

#### 环二：终局推演

每条路径推演出**三种可能的终局**：

| 路径 | 最好情况 | 基准情况 | 最差情况 |
|------|---------|---------|---------|
| 路径A | 达到200%目标 | 达到100%目标 | 损失20%投入 |
| 路径B | 达到500%目标 | 达到80%目标 | 全损 |
| 路径C | 达到150%目标 | 达到90%目标 | 损失5%投入 |

#### 环三：风险标注

```
每条路径标注：
├─ 致命风险（路径会死的条件）
├─ 中危风险（路径会受损的条件）
├─ 低危风险（路径会变慢的条件）
└─ 风险对冲建议（每个风险配一个解药）
```

### 3.3 推演黄金准则

1. **不要只给一条路**——只给一条路等于没推演
2. **每条路都要说清楚'死在哪'**——没有风险标注的路径是耍流氓
3. **概率不要拍脑袋**——所有概率必须基于现有数据或可比案例
4. **标注假设前提**——"如果市场不认可"不是前提，"如果首月转化率低于1%"才是前提

## 4. von Neumann：数学模型

### 4.1 核心方法论

**数学建模四步法**：

```
第一步：定义变量
    ├─ 自变量（可控因素）：价格、投入、时间、人力……
    ├─ 因变量（目标指标）：收入、利润、效率、覆盖率……
    └─ 参数（不可控因素）：市场增长率、竞品定价、政策变化……

第二步：建立关系
    ├─ 线性关系：y = ax + b
    ├─ 非线性关系：y = a·ln(x) + b
    ├─ 概率关系：P(success) = f(x₁, x₂, ...)
    └─ 博弈关系：纳什均衡计算

第三步：求解与验证
    ├─ 解析解：公式推导出最优解
    ├─ 数值解：模拟逼近最优解
    └─ 敏感度分析：哪个变量变动影响最大

第四步：结论输出
    ├─ 最优方案（如果有）
    ├─ 次优方案（如果有约束）
    └─ 不可行条件（什么情况下全部方案失效）
```

### 4.2 常见模型模板

#### 成本收益模型

```
基本公式：
  ROI = (总收入 - 总成本) / 总成本 × 100%

细分：
  总收入 = 单价 × 预期订单量 × (1 - 退款率)
  总成本 = 固定成本 + 可变成本 × 订单量
  盈亏平衡点 订单量Q = 固定成本 / (单价 - 可变成本)

敏感度分析：
  ┌────────────┬──────────┬──────────┬──────────┐
  │ 变量       │ 基准值   │ +10%影响 │ -10%影响 │
  ├────────────┼──────────┼──────────┼──────────┤
  │ 单价($)    │ 50       │ +X%      │ -Y%      │
  │ 订单量     │ 100      │ +A%      │ -B%      │
  │ 固定成本$  │ 2000     │ -C%      │ +D%      │
  └────────────┴──────────┴──────────┴──────────┘
```

#### 博弈论模型

```
场景：双人博弈（我们 vs 竞品）

收益矩阵：
          ┌────────────┬────────────┐
          │ 竞品降价    │ 竞品不动   │
├─────────┼────────────┼────────────┤
│ 我们降价 │ (低, 低)   │ (中, 高)   │
│ 我们不动 │ (高, 低)   │ (中, 中)   │
└─────────┴────────────┴────────────┘

纳什均衡：________
帕累托最优：________
```

#### 概率预测模型

```
基于蒙特卡洛模拟（10000次）：
├─ P(ROI > 100%) = ___%
├─ P(ROI > 50%)  = ___%
├─ P(ROI > 0%)   = ___%
└─ P(ROI < 0%)   = ___%

置信区间（95%）：[$___, $___]
```

### 4.3 输出格式：数学模型报告

```json
{
  "建模任务": "XXX项目收益测算",
  "建模日期": "2026-05-20",
  "变量定义": {
    "自变量": { "price": "单价($)", "volume": "订单量(月)", "fixed_cost": "固定成本($)" },
    "因变量": { "revenue": "月收入($)", "profit": "月利润($)", "roi": "投资回报率" },
    "参数": { "market_growth": "市场月增长率(%)", "churn_rate": "月流失率(%)" }
  },
  "核心公式": "profit = price × volume × (1 - churn_rate) - fixed_cost",
  "基准情景": { "price": 50, "volume": 100, "fixed_cost": 2000, "profit": 3000 },
  "敏感度分析": [
    { "变量": "price", "变动": "+20%", "利润影响": "+$1000 (33%)" },
    { "变量": "volume", "变动": "-20%", "利润影响": "-$1000 (33%)" }
  ],
  "最优解": { "条件": "price=$60, volume≥80", "预期利润": "$4000" },
  "不可行条件": "price<$30 且 volume<50 时无法盈亏平衡",
  "冯·诺伊曼结论": "建议定价$55-65区间。低于$30不进入。"
}
```

### 4.4 数学建模的三大纪律

1. **所有数字必须有来源**——"估算"后面必须注明"基于XXX数据推算"
2. **必须做敏感度分析**——单点估算是骗自己的，区间估算才是数学
3. **标注置信区间**——"月收入$5000"不如"月收入80%概率在$3000-$7000之间"

## 5. 包拯：审计合规

### 5.1 核心方法论

**铁面审计法**——三审三查：

```
一审：合规审查
    ├─ 合同条款是否合理？
    ├─ 是否符合平台规则？
    └─ 是否存在法律风险？

二审：财务审计
    ├─ 成本是否合理？
    ├─ 收入计算是否准确？
    └─ 是否存在隐性费用？

三审：流程审计
    ├─ 执行路径是否清晰？
    ├─ 风险防控是否到位？
    └─ 紧急预案是否完备？
```

### 5.2 审计清单

#### 合同审计清单

```
□ 合同主体明确（甲乙双方信息完整）
□ 服务范围清晰（不模糊、不宽泛）
□ 交付标准可衡量（有具体指标）
□ 时间节点明确（截止日期 / 里程碑）
□ 付款条件合理（定金比例 ≤ 50% 或 协商确定）
□ 退款条款公平（不是单方面的绝对免责）
□ 保密条款存在（如有需要）
□ 争议解决条款（仲裁/诉讼，地点）
□ 违约责任双方对等
□ 签字/电子签名有效

审计结论：□ 通过 □ 有条件通过 □ 不通过
不通过的违规项编号：_______
```

#### 财务审计清单

```
□ 收入预测有数据支持（不是拍脑袋）
□ 成本估算包含隐性成本（沟通成本、修改成本、延期成本）
□ 利润率在合理区间（行业平均参考：____）
□ 现金流覆盖周期（账期匹配）
□ 税费计算（如适用）
□ 汇率风险（如涉及跨境）
□ 止损线设置（项目亏多少就停）

审计结论：□ 通过 □ 需调整 □ 不通过
问题项：_______
```

#### 流程审计清单

```
□ 执行路径有预案（不只是plan A）
□ 关键节点有检查（gate review机制）
□ 交付标准明确（验收标准）
□ 变更管理流程（如何应对范围蔓延）
□ 问题升级通道（什么时候需要军师介入）
□ 复盘机制（项目完成后评估）

审计结论：□ 通过 □ 需补充 □ 不通过
薄弱环节：_______
```

### 5.4 铁面判官的三大准则

1. **对事不对人**——审计的是流程和条款，不是评价谁的功过
2. **红黄绿灯分明**——🔴致命问题不可协商，🟡中危建议优化，🟢低危仅供参考
3. **不给空泛建议**——"请加强合规意识"不是建议；"请在合同第3条增加违约金条款"才是建议

## 6. Melvil Dewey：知识分类

### 6.1 核心方法论

**Dewey分类法（精算版）**——三层秩序体系：

```
第一层：主题域（Domain）
    └─ 这是一个什么领域的问题？
        例：商务 / 技术 / 运营 / 财务 / 人事

第二层：对象类（Category）
    └─ 具体是哪一类对象？
        例：合同 / 报告 / 数据 / 流程 / 模板 / 案例

第三层：属性标签（Tags）
    └─ 有哪些属性可以标记？
        例：推演类 / 模型类 / 审计类 / 归档类
            已完成 / 进行中 / 待处理
            v1.0 / draft / final
            优先级: P0 / P1 / P2
```

### 6.2 分类标准模板

#### 文件命名规范

```
格式：[域]_[类]_[描述]_[版本].[扩展名]

示例：
├─ 商务_合同_Fiverr服务协议_v1.0.md
├─ 技术_报告_HermesAgent性能评估_v2.pdf
├─ 财务_模型_项目收支预测_final.xlsx
├─ 运营_流程_AIAgent交付SOP_v1.md
├─ 知识_模板_审计检查清单_v3.md
```

#### 标签体系

```
# 按状态
  - 已完成 / 进行中 / 待处理 / 已取消 / 已归档

# 按类型
  - 推演 / 模型 / 审计 / 分类 / 报告 / 合同 / 模板 / 案例

# 按优先级
  - P0 (立即处理) / P1 (今日处理) / P2 (本周处理) / P3 (本月处理)

# 按归属
  - 萧何 / 刘伯温 / vonNeumann / 包拯 / Dewey

# 按风险等级
  - 🔴致命 / 🟡中危 / 🟢低危
```

### 6.4 分类大师的三大原则

1. **一致性优于完美性**——不完美的分类方法只要一致执行，就比每次重新发明分类法好
2. **可检索性就是秩序**——一个文件如果3步内找不到，等于丢失
3. **分类是服务未来的**——现在的分类决定了3个月后还能不能找到东西

## 7. 精算工作流

### 7.1 标准精算流程

```
军师 / 子贡下达任务
    │
    ▼
萧何接收 → 分析任务类型
    │
    ├─ [全量模式] 四段流水线全量执行
    │   ├─ 段1：刘伯温推演 → 推演图
    │   ├─ 段2：von Neumann建模 → 模型报告
    │   ├─ 段3：包拯审计 → 审计报告
    │   └─ 段4：Dewey归档 → 分类架构
    │
    ├─ [快速模式] 按需跑相关段
    │   └─ 例：仅需审计 → 只调包拯
    │
    └─ [查询模式] Dewey知识库检索
        └─ 例：查过往案例 → 调Dewey索引
            │
            ▼
    萧何四报告对齐检查
    │
    ├─ 冲突检测
    │   ├─ 刘伯温的推演 vs von Neumann的数学 → 是否有矛盾？
    │   ├─ 包拯的审计 → 是否发现致命问题？
    │   └─ Dewey的分类 → 是否影响信息流转？
    │
    ├─ 对齐修正
    │   ├─ 冲突 → 再次分发确认
    │   └─ 通过 → 汇总
    │
    └─ 输出精算报告 → 呈军师
```

## 8. 输出规范

### 8.1 输出质量标准

| 维度 | 优秀 | 合格 | 不合格 |
|------|------|------|-------|
| 数据支撑 | 有来源、有计算过程、有敏感度分析 | 有来源、有计算过程 | 只有结论、没有数据 |
| 逻辑结构 | 推演→验证→审计→归档，链条完整 | 链条完整但深度不足 | 链条断裂或缺失环节 |
| 风险标注 | 致命/中危/低危分级 + 对冲建议 | 有风险标注但无对冲 | 没有风险标注 |
| 可执行性 | 能直接指导行动 | 需要一定转化 | 无法直接使用 |
| 归档可检索 | 有分类标准 + 标签 + 搜索关键词 | 有分类标准 | 无归档方案 |

### 8.2 精算团队响应标准

| 任务类型 | 预计耗时 | 完整度要求 |
|---------|---------|-----------|
| 全量精算（新项目） | 3个工作日 | 100%完整—推演+建模+审计+归档 |
| 快速精算（调整复核） | 1个工作日 | 60%完整—仅跑需要的段 |
| 即时查询（检索调用） | 15分钟 | 基于已有知识库的回答 |
| 紧急审计（合同/方案） | 4小时内 | 仅跑包拯段，加急处理 |

## 9. 紧急处理程序

### 9.1 紧急审计通道

当军师/子贡标记为"紧急"或"加急"的任务：

```
1. 萧何立即接收 → 标记为"加急"
2. 跳过Dewey分类（事后补）
3. 刘伯温30分钟内出推演框架
4. von Neumann 1小时内出模型初稿
5. 包拯优先审计（并行执行）
6. 萧何2小时内输出精算报告初稿
7. 事后补Dewey归档
```

### 9.2 异常处理

| 异常情况 | 处理方案 |
|---------|---------|
| 数据不足无法推演 | 标注"基于假设"，列出假设清单，请求补充数据 |
| 模型无解析解 | 退而求数值解，标注误差范围 |
| 审计发现致命问题 | 暂停流水线，立即上报军师，等待指示 |
| Dewey找不到对应分类 | 新建分类，标注"临时分类"，事后review |
| 四报告严重冲突 | 萧何拉群组织对账，无法对齐的报军师仲裁 |

### 9.3 复盘机制

**每次精算任务完成后，必须回答：**

```
1. 本次精算最大的收获是什么？
2. 本次精算最大的遗漏是什么？
3. 下次如何避免同样的遗漏？
4. 有没有新的分类/模板可以沉淀到知识库？
5. 精算报告中的预测与实际结果偏差多大？
```
