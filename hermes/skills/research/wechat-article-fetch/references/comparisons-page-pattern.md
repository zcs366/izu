# 比较页模式（Comparisons Page）

> wechat-article-fetch 参考
> 来源：2026-05-14 Gstack 评估

## 何时创建比较页

当微信文章讨论了与 izu 直接相关的工具/项目/方法论时，除了标准的「抓取→评估→raw入库」流程，还应创建比较页。

**信号**（满足任一即触发）：
- 文章描述的工具/方法与 izu 处于同一个问题领域
- 文章揭示的组织模式/协同模式可直接对照 izu 的现有架构
- 文章的核心理念对 izu 当前阶段有「可以学」或「不能学」的明确启示

## 比较页结构

```
wiki/comparisons/{topic-slug}.md
```

### 推荐模板

```markdown
# 标题：A vs izu — 两个视角的对照

> 来源：文章URL
> 作者：XXX
> 摄入：YYYY-MM-DD

## 核心事实
[被评估对象的关键信息：定位/规模/机制]

## 与izu的对比
| 维度 | A | izu |
|------|-----|-----|
| 定位 | ... | ... |
| 核心机制 | ... | ... |
| 护城河 | ... | ... |
| ... | ... | ... |

## 启示
### 可以学的
### 不能学的
### 直接行动
```

## 与评估页的关系

- **评估页**（`wiki/research/{slug}-eval.md`）：完整评估——论据充分度、盲点识别、启示、改进建议分级（P0/P1/P2）
- **比较页**（`wiki/comparisons/{slug}.md`）：快速对照——一页看清两个系统的关键差异和可借鉴点

两者可以共存。评估页适合自己深度阅读，比较页适合快速回顾和给他人看。

## 后续更新

比较页不是一次性的。当 izu 自身架构发生变化时（比如加了元认知调度层），应回顾已有的比较页，更新对比表格中的 izu 列。

## 示例

- `wiki/comparisons/gstack-vs-izu-agent-orchestration.md` — Gstack 15角色 vs izu 7智能体
