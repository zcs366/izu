# AGI长编·实践记录（2026-05-10）

## 项目概况

- **主题**：AGI（通用人工智能）全领域研究
- **方法论**：knowledge-campaign（画地图→收长编→三编通读→出定本）
- **耗时**：约4-5小时完成九面长编（初编约6万字），随后第一编通读补约6000字
- **工具链**：ddgs搜索 + Wikipedia API + curl抓取 + subagent.py流水线

## 关键经验

### 搜索工具降级链
1. web_search（Firecrawl）→ 额度耗尽时
2. ddgs（DuckDuckGo）→ 终端Python调用
3. Wikipedia API → 结构化内容获取
4. curl + 正则 → 网页内容提取

### delegate_task 问题
- OpenRouter免费层模型（gemma-4-31b-it:free）频繁429限流
- 解决方案：改用DeepSeek API直接调用（见 subagent.py）
- 注意：delegate_task的模型配置在会话内缓存，配置更改需新会话生效

### 三智能体流水线结果
- 搜智能体：能产出结构化资料，含来源，效果最好
- 写智能体：产出通俗文章，但长内容可能超时（300秒 timeout 够用）
- 劈智能体：效果最惊艳——能产出符合用户风格的严苛批评
- 三编循环：从初稿（2000字无来源）→ 定稿（6400字含7条参考文献+数据对比表+效应量参照系）

### 长编与认知地图的交付物结构

AGI长编的最终交付物不是一份"定本"，而是两套东西：

**长编（层1索引）**——九面地图，6.6万字，每面独立文件，供查阅和深挖
**认知地图（导航）**——7页手机版，v2.1历经两次迭代：初版知识卡片→叙事引导版→带见解和索引层级的挂轴地图版

认知地图的迭代轨迹展现了"写得漂亮"本身就是引导：
- v1.0：知识卡片风格，显式"你可以："
- v2.0：有情绪的叙述，引子+画面+节奏
- v2.1：第7页重写为挂轴地图——九面关系图+个人见解+索引层级+得道快乐

### 版本管理教训

用户明确纠正：**"又直接改了，要做版本号变更啊，我要看到变迁的痕迹。"**
后续所有文档修改必须：
1. 更新版本号（v1.0→v1.1→v2.0）
2. 在标题下写变更说明
3. 保留旧版本文件供对照
4. 维护一份版本日志

### 用户偏好（需嵌入 skill 使用中）
- 不要催进度，先打地基
- 数据必须可溯源（来源、作者、年份）
- 百分比提升必须给出绝对值和基线
- 要包含失败案例和风险面，避免单向赞歌
- 效应量要放在参照系中理解（对比其他教育干预）
- "劈"要具体、不留情、找来源漏洞
