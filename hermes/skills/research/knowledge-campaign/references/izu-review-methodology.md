# izu战略评估方法论

> 用于每季度（或重大里程碑后）对izu系统做全面回顾、评估、升级和展望。
> 首次执行：2026-05-13，产出 `izu全面评估与升级路线图_v1.0.md`。

## 执行步骤

### 第〇步：信息收集（全线搜索）

1. **内部全量检索**：fact_store.probe("izu") + memory.search + session_search(3-5次历史会话)
2. **文件系统遍历**：search_files 覆盖 /mnt/i/hermes 下所有 izu/ai祝/祝白皮/祝研究 相关文件
3. **Wiki深度阅读**：wiki/index.md + raw/祝成果/ 下所有文件
4. **GitHub检查**：git clone github.com/zcs366/izu，检查README/index.html/cases/
5. **代码审查**：scripts/subagent.py 等核心代码
6. **外部竞品搜索**：web_search 3-4轮，覆盖Deep Research类、知识库Agent、AI报告引擎、记忆系统四个方向

### 第一步：五层解构

把izu拆成五层，逐层列出"有什么"：

| 层 | 内容 | 关键文件 |
|----|------|---------|
| 哲学层 | 明学七则 | 明学纲要_v0.3.md |
| 定位层 | 祝白皮书（六根柱子） | 祝白皮书_v0.2.md |
| 方法论层 | 三段式流程 + 三智能体流水线 | subagent.py |
| 工具层 | Hermes Agent + Wiki + Cron + GitHub | 各类配置文件 |
| 产出层 | AGI九面 + ai祝研究 + 小学教育等 | wiki/raw/祝成果/ |

### 第二步：三档评估

对每一层的每一项，标记：
- 🟢 **稳的**：有哲学/定位/产出优势，竞品无法复制
- 🟡 **晃的**：骨架有但肌肉没有（如三智能体太薄、WikiMeld只写了研究）
- 🔴 **空的**：白皮书承诺但代码没写（画像系统、认知地图引擎、祝号自动化）

### 第三步：外部全景对比

web_search 覆盖至少四个方向：
1. 大厂最新动向（Anthropic/OpenAI/Google）
2. 开源前沿（GraphRAG、记忆系统）
3. 竞品产品迭代（NotebookLM、Perplexity）
4. 2026年AI趋势报告

对比后标注：哪些差异化正在被竞品洗掉？哪些差异化竞品永远不会做？

### 第四步：断点分析

找出"哲学→工程"、"生产→消费"、"承诺→兑现"三条线上哪些是断裂的。

### 第五步：升级方向与优先级

每个升级方向标注：能在多久做（1-2周/2-4周/3-6月/持续），为什么是这个优先级。

### 第六步：输出

写入 `/mnt/i/hermes/output/doc/izu全面评估与升级路线图_v{N}.md`，版本号递增。
再存一份到 wiki raw/祝成果/ 归档。
